### 二、必须修的缺陷（按优先级；每条都带实测证据，可直接复现）

#### D1（Blocker）闸门工具在 GBK 控制台下崩溃，且"崩溃"与"判定 FAIL"退出码相同

- **现象**：把脚本输出管道/重定向时（如 `| Select-Object`、CI 日志重定向），Python 用 `locale.getpreferredencoding()`=cp936 编码 stdout，而闸门输出含 `⓪`(U+24EA) `⑪`(U+246B) 等 GBK 无法编码的字符 → 运行中途抛 `UnicodeEncodeError`。
- **实测三处**：
  - `scripts/gate_all.py:219` 的 `summary(rows)` 崩溃，位置在 `:221` 的 `json.dump(...)` **之前** → **基线 JSON 永远写不出来**，而 `--baseline` 判据回归（契约 §6.6 铁律 2 的执行体）依赖它。
  - `scripts/gate_lecture.py:1081` 打印 ⓪ 段标题时崩溃（判定还没算完），而 `:1334` 只 `return 0 if ok else 1` → **工具崩溃与被判 FAIL 同为退出码 1**，CI 无法区分。
  - `scripts/safe_edit.py:223` 在体检成功后打印最后一行汇报时崩溃（围栏体检其实已成功，却以 exit 1 收场）。
- **复现命令**（不要加 `PYTHONIOENCODING`）：
  ```powershell
  python scripts/gate_lecture.py "<任一批次讲解.md>" --src "<源码根>" | Select-Object -Last 5
  # → UnicodeEncodeError: 'gbk' codec can't encode character '\u24ea'
  ```
- **必须做到**：
  1. 三个入口脚本（或抽一个 `scripts/_console.py` 供 import）在**最早时刻**统一重设输出编码：`sys.stdout.reconfigure(encoding="utf-8", errors="replace")`（stderr 同理）。
  2. `gate_all.py` 调整执行顺序：**先 `json.dump` 写盘，再 `summary()` 打印**——报告打印失败不得连带丢掉基线文件。
  3. 用**独立的退出码**区分语义：`0`=判定通过、`1`=判定不通过、`2`=用法错误（现状）、**`3`=工具内部错误**；在 `main()` 外层包 `try/except`，把未捕获异常转成退出码 3 + 一行可读错误。
  4. 给 `skill_selfcheck.py` **新增负向自测**：在"stdout 被管道接管且 locale 为 cp936"的条件下运行闸门，断言**不得**抛 UnicodeEncodeError。否则这条保证只会写在文档里（文档 `docs/安装与执行边界.md:29` 已声称"Windows 下自检不会因子进程代码页产生误导性线程异常"，实测只覆盖了自检脚本、没覆盖这 10 个工具）。
- **验收方式**：在**不设** `PYTHONIOENCODING` 的情况下用管道跑三条命令，全部正常退出；`gate_all.py --out x.json` 必产出文件；人为制造内部错误（如传入不存在的源码根）得到退出码 3 而不是 1。

#### D4（Major）部分带圈数字在落盘路径丢失 → 闸门**整段不检查**

- **现象**：`⑨ ⑩ ⑮ ⑯`（U+2468/2469/246E/246F）等字符在某些生成/落盘路径上会丢失，标题变成 `##   No-Framework 等价实现`（多一个空格、没有圈码）。
- **后果（已实测）**：`gate_lecture.py:818` 用 `re.search(r"^## ⑫\s", txt, re.M)` **定位段落**——标题丢了圈码 → 该段整体不被检查：⑫ 报 "八条 = 0 ≠ 8"、⑯ 报 "从没写明判据版本"；而 `new_batch.py` 自己却打印「⑫ 八条 = 8」，**两个自带工具结论相反**。
- **关键点**：这不是 `new_batch.py` 独有——**手写正文同样会丢**（实测丢 4 个、保住 2 个）。所以修工具不够，还要堵住"静默跳过"。
- **必须做到**：
  1. **让"找不到段"可见**：`gate_lecture.py` 的 ⓪ 组增加一条硬检查——若 17 个一级节标题中，**任一**未按 §6.4 的规范形态（`^## ①`…`^## ` + 索引节）命中，则**报 FAIL 并列出实际标题原文**（现状是"找不到就跳过"，等于放行）。
  2. `new_batch.py` 生成骨架后**自断言**：17 个节标题正则全部命中、⑫ 八条与八段标签齐备；不满足就报错退出（别让用户拿到畸形骨架）。
  3. 在 `spec/操作手册-闸门与工具.md` 与 SKILL §6.4 的"每批合规性自查"处，加一条**前置动作**：写完正文、跑闸门之前先 `grep -n '^## '` 核对节标题形态；并给出用 `safe_edit.py --replace <行> <行> --block <单行文件> --apply` 修单行标题的标准做法（注意 `safe_edit` 会打印"区间含一级节标题"的告警，那是**提醒**不是错误）。
  4. 附带：`gate_lecture.py` 的 ⑫ 八条计数目前接受 H3/H4（`^#{3,4}`），请确认与 `new_batch.py` 的生成层级一致并写进契约条目，避免两处口径分叉。
- **验收方式**：构造一份把 `## ⑫` 改成 `##  Vibecoding 视角` 的批次副本，闸门必须 **FAIL 且点名该标题**；对未改动的正常批次，判定值必须与改前**逐字段一致**（`gate_all --baseline`）。

#### D5（Major，口径问题）`gate_all.py` 会把含 java 代码片段的第三册文档当"教材批"判

- **现象**：第三册的挑战文档里有一小段 ```` ```java ```` 说明代码 → `gate_all.py` 按第一册的 17 节规范判它 → 记 `节数12 ≠ 17 / 八条=0 / 无回链`（单跑 `gate_lecture.py` 退出码 1）；而同目录只含 ```` ```diff ```` 的 Diff 审查文档与无代码块的实验卡被跳过结构判定显示 PASS。
- **必须做到**：给"卡片类文档"（第三册挑战 / Diff 审查 / 第二册实验卡）一个**显式口径**，二选一或都要：

  2. 或提供 `--exempt <glob>` 并在记分卡里**单列**这些文件的判定口径。
- **硬约束**：**禁止**用"删掉证据代码"的方式过闸门；口径变更必须在输出里说明"这些文件按哪套模板判"。
- **验收方式**：对含 2 篇卡片文档 + 1 篇第一册批次的目录跑记分卡，输出应分别标注两套口径，且**第一册批次的判定值不变**。

#### D3（Minor）`callsite.py` 对方法名恒报 `声明 (0)`

- **现象**：`python scripts/callsite.py streamChat --src <repo>` → `=== 声明 (0) ===`，但该符号在接口里确实有声明。原因：声明段只认 `class/interface/record/enum` 类型声明（`callsite.py:37/:109`），且仅在"声明与调用点都为空"时才打提醒（`:173`）。
- **必须做到**：当传入符号**不是类型**（未命中类型声明正则）时，在输出里**显式加一行说明**（如"（该符号非类型声明；本段只列类型声明）"），或支持方法声明识别。
- **理由**：这与血证 H23 的教训同族——**看到"0 个 X"必须先问"是没查还是查了没有"**。
