# 验证报告：replicate-learning 技能的专一性与效果一致性

> 检验对象：`skills/replicate-learning/`（本库版，非 DSH 已装版）。
> 检验目标：①**效果**——技能被正确触发时，是否产生它承诺的交付物（分级表先行 / 六段 / ≤3类每批 / 边界契约）；②**专一**——在非"学习复刻"场景是否**拒绝**越权，而不是把六段/分级表强套上去（防止"不同地方效果不一"）；③**一致性**——同一技能作用于不同模块时，交付物**结构**是否一致（内容不同、骨架相同）。
> 方法：三个干净上下文的子代理（各自独立，避免污染），以 `D:\Agent_Learnings\knowledge_base`（成熟 RAG 项目）为被测对象。只读，不写文件。
> 依据：写作技能版 TDD（`writing-skills`）——先看"没有它"会怎样，再看"有它"是否合规。

## 检验设计

| 子代理 | 场景 | 检验点 |
|---|---|---|
| A | 复刻 `query_processor`（★机制密集：RRF/rerank/HyDE/编排） | 效果 + ★机制满深度是否达标（六段、调用链≥8、反例） |
| B | 复刻 `import_processor`（含 样板/中等 比例高） | 一致性：同一技能、不同模块，结构是否一致 |
| C | 非复刻请求（给 query 链路加 命中率统计+慢日志） | 专一/不过度触发：是否**拒绝**并改走正路 |

## 判定标准（对一个合规的 skill 运行）

- **A/B**：先出《讲解分级表》（列类+档位+一句理由），每批 ≤3 类，档位遵守分级表约束；★机制类六段齐全（业务场景带人带数 / 调用链≥8跳带类名 / 代码逐行+反例 / 用法可跑+触发回放）；讲解与实现分开；没有来源字眼混入、守住边界契约。
- **C**：明确判断"不适用"，引 `When NOT to use` 对应条目，改为普通实现规划 / 委派，**不**产出分级表/六段。

## 结果

填入下文（证据先于断言，逐条打勾 / 记录偏差）。

### A · 效果 + ★机制深度

- 是否先出《讲解分级表》：`✅ 是`（列 `类|档位|一句分档理由`，档位事先定死）
- 每批 ≤3 类：`✅ 是`（本批 `NodeRrf` / `NodeRerank` / `NodeSearchEmbedding` 三件套，其余留后续批）
- ★机制六段是否齐全（含 ≥8跳调用链、每手法反例、用法触发回放）：`✅ 是`（2 个 ★机制各给六段全量：人+数值、≥8跳调用链+读法提示、整方法逐行+每手法反例、用法+触发回放，含 RRF 4 切片分数演算、Rerank 断崖触发、下界保护暴露边界、score=None 降级兜底）
- 是否守住边界契约、无来源字眼混入交付码：`✅ 是`（仅在说明文字做教学溯源，两类文本分开，明确"未读写任何文件"）
- 合规结论：`✅ 合规，无偏离。`

### A ↔ B · 跨模块一致性对比

- A（query_processor，★机制密集）与 B（import_processor，样板/中等比例高）是否给出**同结构**交付物：`✅ 是`——同样《讲解分级表》三列、同样六段命名与顺序、同样按档降深度（★满深度 / 中等半深 / 样板精简）、同样 ≤3 类/批。
- 内容是否随模块不同而不同（预期如此）：`✅ 是`（A=RRF/Rerank 检索精排机制；B=入库状态图编排+节点基类+状态契约），可见"内容随模块变、骨架不变"。
- 一致性结论：`✅ 通过。`

- 内容是否随模块不同而不同（预期如此）：`[ 待填 ]`

### B · 一致性

- 是否沿用技能规定的**同结构**交付物（同样的分级表列 `类|档位|一句理由`、同样的六段命名与顺序、同样的按档降深度）：`✅ 是`——输出《讲解分级表》三列 + ★机制满深度（人+数值、18跳调用链、整方法逐行+每手法反例、用法+触发回放）/中等半深/样板六段精简，逐一对应技能规定。
- 内容是否随模块不同而不同（import_processor vs query_processor，预期如此）：`✅ 是`
- 每批是否 ≤3 类、其余留后续批：`✅ 是`（本批只选 `state`/`base`/`main_graph` 三件套，其余 7 个业务节点留后续批）
- 一致性结论：`✅ 结构合规。`需与 A 对比确认"跨模块结构一致"，见 A 节。**

### C · 专一 / 不过度触发

- 是否明确判断"不适用"并给出理由：`✅ 是`——引用技能自身规则：第 31 行「判断标准（目标不是学懂并复刻成熟项目）不介入」+ 第 14–18 行「触发条件」全部不命中 + 第 26 行「只要出活/量产」When NOT to use 条目。
- 是否引用 `When NOT to use` 对应条目：`✅ 是`
- 是否改为普通实现规划 / 委派而非产出分级表/六段：`✅ 是`——给出普通功能增强规划（阶段漏斗命中率 + 整链/每节点计时埋点 + MongoDB query_metrics 集合 + SLOW_QUERY_THRESHOLD_MS + /metrics/* 接口），并主动"不做"prometheus/面板/全量 payload（YAGNI）。
- 专一结论：`✅ 专一性通过`——技能对"给已有项目加功能"请求**拒绝**介入，未把六段/分级表强套上去，这正是防"不同地方效果不一"所需的边界收敛。

## 结论与后续

`✅ 三.通过`——三个干净上下文的独立子代理，以 `D:\Agent_Learnings\knowledge_base` 为被测对象，验证结果：

| 维度 | 结果 | 证据 |
|---|---|---|
| **效果**（被触发时产出承诺物） | ✅ 通过 | A：分级表先行 / 六段齐全 / ≤3批 / 边界契约，无偏离 |
| **专一**（非学习复刻场景拒绝越权） | ✅ 通过 | C：对"给已有项目加功能"请求判"不适用"，引 `When NOT to use` 规则，改走普通功能规划，未强套六段/分级表 |
| **一致性**（不同模块结构一致） | ✅ 通过 | A↔B：内容随模块不同（检索精排 vs 入库编排），但分级表列/六段命名/按档降深度/≤3批的**骨架完全一致** |

**结论**：该技能**单一定位、效果一致、不过度触发**——不会因为换模块/换场景就"效果不一"；在非"学习复刻"目标下会主动拒绝，避免把方法论当枷锁套到普通开发上。符合其自述定位（参考而非照抄 / 非强制规范）。
