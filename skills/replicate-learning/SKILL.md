# 复刻式学习：执行入口

默认只生成**第一册《项目源码与工程实现》**。第二册《实验与机制验证》、第三册《架构挑战与独立重构》只在用户明确请求对应册时启用。普通“继续”延续已明确的项目范围；没有明确记录时仍只第一册。未请求的册是 `not_requested`，不创建目录、索引、欠账、补齐期限，也不反复询问是否恢复。

第一册仍须讲清真实项目中的业务闭环、源码、底层机制、失败路径、测试证据、AI协作与验收。验证一段说法或做一次指定实验，不自动开启第二册；解释架构位置也不自动开启第三册。

## 快速路由

| 用户意图 | 本轮动作 | 按需读取 |
|---|---|---|
| 学习/深度拆解/开始 | 确定项目与范围；首次建基础地图，从第一批开始 | `references/第一册执行协议.md`、`references/V2执行协议.md` |
| 继续/next | 读精简状态、覆盖矩阵、最近批次、源码变更；只续未完成部分 | `references/第一册执行协议.md` |
| 讲解某文件/某机制 | 准备本批证据，生成第一册相关内容 | `references/第一册执行协议.md`、相应质量细则 |
| 实验/验证机制 | 做指定验证；仅明确说“第二册”才生成第二册 | `references/预测卡模板.md`、`references/证据卡模板.md`、`references/实验卡模板.md` |
| 架构挑战/重构/迁移 | 做指定挑战；仅明确说“第三册”才生成第三册 | `references/架构挑战模板.md` |
| Issue/功能/修复/让 AI 改代码 | 执行工程任务，使用实际需要的Issue与审查记录 | `references/工程Issue模板.md`、`references/上下文包模板.md`、`references/Diff审查模板.md`、`references/Debug记录模板.md` |
| 验收/检查完整性 | 核对真实覆盖、证据、门禁与用户验收状态 | `spec/00-质量契约.json`、`spec/V2质量契约.json` |

模式可用 `python scripts/study_scope.py --request "继续"` 核对。项目已有明确三册授权时，给它的JSON状态加 `--state <状态.json>`；不能只凭旧版关于三册节奏的文字推定用户授权了二、三册。

## 每批只走这一条路径

0. **计时**：开批先 `python scripts/batch_trace.py --file <批次目录>/trace.jsonl start --batch-id <本批号>`，各步用 `begin/end --phase prepare|investigate|write|inject|repair|gate|verify|publish` 记分步耗时，收尾 `report` 汇总。**只有脚本跑得出的耗时才算实测**；模型写作耗时由操作者按秒表并写明口径，没测就写"未实测"——不要从会话时间戳反推，也不要预报降幅。
1. **定位**：读取被学习项目的 `AGENTS.md`、精简状态、覆盖矩阵和源码变化。首次运行才完成全库文件清单及系统地图；之后只增量更新。范围包含 Java、Python 及实际使用的配置、测试、脚本等文件；不要以语言划分教学深度。
2. **备证据**：批量读取本批源码、真实调用方和相关测试，记录源码版本或脏工作树文件hash。用 `scripts/batch_manifest.py prepare` 生成本批文件清单，再生成骨架。阅读样例只取匹配本批语言与难点的短节；门禁指出特定缺陷才读对应事故与细则。
3. **开批**：用 `scripts/new_batch.py` 从模板生成17节骨架；起笔就按当前完整判据版本写。用 `scripts/inject_source.py` 从真实源码注入代码和真实行号，教学解释另存注释计划。AI写因果、边界、回放和真实项目的AI协作示例，不手抄源码。**注入之前先跑 `scripts/batch_preflight.py`**：它复用闸门的同一套检查函数，直接在计划阶段报出 ★ 签名缺口、无注释连段与可补注的源文件行，并检查注释键是否为真实行号、是否落在注了也不生效的位置（Python 多行字符串/反斜杠续行）。预检 FAIL 先改计划，不要靠在闸门与注入之间反复试错。它同时要求**本批清单覆盖注释计划里的全部源文件**（缺件直接 FAIL，2.30 起）。规则 ID 与结果 schema 见 `scripts/lecture_checks.py`。
4. **组装与修复**：把完整的 `##` 章节分别写成片段，终稿由 `python scripts/batch_build.py --batch <batch.json>` 从「骨架 + 分片 + 注释计划」**重建**（改了注释或分片就重跑，不要手改组装品）。源码块的身份是**稳定槽位**：`new_batch.py --plan ... --batch-json ...` 会在 ⑥ 为每件写一行 `<!-- src-slot id="source:<sha8>:6.N" path=... lines=... sha256=... -->`，槽位 ID + 源路径即身份，标题措辞与块内已替换的文本都不参与寻址——因此"补几条注释再重注入"不需要再猜旧的 `contains` 占位串；源文件 hash 变化时拒绝写入（不会把旧行号套到改过的源码上）。旧批没有槽位标记时自动退回 `anchor`/`contains` 并告警。`--out` 是**终稿**、`--skeleton` 是**骨架**，两者必须是两个文件；注释计划只有 `batch.json` 里 `annotations` 指的那一份可编辑（`plan_source` 只是输入）。构建前 fail-closed 拦住四种"假重建"：骨架=终稿（就地改旧正文）/ `annotations` 指回原始计划 / 分片目录为空 / 某节仍是模板占位原文（缺分片）；`--check` 把 ⑯ 的机器盖章块排除在比对之外（盖章后不该报假差异）。先检查围栏、标题、表格、占位，再运行 `scripts/gate_lecture.py <批次.md> --src <项目根>`；按失败规则ID只改对应片段或注释计划，再重建。必要时用 `scripts/safe_edit.py`，不直接区间替换长篇源码块。
5. **终检与续传**：终稿运行完整单批门禁（`--json <结果.json>` 是结构化结果：稳定规则 ID、状态、**核验对象数**与定位；`NOT_CHECKED`/`ERROR` 不算通过；`--manifest <本批清单>` 才会把该清单哈希写进结果供盖章核对）、`scripts/batch_manifest.py check` 与语义审读；⑯ 表用 `scripts/sync_gate_result.py --result-json <结果.json> --apply` 从结果渲染（先验契约版本与正文/清单哈希，旧结果不得给改动过的正文背书；盖章后自动复跑一次完整闸门并单独记录最终哈希）。根据实际执行记录编译、单测、集成测试和未实测项。更新覆盖矩阵、索引、精简状态；普通教材批次不自动创建五类工程Issue日志。共享判据或工具变更时另跑全库回归。

日常细节在 `references/第一册执行协议.md`；第一册逐节规则在 `references/第一册质量细则.md` §6.4。只读当前要写的节与相关细则，不要每批重读整份细则、`spec/血证档案.md`、所有黄金样例或完整模板。模板由 `new_batch.py` 读取，不需把793行模板全文装入对话。`references/第一册质量卡.md`是短检查表，来自以下质量契约，不可用它取代实际门禁。

## 质量与证据

质量权威是 `spec/00-质量契约.json`；`references/批次讲解全文模板.md`和 `scripts/gate_lecture.py` 应与之同步。保持现有17节和v2.31质量要求，固定篇幅/轮数等契约简化需另起版本、经盲评与负向回归证明不退步。

- ★核心类真实源码完整注入；已列入本批范围的其他文件按复杂度完整解释。正向保真、反向覆盖、方法覆盖与行号核对必须实际执行。不能以“0个被检查对象的PASS”代替检查。
- 代码块的行号与教学注释有明确归属。块内注释解释这一行，逐行要点解释因果，回放说明执行顺序；三处避免机械复写。
- 对每个重要件讲构造、调用、【怎么用】、【上下游】；真实存在扩展契约时讲【怎么接】和【扩展步骤】。保留⑦.5接入路径。
- 每个关键机制说明正常路径、异常路径、状态和副作用。源码事实、历史事实、实测、外部事实与推断分开标。Java与Python都遵守同一事实标准；注释前缀、源码块形式与检查适用范围按语言选择。闸门若对某语言输出零对象 PASS，人工记录为“未检查”，不得把它当作覆盖证据。
- **⑨ 是「八股讲解」（v2.31 起取代原 No-Framework 等价实现）**：按本批真实代码列面试考点（≥6 条，每件至少 1 条），每条 `**【考点】**`/`**【一句话定义】**`/`**【为什么考】**`/`**【本批落点】**` 四段，落点回链 `6.x` 或 `:Lnn`，段末给「本批八股速查表」；八股结论标 `【外部事实】`/`【推断】`，不许冒充源码事实。存量批次仍是旧节 → 报告档不追溯。
- 第一册的⑫保留真实需求、既有资产、方案比较、增量实现、多轮提示词、审查与验证反馈。真实失败只引用真实记录；未发生的场景标“预设验证”，不编造日志或对话。
- 编译通过、测试设计和测试实际通过是不同证据。外部服务无法运行时照常做静态讲解并写“未实测”；不把本批测试结果推成生产可靠。

源码覆盖、围栏安全和真实证据方面的事故及修法见 `spec/血证档案.md`。需要修改判据时再读 `docs/判据变更史.md`、`spec/操作手册-闸门与工具.md`和 `spec/阶段工作流.md`；规则与工具用 `scripts/skill_selfcheck.py`、`scripts/v2_selfcheck.py` 验证。日常不运行全库 `scripts/gate_all.py`；改公共判据或进入阶段收尾时运行。

## 目录与完成状态

第一册默认写入 `<项目>/NOTES/教学讲解/第一册-项目源码与工程实现/`，系统地图、覆盖矩阵、词典和总索引写入 `<项目>/NOTES/`。第二、三册仅按明确请求建立对应目录。工程任务日志默认在项目同级的 `.replicate-learning-log/<项目名>/`，用户指定位置优先。首次写入检查 `.gitignore` 与用户已确认的写入边界。

每次结束写下本批文件范围、已讲与未讲、源码依据、实际运行的命令和结果、失败证据、下一步入口。`已扫描`、`已讲解`、`已核验源码`、`编译通过`、`测试通过`、`用户验收`分别记录。收尾更新覆盖矩阵/总索引/阶段页/精简状态时用 `scripts/publish_batch.py --record <batch_record.json>`：**一份批次记录**渲染全部派生视图，`--dry-run` 先看差异，`--apply` 先验（路径不逃逸、讲义与门禁最终哈希一致、主讲不重复、下一批号不回退）再写，冲突时一个文件都不动，重复运行零变化。**已发布批次的既有行要回修**（例如判据改版后覆盖矩阵/总索引里行内的旧版本号）用同一个工具、第五种 op `update_line`：`anchor` 是回修后仍唯一命中的定位串、`expect` 是该行**当前整行原文**、`text` 是回修后的整行，幂等按目标行现状判；**不许为此另写一次性脚本**（见操作手册 §22.1）。AI只报告证据，最终工程任务验收由用户决定；正常教材批次不强制等待用户做一次Accept选择。

现有项目迁移：用户原本明确要求第一册优先时转为普通默认模式，旧暂停文字留在历史，不再生成二、三册欠账；明确要求三册同步且尚未撤销的项目保留三册范围。旧教材按其声明版本核验，不为新默认批量改写。

扩展册说明见 `references/三本书与工程日志.md`。既有脚本的参数、故障处理和历史判据在 `spec/操作手册-闸门与工具.md`，本入口只给当前工作顺序。
