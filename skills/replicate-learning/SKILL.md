# 复刻式学习方法（技能入口）

> 这是什么：**通过直接复刻一个成熟项目 + 把每类讲透，来快速学会它**。配置/目录等工程惯例从原项目抄，机制/算法也从原项目复制并讲清楚——**不强制使用者手写第一版**，重点是把「它为什么这么做、转译成自己的代码」讲透，让人快速理解。
> 非强制规范，适配而非照抄。
> 深入：方法论全量在 `docs/复刻式学习方法-通用.md`；讲解深度基准在 `examples/黄金样例.md`；可复用模板在 `references/`。

## 面向谁 · 讲解到多深（先立这条，全程贯穿）

- **默认读者 = 初学者**：只假设你**懂一门语言 + 基础语法**（变量、循环、函数、类、基本类型，其余一律不讲默认会）。任何你没见过的词，讲解都必须**当场停下用大白话 + 例子讲一句**，不许甩名词、不许让新手靠猜。
- **解释必须「到底」（术语不自举，无悬空引用）**：任何解释（先修概念/行注释/实现四问/调用链）里出现的每个词，要么是**生活语言或语言基础**，要么是**本文此前已解释过的**——**禁止用术语解释术语**：拿「预检请求」解释 OPTIONS、拿「异步派发」解释 `DispatcherType.ASYNC` 都是悬空（"预检""派发"本身也是生词，等于没解释）。判定法：把解释读给"只会语言语法的人"，每读到一个词他都认识吗？有一个不认识且没铺垫 = 悬空，**继续往下拆到落地为止**。底层机制**首次出现拆到底**，同批内再出现可简写「见先修概念」。
- **每一个类都讲满深度，不做分级降档**：不管这个类是「复杂机制」还是「一个 DTO / 配置 / 常量」这种零件，六段都**完整走一遍、讲到新手能看懂每一行为止**。区别只在于内容的**份量**（机制行多、DTO 行少），**不降讲解深度、不缩结构**。
- **每一步给你的信息都从「初学者视角」写**：先修概念、业务定位图、逐类六段、验收问答、构建验证——所有流程产物都以「一个只懂语言的人能跟着走通」为合格线。
- **代码必须自带详细注释（写进真实源码文件，每处答三问）**：写码落盘时，就把**逐行级中文注释**写进真实的 `.java`/`.py` 等源文件里。每处注释按**三问**写——**①这是什么**：这个 API/机制本身是什么，一句话落到已知地基（解释里出现新词就继续拆，不许悬空）；**②为什么这行要它**：本行的目的；**③不这样会怎样**：反例（关键分支才写）。**只写"为什么"不写"这是什么" = 没注释**（`// 预检放行`四个字不合格，`OPTIONS` 是什么、预检是啥流程必须讲清）。目标：学习者在**不打开任何讲解**的情况下，光看源码文件就能读懂每一段在干嘛。讲解里的「代码逐行」直接照这份已注释的源码讲，不重复劳动。

## 认知主线 · 三层递进（业务 → 架构 → 代码，每类都按这个顺序走）

熟练 vibecoding 的前提，是**先有业务能力 → 再有架构设计能力 → 最后能看懂并掌控代码**。所以每类的讲解，都按这条自上而下的认知主线推进（它**不是新造结构，而是给六段加一条顺序准绳**）：

| 层 | 你要练的能力 | 对应六段 | 这一层讲完，你要能回答 |
|---|---|---|---|
| **第①层 业务能力** | 这软件在解决什么、这个类服务哪个业务闭环动作 | ①业务场景（+ 业务闭环定位图） | 「不写代码时，业务上到底要解决什么？删掉这个类，哪个业务问题会回来？」 |
| **第②层 架构设计** | 它站在系统哪一层、上下游是谁、依赖方向怎样、为什么放这 | ②架构位置 | 「它为什么放这一层而不是别处？谁依赖它、它依赖谁，方向对不对？」 |
| **第③层 代码实现** | 每行干嘛、调了什么、为什么这么写，看得懂、改得动 | ③实现四问 + ④代码逐行 + ⑤调用链（⑥用法是"会用"的收口） | 「这段代码做了几件事、每件事怎么落地、每个 API 干嘛？」 |

**每层讲完 + 每类讲完，都要做「脱手复述测试」（见下）——这是你「可控 vibecoding」的度量器。**

## 核心思路（一句话）

**直接复刻（样板从原项目抄、机制从原项目复刻）+ 讲解讲透**；每类按**六段**讲透（业务场景→架构概念先补→实现四问→代码逐行→调用链→用法），**每一类都讲满深度**；每批 ≤3 类、多轮次依次实现；每批即构建验证；完成归档 `NOTES/阶段N` + 勾完整性地图 + 更新进度表 + commit。**做中学 + 具象化**：直接复刻 + 写码先行 = 动手做（清华 OpenMAIC 的共识：动手优于被动听）；数据流/状态机/调用链等"关系"类内容，能用 ASCII 图/流程图就画一张，别只文字。

## 第一步 · 先问在哪复刻（务必先确认目录）

开始前先问使用者：**要在哪个目录做这次复刻**。据此给目录规范——**官方项目（被复刻的原项目）和复刻目录放在同一级**最好（便于对照 diff、官方只读互不干扰、路径短好找）：

- **本地已有项目**：在**该项目的父目录**下建复刻目录。例：原项目 `D:\dev\myapp` → 复刻目录 `D:\dev\myapp-replica`（同级）。
- **给出 GitHub/远程仓库地址**：先建议一个"项目根"，把官方项目 clone 到该目录，复刻目录也放**同级**。例：`D:\projects\` 下 clone 官方 → `D:\projects\myapp-book`，复刻目录 `D:\projects\myapp-replica`。
- **确认后**：复刻目录 = 本项目根（`AGENTS.md` 就放这里面）；官方项目作为**只读答案卷**始终放在旁边，供对照与 diff。

## 第二步 · 在复刻目录建"开局三件套"

1. `AGENTS.md`：复制模板，填项目名/进度/学习资料指针（模板在 `references/AGENTS.md-复刻增量模板.md`）。
2. `NOTES/阶段对照-完整性地图.md`：把官方项目交付面拆成阶段勾选清单，**★ 标注「重点/难点」**（含算法/状态流转/路由/编排/并发/兜底等逻辑较难、要多花时间讲透的类）。★ 只是「这类的机制逻辑较难、讲透它要花更多工夫」的路标，**不再关联讲解深度**——所有类都同样满深度。
3. `docs/阶段0-开工清单.md`：跑通参照环境的命令序列（阶段0 = **跑通参照**，不是写代码）。

大型项目/多阶段长周期，再额外产出一部《全链路拆解文档》当地图。

## 然后 · 标准讲解循环（每批 ≤3 类；批只控节奏，不降深度）

**对每一批（≤3 类）按序走完这六步。每个类都走**完整六段**；批量只影响"每轮做几个类"，不影响每类深度——每一类都讲满深度。**

- **0️⃣ 先修概念**：把本批涉及、但初学者可能不懂的概念用大白话先解释一遍（不默认会；任何词首次出现给一句话解释）。**扫描范围不只业务/框架词，还包括底层平台与协议机制**——HTTP 方法（GET/POST/OPTIONS…）与 CORS 跨域预检、Servlet 容器/过滤器链/请求分发类型、线程池、序列化……都在内。**判定法**：扫一遍本批代码和讲解草稿，凡"解释它时不得不再用另一个没讲过的词"的，全部进先修（如「预检」要讲，就得连 CORS/跨域一起讲）。
- **1️⃣ 业务闭环定位前置**：先输出「业务闭环定位图」——本批每个类在主链路（如 提问→理解→检索→生成→溯源）的哪一段、服务哪个业务场景，一句白话。从全局定位落到类，禁止孤立地逐类念注释。
- **2️⃣ 《本批类清单表》**：列出本批每个类（**不再分级，统一满深度**）+ 每个类一句「它是干嘛的」（此处不展开讲解，只为让学员先看到全局 X 类；真正的讲解在 ③ 逐类六段）。
- **3️⃣ 整批写码 + 逐类六段讲解**：**先写该批次的全部类**（复刻出你的实现；写码先于讲解，用户可全程对照真实码）→ **再逐个类照码讲六段**（①业务场景→②架构位置→③实现四问→④代码块逐行→⑤调用链≥8跳→⑥用法），**必须 1 类 1 节、禁止合并**（即便整批先写完，讲解也要逐类完整、不揉成一段）；同类样板才可共享"先修概念+调用链"，每类代码块与用法示例必须各自出现。**讲解必须落到已写好的码上逐行讲**；**整批写完不逐类讲=没讲完**。**对初学者友好（六段每一段都适用）**：术语/概念/手法/API 首次出现都用大白话+例子点一句、不许甩名词、**解释禁术语悬空（见上「解释必须到底」）**；**实现四问禁电报体**——「手法：SaInterceptor + UserContextInterceptor」这种名词串不算讲，每个手法必须写完整教学句展开「它是什么 / 为什么用它 / 不用会怎样」。**注释要求（写码这步就做，不是讲解时才补）**：写进真实源码文件的注释要**逐行级中文注解、每处答三问（①这是什么 ②为什么这行要它 ③不这样会怎样）**——类头职责、方法头步骤、每个关键行 + 每个陌生 API/库调用全覆盖；这样讲解④里的「代码逐行」照这份已注释源码直接讲，学习者关掉讲解也能单独读懂源码文件。
- **4️⃣ 每批验收 · 三层三题 + 脱手复述（都附标准答案）**：本批讲完立即验收，**两层都做、且每一题的"标准答案"当场给出（不是只出题让学习者自己猜）**——①**脱手复述测试（每类必做，更强）**：让学习者**合上讲解，光凭自己写的源码（含注释）**，用自己的话复述这个类「业务上解决什么 / 架在哪个位置 / 代码分几件事、每件怎么落地、每个 API 干嘛」；**复述题列出后，紧跟每题的"标准答案"**（一问一答式，按三层组织），学习者复述完照答案核对，磕巴卡壳的点 = 回炉该层；②**三层三题带标准答案（一问一答）**：按三层各出一题——**业务一题 + 架构一题 + 代码一题**，每题**紧跟标准答案**（不是事后打分；答错/含糊的点=回炉该层）。
- **5️⃣ 每批构建验证**：每写完一批立即构建/测试并如实汇报证据（证据先于断言；不许"全部写完再一次性验证"）。
- **6️⃣ 归档（讲解全文落盘 + 工程三件套，讲完即写，不等阶段结束）**：
  - **① 讲解全文落盘到 `NOTES/教学讲解/`（学习资产，「阶段→批次」两级目录）**——**为什么要落盘：聊天窗口会随会话变长被压缩折叠，讲过的内容回头就翻不到了**（真实事故：某阶段批次2 的整份六段讲解在聊天里消失，只能整批重讲）。所以课堂上那份**完整六段讲解必须整篇写进文件**，不是摘要：

    ```
    NOTES/教学讲解/
      └─ 阶段4-system支撑域（Sa-Token认证+审计变更日志）/        ← 目录名带本阶段关键技术
           ├─ 00-阶段总览.md                                    ← 索引：定位 + 批次清单链接 + 进度
           ├─ 批次1-SaToken认证三件套（三件套+UserDO+UserRole）.md
           ├─ 批次2-Auth登录登出（AuthServiceImpl★+LoginVO）.md   ← 文件名带本批核心类
           └─ 批次3-审计写侧（BizChangeLogContext★+RecordService）.md
    ```
    - **命名规则（括号里"跟什么有关"的标注是强制的）**：阶段目录 = `阶段N-<主题>（<本阶段关键技术 2~3 个>）`；批次文件 = `批次M-<一句话主题>（<本批核心类，★ 标重点>）`。**目的**：日后扫一眼目录就知道每批讲了什么、涉及哪些类，不必逐个点开。**约束**：总长 ≤40 字；禁用 Windows 非法字符 `\ / : * ? " < > |`（多个类名用 `+` 连接，别用 `/`）。
    - **每个批次文件 = 课堂那份完整讲解的全文**，八块齐全：先修概念 / 业务闭环定位（含定位图）/ 本批类清单表 / 全局调用链图 / **逐类六段全文**（每类独立一节：①业务场景 ②架构位置 ③实现四问 ④代码逐行·整方法贴全 ⑤调用链≥8跳带类名 ⑥用法+触发回放）/ 验收（脱手复述题 + 三层三题，**题后紧跟标准答案**）/ 构建验证证据 / 溯源与答案卷 diff 结论。模板见 `references/批次讲解全文模板.md`。
    - **写入时机**：**一批讲完立即写该批文件 + 更新 `00-阶段总览.md`**。禁止"攒到阶段结束一起写"——中途开新会话就拿不回聊天里的讲解了。
  - **② 工程三件套（状态与索引，与①分工）**：勾完整性地图对应条目 + 更新 `NOTES/阶段N-主题.md`（**只放机制摘要 / 构建证据 / 下一步等状态与索引，讲解全文一律链接到①**）+ 更新 AGENTS.md「当前进度+下一步」；到验收点 commit（`NOTES/` 是否入 git 按项目约定，此处不强求）。

**深度基准 / 为什么"每批≤3 类"不等于"每批省深度"**：每个类的六段都按 `examples/黄金样例.md` 的**单类**尺度校准（详深度只按"类"计，批量不共享、不稀释）；批只是把 N 个类切成 ≤3 的轮次，避免一次批量过大导致逐类压成大纲句——每个类都走满**同一个满深度**。六段结构与完整性每类不变，份量随类的体量自然伸缩（机制行多、DTO 行少），深度不打折。

## 分批（分阶段 → 分批 → 每类都满深度）

项目先拆成**阶段**；某阶段类多了再**分批**（每批 ≤3 类，多轮次依次实现）。**节奏靠分批控制，不靠降深度省时间**——每一类都满深度讲。

每阶段开工先出**《类清单表》**：列出本阶段每个类 + 该类的「是什么/它干嘛的」一句，学员确认范围后才开讲；不再分档，全部按满深度六段讲。

> 意图：**每一类都满深度**（学深），不分"机制/样板"高下、不做降档；节奏靠**分批**（每批 ≤3 类）控，不靠降深度省时间。**全量六段叙事必须落盘进 `NOTES/教学讲解/阶段N-x/批次M-y.md`**（聊天会被压缩折叠，磁盘才是长期可读的载体），`examples/黄金样例.md` 仍作"讲到什么程度算达标"的基准锚点。清单表模板见 `references/类清单表模板.md`。

> **最少够用 vs 可裁剪**：主流程 = 问目录 + 三件套 + 类清单 + 六段 + 每批验证 + 归档续传（**含讲解全文落盘**）。**进阶件可裁剪**（时间紧就砍，不影响主流程）：《全链路拆解文档》（仅大型/多阶段才需要）、面试题卡、会话分配策略。**砍掉过度设计（YAGNI）**——第一版只做够主流程的最小闭环，别为"以后可能用到"的假设需求加料。
>
> **教学讲解全文不可裁剪**：它是唯一能跨会话回看的讲解载体（聊天会被压缩折叠），砍掉等于讲过即丢失。

## 续传 · "继续复刻"怎么接着做

每个阶段都已归档（`AGENTS.md` 的「当前进度+下一步」+ 完整性地图 + `NOTES/阶段N`）。所以下次用户说「继续复刻 / 接着做 / 再来」，或开了新会话，**先读 AGENTS.md + 完整性地图 + NOTES**，从当前状态续接——不靠对话记忆，磁盘就是记忆。

## 常见翻车

- 一次批量 7 个类 → 必然压成大纲句。每批 ≤3 类、多轮次。
- 讲解与实现不同轮、或"全批写完就收工不讲解" → 先写该批次的类、再逐类照码讲（用户直接看码）；别先空讲后写，也别只写码不逐类讲。
- **任何类被降深度/带过（尤其一个 DTO、配置、常量被当成"样板"一笔带过）** → 每一类都该满深度，别省；哪怕这个类只有 3 行，也要把「它为什么存在、数据从哪来、被谁用」讲透。这是学习深度，不是可省的成本。
- 写码前不先走读 / 不讲调用链+数据流 → 只讲手法名 = 没讲完。
- **写码落盘没写逐行中文注释（或注释没答全三问）** → 学习者打开真实源码文件看不懂每一段在干嘛，等于「代码没交付」。注释必须**写进源码文件**（类头职责/方法头步骤/每关键行+每陌生 API 按三问：①这是什么 ②为什么这行要它 ③不这样会怎样），不是只在讲解消息里贴。
- 不分批构建验证、"全部写完再验证" → 每批即验证，证据先于断言。
- **对初学者甩术语、假设对方"这我该会"** → 每个陌生概念/API 首次出现必须白话点一句，读者定位始终是「只懂语言 + 基础语法」的人。
- **用术语解释术语（悬空解释）** → 拿"预检"解释 OPTIONS、拿"异步派发"解释 ASYNC = 没解释。每个词要么是生活语言/语言基础，要么前文已讲过；有一个悬空就继续拆。
- **注释只写"为什么"不写"这是什么"**（如 `// ② 预检放行` 八个字带过）→ 注释三问少一问 = 没注释，回炉补"这是什么"。
- **实现四问写成电报体名词串**（"手法：A+B""边界：A/B/C"一行完事）→ 每问写完整教学句，手法展开"是什么/为什么/不用会怎样"。
- **代码块标注"节选"** → "节选"就是片段，照样不达标——"源码文件里已有注释"不是节选的理由；④要么贴整方法/整段，要么该类本来很短就整文件贴出。
- **完整讲解只留在聊天消息里、没落盘** → 会话一长就被压缩折叠，回头翻不到（真实事故：某阶段批次2 的六段讲解在聊天里消失，用户问"给了吗怎么没看到"，只能整批重讲）。每批讲完**立即**整篇写入 `NOTES/教学讲解/阶段N-<主题>（技术）/批次M-<主题>（核心类）.md`。
- **目录/文件名不写"跟什么有关"**（如只叫 `阶段4.md`、`批次2.md`）→ 三个月后打开是盲盒，得逐个点开才知道讲了什么。命名必须带主题与技术标注。
