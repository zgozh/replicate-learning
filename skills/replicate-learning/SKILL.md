# 复刻式学习方法（技能入口）

> 这是入口。全细节方法论在 `docs/复刻式学习方法-通用.md`（必读），讲解深度基准在 `examples/黄金样例.md`（讲解前先读它校准），可复用模板在 `references/`。
> 定位：**参考而非照抄**——骨架/配置从答案卷抄（工程惯例），机制/算法自己手写（那才是学到的东西）。
> 诚实边界：注释/代码只写「做什么/为什么」，禁止来源字眼；对外表述「个人结合 AI 辅助 + 自研增量」。

## 何时用（触发条件）

当你正在「照着一个成熟项目学 + 把它复刻成自己的代码」，需要对**每一类**做：先讲懂、再实现、diff、构建验证、归档勾地图。典型触发词：

- 「读 AGENTS.md 和教材第 N 章，继续阶段 N」
- 「进入 ★<类名>」「<类名> 我写完了」
- 「这一批讲完再写」「下一个机制我自己写」

## 何时不要用（When NOT to use，防止越权套用）

| 场景 | 该去哪？ |
|---|---|
| 从零做一个新产品（非学习场景） | `new-project-bootstrap` 主导 |
| 纯分析一个参照项目的架构、提炼模式（不动手复刻） | `architecture-patterns` |
| 用户明说「只要出活 / 量产 / 别讲 / 直接写」 | 可跳过详解直接写码（构建验证不可免），走 `ai-native-dev-workflow` 派活 |
| 写 AGENTS.md / 验收清单 / commit 规范 / 跨会话续接 | `ai-native-dev-workflow` |
| 完成声明前的验证纪律（证据先于断言） | `verification-before-completion` |
| TDD / 执行计划 / 子代理开发 / 代码评审 / git worktree | 对应 superpowers 技能 |

**判断标准：如果用户的目标不是「学懂并复刻一个成熟项目」，就不要让本技能介入。** 六段 / 分级表只服务于「逐类讲透 + 复刻」，套到普通开发任务里会变成枷锁——这正是「在不同地方效果不一」的根源。

## 核心闭环（一句话）

**抄样板（外观/工程惯例）、写机制（自己动手，★必亲手写第一版）**；每类按**六段**讲透（业务场景→架构概念先补→实现四问→代码逐行→调用链→用法），按档位分配讲解深度；每批 ≤3 类、宁多轮不量产；讲完给验收问题（一问一答带答案）；每批立即构建验证；完成后归档到 `NOTES/阶段N`、勾完整性地图、更新进度表、commit。

## 讲解分级规则（重点，防止"每类都一样长、讲解成本失控"）

开工第一步先出**《讲解分级表》**（列出本阶段每个类 + 档位 + 一句分档理由），你确认/调整后才开始讲解——因此**档位是事先定死的，不随讲解中途变**。

| 档位 | 判定（自上而下命中即定） | 讲解深度 | 教学讲解记录 |
|---|---|---|---|
| **★机制**（满深度） | ①完整性地图标了 ★；或 ②含算法/状态机/协调器/路由/竞态/多步编排等**并发、分支、兜底、fail-fast 红线**逻辑；或 ③面试高频、讲"为什么需要+怎么权衡" | 六段全量（场景带具体人/数值、调用链≥8跳带类名、整方法逐行+每手法反例、用法带触发回放） | **机制深卡**（~1-2KB：场景一句带数值 + 非显然关键跳2-3跳 + 每手法一句反例 + 触发回放一行 + 验收问答） |
| **中等**（半深） | 非★，但含多于一根 if-else 的分支/状态流转/字段间校验逻辑 | 场景+调用链+关键代码段+用法，反例挑重点 | 薄摘要（一两行） |
| **样板**（精简） | 纯声明/映射/配置/DTO/常量/枚举/注解/单一用途 TypeHandler | 六段**保留但精简**（一行业务+一行架构+一行契约语义+一行用法） | 薄摘要（一行业务+一行架构+一行用法） |

- **★ 以完整性地图预先标注为准**（人在拆地图时已定，不靠讲解时临时拍脑袋）；中等/样板按"有没有真实算法/分支/竞态逻辑"二分，客观可复现。三者合起来 = 档位确定、不乱的依据。
- 全量六段叙事**不进教学讲解**，留会话记录 + `examples/黄金样例.md` 作基准锚点。
- 开工表模板见 `references/讲解分级表模板.md`。

## 边界契约（本技能只做这五件事）

本技能只管「学习复刻场景」的：①抄样板/写机制分治与排雷阅读法；②完整性地图与 ★必亲手写红线；③大型项目地图先行拆解（v1 冻结）；④选择性复刻（跨栈 mini）；⑤六段讲解+分级+教学讲解纪要。**其余需求一律委派**给上表对应技能，不在此重述（one home per fact）。

## 常见翻车与反模式

- **一次批量 7 个类** → 必然压成大纲句。≤3 类/批，宁多轮不量产。
- **讲解与代码不同批、或"全部写完再统一讲"** → 讲解先行、讲一个写一个。
- **样板也上满深度** → 烧讲解成本；分级表事先定死，不中途变档。
- **★机制让 AI 直接给完整实现** → 违反"自写第一版"；只给骨架等学员手写（学员明确授权代写除外）。
- **写码前不先走读 / 不讲调用链+数据流** → 只讲手法名 = 没讲完。
- **交付码里混入来源字眼**（复刻/参照/来源于）→ 禁止；学习讲解允许溯源（两类文本分开）。
- **不分批构建验证、"全部写完再验证"** → 每批即验证，证据先于断言。

## 快速开始（供新会话遵循）

1. 读 `docs/复刻式学习方法-通用.md` + `examples/黄金样例.md`（讲解前校准）。
2. 开工先出《讲解分级表》（模板在 `references/`）→ 用户确认 → 按档讲解。
3. 讲一个写一个（样板 AI 写；★先给骨架等学员手写，学员明确授权代写除外）。
4. 每批立即构建验证并汇报（铁律见 `verification-before-completion`）。
5. 完成归档 `NOTES/阶段N` + 勾地图 + 更新进度表 + commit。
