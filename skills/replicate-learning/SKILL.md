# 复刻式学习（技能入口 · 讲解中心版）

> 这是什么：**照着成熟项目，AI 负责复刻 + 把每个文件讲透，讲解全文落盘成可反复阅读的教材**，读者快速吃透「业务 → 架构 → 代码 → 底层机制 → 工程判断」。
> 时代前提：**vibecoding**。你自己不用手写代码——未来代码由 AI 产出、你负责看懂、判断对错、下指令。所以**本技能不要求读者动手写码 / 复述 / 交作业**，一切"动手才学得会"的东西都**转译为讲解文本直接讲给你**。
> 核心交付物：**《教学讲解》落盘文件**（聊天会被压缩折叠，磁盘上的完整讲解才是你的教材）。
> 非强制规范，适配而非照抄。深入：方法论在 `docs/复刻式学习方法-通用.md`；深度基准在 `examples/黄金样例.md`；空白模板在 `references/`。

## 面向谁 · 讲解讲到什么程度（先立这条，全程贯穿）

- **读者 = 初学者 + 未来指挥者**：只假设你**懂一门语言 + 基础语法**（变量/循环/函数/类/基本类型，其余一律不讲默认会）。但你的**目标不是"写得出来"，是"看得懂、讲得清、判断得准"**——AI 给的代码对不对、哪里会出故障、该让 AI 怎么改，你要能判断。任何你没见过的词，讲解必须**当场停下用大白话 + 例子讲一句**，不许甩名词。
- **解释必须「到底」（术语不自举，无悬空引用）**：任何解释里出现的每个词，要么是生活语言或语言基础，要么是本文此前已解释过的——**禁止用术语解释术语**（拿「预检请求」解释 OPTIONS、拿「异步派发」解释 `DispatcherType.ASYNC` 都是悬空）。判定法：把解释读给"只会语言语法的人"，每读到一个词他都认识吗？有一个不认识且没铺垫 = 悬空，**继续往下拆到落地为止**。底层机制首次出现拆到底，后续出现可简写「见概念词典 §X / 见批次N」。
- **每一个件都讲满深度，不做分级降档**：不管它是复杂机制还是一个 DTO / 配置 / 常量零件，讲解都**完整走到"读者能看懂每一行为什么存在"为止**。区别只在**份量**（机制行多、零件行少），**不降深度、不缩结构**。零件类用紧凑讲解模板（见 `references/零件类讲解模板.md`），深度不减、篇幅更省。
- **讲解的可验证标准 = 读者看完能自己讲清并判断，而不是能默写**：每处讲解都以「一个不写码的人听完能向别人转述、能指出 AI 这么写对不对、哪里会咬人」为合格线。
- **代码注释仍然必须写进真实源码（AI 写码时做，每处答三问）**：虽然读者不手写，但**源码是你对照讲解的第一手材料**——AI 复刻落盘时就把逐行级中文注释写进真实源文件，每处答三问——**①这是什么**（这个 API/机制本身是什么，落到已知地基，出现新词继续拆）；**②为什么这行要它**；**③不这样会怎样**（反例，关键分支写）。讲解④直接照这份已注释源码讲，读者光看源码也能读个大概。

## 底层穿透（防「API 调用工程师」，硬要求；讲解给足，读者零动手）

这类项目的代码大多是**层层包装的框架 / 外部工具 / 中间件 SDK 调用**。如果讲解只是「这行调 X 的 Y 方法做 Z」，读完 = 记住一份 API 清单，**换个框架就归零**。所以**凡遇到框架/外部工具/中间件/SDK 调用，一律往下剥**。穿透以 **L0~L4** 五层执行，全部由 AI 查证后**写进讲解**，读者阅读吸收即可、不必自己动手验证：

| 层 | 要回答什么 | 在讲解里的落点与达标句 |
|---|---|---|
| **L0 源码实证（所有机制性调用必做）** | 它内部到底靠什么做到的？证据在哪？ | **贴真实源码片段 + 文件 + 行号**（IDE 跳转 / 反编译 jar / GitHub 源码仓库）。禁止凭记忆写机制。拿「用 @Around 环绕」「ThreadLocal 是线程私有」这类当结论 = 悬空，要拆到「Spring 给 Bean 生成代理对象、方法调用先过代理 invoke」/「数据存在 Thread 对象的 threadLocals 表里」这种能看到源码的落地层 |
| **L1 机制层（所有外部调用必做）** | 它替你干了哪几件事，每件怎么做到的？ | 把「框架替你做的 N 件事」逐件拆到"换我自己写是哪些步骤"，能指到关键类/方法名就指 |
| **L2 手写示范（★ 类与核心依赖必做）** | 不用它，等价实现长什么样？ | AI 给出 20~40 行等价手写代码**作为讲解示范**（**读者阅读即可，不需要自己写**），且要**够真**——逐条写出框架真正替你扛的边界（ThreadLocal 清理 / 失败改写 / 模板求值 / 松散绑定递归 / 转义解析 / 连接池）。判定「够真 vs 玩具骨架」见下 |
| **L3 取舍层（★ 类必做）** | 它为什么这么设计？不用它会出什么**具体**故障？ | **分钟级时序推演**：哪个请求、第几毫秒/第几秒、出什么具体错（"业务 01.250 rollback 把审计一起回滚""第 3 个并发请求读到脏数据"）。「难维护 / 易出错」这类形容词不合格 |
| **L4 故障实证（★ 中间件依赖，做得动就做）** | 真破坏一下会看到什么？ | AI **替读者真跑实验**：删掉一行 `clear()` / 停掉 Redis / 把事务放错层，跑一遍**贴真实报错/日志/数据行**当讲解素材。做不动就退回 L3 推演并注明"这是推演，未实测" |

**L2「够真」vs「玩具骨架」的硬判定（约束 AI 的示范质量，不是让读者写）**：手写示范写完逐条核对——它写出框架真正替你兜的边界了吗？至少 3~4 条才算够真：

| 骨架与否 | 判定 |
|---|---|
| ❌ 玩具骨架 | 只写"try/catch + save/取数"30 行就完事，框架替你扛的**清理 / 失败改写 / 模板求值 / 解耦 / 递归嵌套 / 转义解析 / 连接池**边界一条没提，读者看完"就这？"感受不到框架价值 |
| ✅ 够真 | 把边界逐条显式写出并**点明它们去哪了**（如 @ConfigurationProperties：松散绑定 `open-duration-ms→openDurationMs`、递归嵌套 `providers.ollama.url`、List/Map 自动绑定、`${}` 占位符解析、缺省默认值） |

**L3「具体故障」vs「形容词」的硬判定**：写成"哪个请求、在什么时刻、出什么具体错"（如「业务 01.250 提问 → 读到全 null 的配置 → 选不出模型 → NPE，且因启动时没校验、运行时才炸」）才算；「代码会难维护 / 容易出错 / 不优雅」不算，回炉。

**零件类 ≠ 说明书（防把 DTO/枚举/配置讲成字典）**：零件类讲解同样要有**具体的人在用 + 方案对比 + 反例**（"同事把 'bailian' 拼成 'BaiLian'，路由 equals 失配静默跳别家"），而不是"它存了这几家的 id"。凡讲解里出现"它就是个枚举/这很简单"，说明滑向说明书，回炉成"谁在什么时候会被它咬一口"的镜头。

**示例密度**：每批至少 **1 处完整穿透**（L0+L1+L2+L3 齐全，给本批最"包装"的那个依赖）；其余非核心 API 至少做 L0+L1；**★ 类打满 L1~L3（L4 能跑就跑）**。穿透落在该类的讲解小节内（③ 手法问 / ④ API 三问注释的「这是什么」/ 类末工程视角 / No-Framework 手写示范节），不另设孤立的第七段。

**穿透点清单（每批开工先列、逐条销号）**：写码前先把本批代码里**每个外部调用点**列成清单（框架注解 / ORM / 工具方法 / Starter / 客户端…），逐条判「归哪类、穿到哪层、销号了吗」：

| 调用点类型 | 穿透要求 | 销号动作 |
|---|---|---|
| 本批**新出现**的框架/工具调用 | 至少一处完整穿透，其余 L0+L1 | L0 贴源码证据（无「扫描/改写/环绕/线程私有」悬空词）；L1 拆到底；L2 手写示范够真；L3 有分钟级时序；★类尽量 L4 |
| 前面批次/黄金样例**已穿透**过的调用 | 不重复拆，但**显式引用**「机制见批次N / 黄金样例 §X / 概念词典 §X」 | 引用一句话 + 指向，不让读者以为没讲 |
| 语言/平台级（JDK 内置） | 首次拆到底，之后「见概念词典」 | 同「解释必须到底」条 |

**判定（防糊弄）**：写完自问「我是不是还在用『扫描/改写/环绕/私有/解析』这类悬空动词？它到底落到哪个类、哪个方法、哪个字段？」答不上 = 没拆到底，回炉。参照 `examples/黄金样例.md` 的例④：@TableLogic 若只写「MP 扫描实体后改写 SQL」就是悬空，要拆到「TableInfoHelper 解析 @TableLogic 进 TableFieldInfo.logicDelete → DefaultSqlInjector 按实体有无逻辑删除字段选 SqlMethod.LOGIC_DELETE_BY_ID（生成 UPDATE）而非 DELETE_BY_ID → select 的 where 由 TableFieldInfo 自动 append AND deleted=0」。

## 认知主线 · 三层递进（业务 → 架构 → 代码，讲解一律按此顺序）

| 层 | 读者要获得的能力 | 对应讲解内容 | 读完后读者能回答 |
|---|---|---|---|
| **① 业务能力** | 这软件解决什么、这个类服务哪个业务闭环动作 | 业务场景（具名人物+数值）+ 业务闭环定位图 | 「不写代码时业务上要解决什么？删掉这个类哪个业务问题会回来？」 |
| **② 架构能力** | 它站在哪层、上下游谁、依赖方向、为什么放这 | 架构位置 + 系统全景地图定位 | 「为什么放这层不是别处？谁依赖它、它依赖谁？」 |
| **③ 代码能力** | 每行干嘛、每个 API 内部怎么做到、为什么这么设计、会怎么坏 | 实现四问 + 代码逐行 + 调用链 + 工程视角 | 「这段代码分几件事？AI 写的对不对？哪里会出故障、怎么定位？」 |

**认知主线在项目维度同样成立**：先**系统全景**（整体）→ 再**阶段 → 批次 → 单类**（部分）。不许一上来钻进某个类。

## 学习怎么发生（阅读者的工作流）

你是**读者**，不是**作业者**。你的动作只有：**读讲解 → 想（用自己的话在心里讲一遍）→ 不懂就问 AI → 翻源码对照**。技能流程（AI 执行）保证每批产出：可读源码 + 完整讲解落盘 + 构建证据 + 词典更新。**没有"你必须先自己写 / 先复述 / 手写 20 行才能过"的门禁。**

讲解本身要替读者覆盖"原本靠练才能会"的四种能力，**以读代练**：

| 原本靠练习获得的能力 | 讲解里怎么直接给你 |
|---|---|
| 设计判断力（为什么这么设计） | **直觉对照**小节：先讲"一个照抄者/新手本能会怎么写、会漏什么、为什么翻车"，再讲答案卷为什么这么设计——把"先想错再纠正"的认知冲击直接写进文本 |
| 排错力（出故障怎么定位） | **故障情景**小节：具体故障 → 现象 → 排查步骤（从日志/堆栈哪一行看起 → 怎么缩小范围 → 定位到哪个类哪一行），讲给读者看，配 L4 真跑证据 |
| 测试眼光（怎么验证代码对） | **测试视角**小节：这个类该测哪几条分支、造什么输入、断言什么、典型坑（如 mock 时 `excludePathPatterns(String...)` 与 `List<String>` 重载歧义），以讲代练 |
| 工程史观（设计为什么长成这样） | **演进视角**小节：AI 跑 `git log -p / blame`，讲这个类被哪些 bug/需求改过、为什么变成现在这样 |

## 第一步 · 先问在哪复刻（务必先确认目录）

开始前先问：**要在哪个目录做这次复刻**。官方项目（被复刻的原项目）与复刻目录放**同一级**最好（diff 方便、官方只读互不干扰）：

- **本地已有项目**：在**该项目父目录**下建复刻目录。例：原项目 `D:\dev\myapp` → 复刻目录 `D:\dev\myapp-replica`（同级）。
- **给出 GitHub/远程地址**：先建议"项目根"，官方 clone 进去、复刻目录也**同级**。例：`D:\projects\myapp-book`（官方，只读）+ `D:\projects\myapp-replica`（你的复刻）。
- **确认后**：复刻目录 = 本项目根（`AGENTS.md` 放这）；官方项目作为**只读答案卷**始终放旁边，供对照与 diff。

## 第二步 · 开局四件套（整体到部分的第一步）

1. `AGENTS.md`：复制模板填项目名/进度/资料指针（`references/AGENTS.md-复刻增量模板.md`）。
2. **`NOTES/00-系统全景地图.md`（新增，强制）**：开工先产出**《系统全景地图》**——这是"从整体到部分"的第一课，之后每个类都能挂回这张图。五件内容与模板见 `references/系统全景地图模板.md`：①运行时部署图（进程/端口/中间件/外部依赖，每个框"挂了会怎样"）；②一条请求打穿全栈（**真跑一遍抓完整链路**，贴真实日志/堆栈，不是画出来的）；③数据模型全景（ER + 表↔模块读写矩阵 + 每张表"为什么这么设计"）；④模块依赖方向图（每模块一句话职责 + "删掉它哪个业务问题回来"）；⑤**业务约束 → 架构决策推导链**（QPS/数据量/一致性/延迟/成本 → 为什么选 MySQL 不选 PG、为什么要 Redis/MQ，每条给备选与不选理由）。全景地图边学边回填修正。
3. `NOTES/概念词典.md`（新增，强制）：全局概念大白话词典（模板见 `references/概念词典模板.md`）。每批的新词讲完即回填；后面批次遇到已收录词只写「见概念词典 §X」，不重复展开——**这是讲解去重、省篇幅、可复习的关键**。
4. `docs/阶段0-开工清单.md`：跑通参照环境的命令序列（阶段 0 = 跑通参照 + 抓那条"打穿全栈"的请求链路）。

大型项目/多阶段长周期，再额外产出一部《全链路拆解文档》当地图。

## 然后 · 标准讲解循环（批次 = 相关类聚合；批只控节奏，不降深度）

> 流程里"写码 / 构建 / diff / 查证 / 跑实验"全部由 AI 执行，**读者不承担任何提交动作**；读者的产出只有一个——**读懂了，随时能提问**。

**每批按序走完下面八步。每批 = 一个可运行的最小实现增量 + 一份完整讲解落盘。**

### 批前 Gate（写码前必过，保证讲解质量不漂移）

**Gate 1 · 穿透点清单（先查证再写码）**：扫出本批每个外部调用点填表（真实机制 + 真实类名 + L0 源码证据出处 + L2 一句话 + L3 一句故障 + 是否已穿透引用），凭训练记忆写「扫描/改写/注册」这类悬空动词 = 没查证 = 停下重查。**表填完，写码时的三问注释与讲解里的穿透直接照它写，不重复劳动。**
**Gate 2 · 讲解骨架（讲解动笔前）**：对照 `examples/黄金样例.md` + 本项目最近一份"你满意"的批次文件，先写出每类的讲解子标题 + 每段一句话要点（场景人物数值 / 架构层位 / 四问哪几条 / 穿透落点 / 工程视角给不给），确认齐了再填全文。**禁止不打开基准直接开写。**

### 每批八步

- **0️⃣ 本批地图**：一句话说清本批在主链路的位置（挂在系统全景地图哪一块）+ 件与件的关系图。给读者空间感，禁止孤立逐类念。
- **1️⃣ 先修概念**：本批新词用大白话 + 生活化类比讲一遍（token=游乐园手环、Redis=键值仓库、HTTP 请求=信封+信纸、AOP=给方法门口挂门帘）——**只讲新词**；已收录词引用「见概念词典 §X」。每句 = 大白话 + 类比/例子，**禁止「术语→术语」**（"AOP=在方法前后插逻辑的技术"是纯定义、无钩子，不合格）。扫描范围含底层平台与协议词（HTTP 方法/CORS/Servlet 容器/线程池/序列化…）。
- **2️⃣ 业务闭环定位**：本批在主链路（如 提问→理解→检索→生成→溯源）的哪一段 + 定位图 + 一句「删掉这批会怎样」。本批定一个**贯穿人物**（运营小李/审计老王…），从定位到每类场景都用 TA，像连续剧。
- **3️⃣ 类清单表**：本批每个该复刻文件（类 + 建表脚本 + 配置文件都算）一句「它是干嘛的」。先让读者看到全局 X 件，再逐件展开。
- **4️⃣ 整批写码（AI）+ 逐件讲解（读者阅读）**：**先写该批全部件**（复刻出实现，源码自带三问逐行注释）→ 构建验证跑通 → **再逐个件照码讲**（讲解结构见 `references/批次讲解全文模板.md` 的"每类讲解结构"，1 件 1 节，禁止合并；同类样板才可共享先修+调用链，代码与用法各件自出）。每个件的讲解按**六段 + 视需要追加工程视角**：
  - ① **业务场景**：具名人物 + 具体数值 + 镜头感 + 期望结果（"运营小李把 200MB 知识库文档传上去"）。出现"用户/请求/系统"而无名无数值 = 抽象句，回炉。零件类同样要有"谁在什么时候被它咬一口"的镜头。
  - ② **架构位置**：放哪层、上下游、依赖方向、为什么在这（挂回系统全景地图）。
  - ③ **实现四问 = 开发四问**（完整教学句，禁电报体名词串）：**思路**（解决什么 + 分几步 + 为什么这么拆）→ **设计决策**（为什么这么设计？备选方案？为什么选这个？代价？）→ **手法**（每个手法 = 是什么 → L0/L1 内部怎么做到 → L2 手写示范 → L3 不用会怎样，穿透融进这里）→ **数据流与边界**（数据怎么流转 + 异常/并发/降级/边界在哪怎么兜底）。
  - ④ **代码逐行**：贴**整方法**（不标"节选"），照源码三问注释逐行讲，每个陌生 API 的「这是什么」答到机制层。
  - ⑤ **调用链 ≥8 跳**：每跳带真实类名/方法名 + 一句大白话"它干嘛"，结尾给读法提示（"断在第 N~M 跳 = 还没懂的点"）。
  - ⑥ **用法 + 触发回放**：可照跑的请求/输入 → 逐段流转 → 返回长什么样。**末尾给 No-Framework 手写示范**（★ 类必给整段、其余至少"手写要做哪几步"——**作为理解机制的讲解内容，明确写"阅读即可，不必自己写"**）。
  - ⑦ **工程视角（视需要配给，不是每类都全）**：见上文"以读代练"表——直觉对照 / 故障情景（配 L4 证据）/ 测试视角 / 演进视角 / 横向对照（同机制别的项目怎么做），按这个类的"值得讲"程度选 1~2 个。
- **5️⃣ 讲解内核对问答（纯阅读，无提交无卡关）**：本批讲完，文件里给出**核对问答 + 标准答案**（一问一答：业务问 / 架构问 / 代码问各若干，题数随本批知识点与难点数浮动，每层至少 1 题）。**读者自己看完答案对一下**，哪题答不上就回去重读对应段（或直接问 AI），**不设门禁、不卡进度、不需要交任何东西**。想检验"真懂没"，读者可自己合上文件复述——但那是可选动作，不是流程要求。
- **6️⃣ 构建验证证据**：AI 每批跑构建/测试，贴真实证据（命令 + 关键输出）。**证据先于断言**，未跑不得宣称完成。
- **7️⃣ 归档 + 落盘 + commit**：
  - **① 讲解全文落盘到 `NOTES/教学讲解/`（本技能唯一核心交付物，讲完即写，不等阶段结束）**——聊天窗口会随会话变长被压缩折叠（真实事故：某阶段批次2 的整份六段讲解在聊天里消失，只能整批重讲），**磁盘上的完整讲解才是你的教材**。目录与命名见下。
  - **② 回填**：本批新词回填 `NOTES/概念词典.md`；修正/回填 `NOTES/00-系统全景地图.md`。
  - **③ 工程三件套（状态与索引，与①分工）**：勾完整性地图 + 更新 `NOTES/阶段N-主题.md`（只放状态与索引，讲解全文一律链接到①）+ 更新 AGENTS.md「当前进度 + 下一步」。每批验证通过即 commit（一批一个 commit = 一个可运行最小增量；`NOTES/` 等学习件是否入 git 按项目约定）。

### 教学讲解落盘规范（名字带"跟什么有关"，扫目录即知内容）

```
NOTES/教学讲解/
  └─ 阶段4-system支撑域（Sa-Token认证+审计变更日志）/        ← 阶段目录名带本阶段关键技术 2~3 个
       ├─ 00-阶段总览.md                                    ← 索引：定位 + 批次清单链接 + 进度
       ├─ 批次1-SaToken认证三件套（三件套+UserDO+UserRole）.md
       ├─ 批次2-Auth登录登出（AuthServiceImpl★+LoginVO）.md   ← 批次文件名带本批核心类，★标重点
       └─ 批次3-审计写侧（BizChangeLogContext★+RecordService）.md
```

- **命名约束**：总长 ≤40 字；禁用 `\ / : * ? " < > |`（多类名用 `+` 连接）；括号标注是强制的。
- **每个批次文件 = 读者教材全文**，块齐全：本批地图 / 先修概念 / 业务闭环定位 / 类清单表 / 逐件详解全文 / 核对问答（带答案）/ 构建证据 / 溯源与 diff 结论。模板见 `references/批次讲解全文模板.md`。
- **落盘前自查**（对照 `examples/黄金样例.md`「讲解产出自查」）：①场景有具体人+数值吗 ②调用链 ≥8 跳带类名吗 ③代码整方法没标"节选"吗 ④用法能复制改改就跑吗 ⑤先修带生活化类比吗 ⑥讲解独立成节没压成一行式吗 ⑦关键依赖穿透了吗（L0 源码证据？★ 类给了 L2 手写示范 + L3 具体故障？）⑧「不用会怎样」是具体故障不是形容词吗。
- **写入时机**：**一批讲完立即写该批文件 + 更新 `00-阶段总览.md`**。禁止"攒到阶段结束一起写"。

## 分批（分阶段 → 按「相关类聚合」分批 → 每件都满深度）

- **阶段划分先立能力主线**：阶段 0/-1（系统全景+跑通）→ 地基层 → 支撑域 → 业务域 → 收官对照。每阶段开工先出《类清单表》确认范围。
- **批 = 当前做的那件事涉及的相关类聚合**：一批装「同一件事/同一自洽主题」的件（3~9 件合理区间，数量不设死上限）。**判定标准：每个件还能不能讲满、不压成大纲句**。十几个/几十个件塞一批 = 必然压成大纲句 → 按主题切块多批（写侧/读侧、地基/入参/真身），宁多批不量产；反过来 3~5 个强相关件也不该硬拆成单件批。
- **每批 = 一个可运行的最小实现增量**：写完即构建验证 → 讲解 → 落盘 → commit。
- **讲解覆盖面 = 复刻范围内官方所有文件**：不只 .java——建表 SQL（建了什么表/每列动机/索引为什么这样建）、yaml（每个旋钮语义/怎么被注入）都要入表、都要讲。

> 意图：每一件都讲满深度（学深），节奏靠按主题分批控，不靠降深度省时间。**全量讲解必须落盘进 `NOTES/教学讲解/阶段N-x/批次M-y.md`**（聊天会被压缩折叠，磁盘才是长期可读的载体），`examples/黄金样例.md` 是"讲到什么程度算达标"的锚点。
>
> **可裁剪（时间紧就砍，不影响主流程）**：《全链路拆解文档》（仅大型多阶段）、横向对照/演进视角（可选深潜）、L4 故障实证（做不动退回 L3 注明未实测）。
> **教学讲解全文不可裁剪**——它是你唯一能跨会话回看的教材，砍掉等于学过即丢。

## 续传 · "继续复刻"怎么接着做

每批都已归档（AGENTS.md「当前进度+下一步」+ 完整性地图 + `NOTES/阶段N` + 教学讲解）。下次说「继续复刻 / 接着做」，**先读 AGENTS.md + 系统全景地图 + 概念词典 + 完整性地图 + NOTES**，从当前状态续接——不靠对话记忆，磁盘就是记忆。

## 常见翻车（讲解中心版）

- 十几个类硬塞一批 → 压成大纲句。按「相关类聚合」拆批（3~9 件），宁多批不量产；也别把 3~5 个强相关件硬拆单件批。
- **讲解停在 API 清单、不穿透**（"这行调 `eq(...)` 拼条件"）→ 防 API 调用工程师：每个外部调用 L0 贴源码证据 + L1 拆到底，★ 类给 L2 手写示范（够真）+ L3 具体故障。判定法：把所有 API 名换成别的框架同款，讲解还成立吗？成立 = 只讲了调用姿势。
- **穿透卡停在悬空动词**（"用 @Around 环绕""ThreadLocal 是线程私有"）→ 环绕 → 代理对象（JDK 动态代理/CGLIB 子类）；线程私有 → Thread 对象的 threadLocals 表。穿透不是"高级先修概念"，同样不许甩名词。
- **L2 手写示范写成玩具骨架**（try/catch+save 30 行）→ 把框架真正替你扛的边界写出来并点明它们去哪了（清理/改写/求值/解耦/递归/转义/池化，至少 3~4 条），读者才感受得到框架价值。
- **「不用会怎样」写成抽象形容词** → 必须具体"人-时-错"三元组（哪个请求、第几毫秒、什么错）。形容词回炉。
- **零件类被讲成说明书**（"它存了这几家 id"）→ 要有具体的人在用 + 方案对比 + 反例（"同事把 'bailian' 拼成 'BaiLian'，equals 失配静默跳别家"）。
- **概念重复展开、不引用词典** → 先修概念只讲本批新词，已收录词一律「见概念词典 §X」。
- **讲"整体"缺席、一上来钻类** → 先出系统全景地图（五件），每个类讲解挂回地图定位；没有全局的局部讲解 = 盲人摸象。
- **把讲解写成"你回去自己练"** → 读者是阅读者不是作业者：练习型内容（设计判断/排错/测试眼光/工程史）一律**以读代练**转译进讲解文本（直觉对照/故障情景/测试视角/演进视角小节）。
- **完整讲解只留在聊天里、没落盘** → 会话一长被压缩折叠就翻不到（真实事故）。每批讲完**立即**整篇写入 `NOTES/教学讲解/阶段N-<主题>（技术）/批次M-<主题>（核心类）.md`。
- **目录/文件名不带"跟什么有关"**（只叫 `阶段4.md`）→ 三个月后是盲盒。命名必须带主题与关键技术标注。
- **把上一批的数字当常量照抄**（真实事故：批次2 是 6 类、批次3 有 8 类，验收却沿用固定题数，标题写成「类 8/6」）→ 所有数量随本批动态：类编号分母 = 本批件数、核对问答题数 = 本批知识点/难点数，没有固定数字。
- **代码块标"节选"** → 节选 = 片段 = 不达标；④要么贴整方法/整段，要么类短就整文件贴。
- **先修概念写成"术语→定义"、无类比** → 每个词带生活化类比（token=手环、Redis=仓库、AOP=门帘），类比是记忆钩子。
- **讲解不落到已写好的码上**（先空讲后写、或只写码不逐件讲）→ 先写该批件（AI）、再逐件照码讲；每件独立成节。
- **构建验证"全部写完再一次性做"** → 每批即验证，证据先于断言；测试也是讲解素材（测试视角讲"该测哪几条、怎么断言、有什么坑"）。
