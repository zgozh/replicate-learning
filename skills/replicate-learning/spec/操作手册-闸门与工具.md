# 操作手册：闸门与工具（从 SKILL §6.4「每批合规性自查」搬出的操作性内容）

> 规则条文在 SKILL §6.4 / 契约条目在 `spec/00-质量契约.json`；本文件只放**怎么敲命令、怎么修、怎么核**。
> 判定口径见 SKILL §6.4 的判定表；版本与变更规程见 SKILL §6.6。

## 0. 开批之前：预检（`batch_preflight.py`）——**先报缺口，再动笔**

```bash
# 注入/写作之前跑一次：注释计划的结构 + 与闸门同口径的密度/★签名/★反向 + Python 注入安全
python "<skill>/scripts/batch_preflight.py" --src <源码根> --plan <注释计划.json> \
       [--manifest <本批清单.json>] [--lecture <已组装的批次.md>] [--json preflight.json]

#   退出码 0 = 预检通过；1 = 有 FAIL（每条都带文件与行号，改计划后重跑即可）
#   规则 ID（与 spec/00-质量契约.json 条款挂钩，见 scripts/lecture_checks.py 的 CHECK_GROUPS）：
#   P-PLAN   注释计划结构：键必须是真实行号；拼错/重复/越界/落在 Python 字符串或反斜杠续行上 = 错误
#   P-HASH   源文件 hash 与 manifest 一致（不一致立即停止，不再往下判）
#   P-DENSITY 关键行无中文注释连段 <8、注释条数 ≥ 关键行÷12（与 gate_lecture.check_density 同函数）
#   P-SIG    ★类方法签名注释覆盖（按整类、跨块，与闸门 ③c 同函数）
#   P-REVERSE ★类源码行反向覆盖（注入前就知道会不会漏行）
#   P-PY     Python 块：哪些行因语法限制不会被标注（不是错，是别写在那儿）+ 内存 compile() 语法检查
#   P-ADDR   anchor/contains 或稳定槽位必须唯一命中（零命中与重名都 fail closed）
#   P-SNIP   【怎么用】/【怎么接】教学片段：语法、花括号、构造参数个数与明显类型错位 → FAIL；
#            参数顺序与第三方 API 行为标 manual_review（**不声称可编译**）
#   P-SCOPE  本批适用的 17 节清单 / ⑫ 八条 / 证据等级（不必把整份细则灌进上下文）
```

**为什么先跑它**（第48批实录）：那一批是**注入之后跑闸门才知道**「★ 签名缺 3 处、密度连段 5 处」，
随后临时写了两个探针脚本（还因 API 误用失败两次），扫出来的数还和闸门不一致。
预检复用闸门自己的检查函数，所以**预检说什么，终检就说什么**。

**结果 schema 与规则 ID 的单一来源**：`scripts/lecture_checks.py`（`PASS/FAIL/REPORT/NOT_CHECKED/ERROR`
五个互斥状态；`NOT_CHECKED`（零对象）与 `ERROR` **都不算 PASS**；结果里带 `lecture_sha256` /
`source_manifest_sha256` / `contract_sha256`，供盖章前校验"不是拿旧结果给改过的正文背书"）。

## 1. 每批落盘后：一条命令

```bash
# 权威判定（七项一次跑完，退出码 0 才算过；快照自动读批头「源码依据：commit <sha>」）
python "<skill>/scripts/gate_lecture.py" "<批次.md>" --src <源码根目录> [--snapshot <commit>] [--json out.json]

#   ⓪ 结构：节数=17 / **17 个一级节标题按规范形态命中**（带圈数字丢失/多余空格=FAIL 并打印实际标题原文，2.15）/ 围栏偶数**且配对**（块内不得再出现带语言标签的围栏、`### ` 标题不得落入块内）/ 占位=0（含中文的 `__占位__` 也算，2.9）/ ⑫ 八条=8、八段=8、自指=0、回链≥1、无薄条 / **⑫ 无「回顾语」**（回顾性重构/本批已实现/回看这一批 等以"已有该批成果"为前提的表述，2.16）
#   ⓪b 每批必含内容（2.17）：① 有架构图（围栏块 ≥5 行连接符 + 图中 ≥3 个标识符能在仓库找到）/ ⑦.1 有 ≥5 跳编号链且每跳带行号 / ⑧ 有 L0~L3 层级标签 + 「省略了什么生产边界」段
#   ⓪c 教材自足与构造手法（2.18 · **报告档不计 FAIL**）：代码块白话开场覆盖率 ｜ ⑥ 件构造方式/手法点名统计
#   ① 正向保真：每个 java 块逐行须在「当前树或本批快照」找到（只在快照命中 = 源码演进，不计 FAIL）
#   ② 反向完整：★类源文件每个有效行都要出现在讲解里（★ 在父标题同样计入；多块按并集）
#   ③ 注释密度：连段 <8 / 条数 ≥ 关键行÷12 / ★类方法签名有注释
#   ④ 行号一致性：`// :Lnn` 必须就是该内容真正所在的行
#   ⑤ 用法与接入：每件【怎么用】【上下游】；抽象件【怎么接】；批级 ⑦.5（≥3 步）；**位置**——【怎么用】必须排在「逐行要点表」之后、件内 `---` 之前
#   ⑥ 散文符号真实性：正文（围栏外）里的 `Xxx.java:NN` 引用 / 件标题声明的 `.java` / `本仓类.method(` 三类必须真实存在；
#      反引号里的其他 CamelCase 符号走 spec/散文符号白名单.txt + 待确认清单（不计 FAIL）
```

`--json` 输出的是**结构化结果**（schema v1：`checks[]` 带稳定规则 ID / 状态 / 核验对象数 / 定位，外加
`contract_version`、`lecture_sha256`、`source_manifest_sha256`、`pass`），规则 ID 与
`spec/00-质量契约.json` 条款挂钩（见 `scripts/lecture_checks.py` 的 `CHECK_GROUPS`）。
五个状态 `PASS / FAIL / REPORT / NOT_CHECKED / ERROR`：**核验对象为 0 记 `NOT_CHECKED`，不算通过**；
`ERROR`（检查器出错）同样不算通过。旧字段（`fidelity`/`reverse`/`density`/`lineno`/`usage`/`form`/
`struct`/`snapshot`/`ver_marked`/`pass_`）**保留**，判据回归比对仍可逐字段比。

```bash
# ⑯ 的实测表：从结构化结果渲染（推荐），盖章前先验哈希与版本，盖章后再复跑一次完整闸门
python gate_lecture.py <批次.md> --src <仓库根> --json gate-result.json
python "<skill>/scripts/sync_gate_result.py" <批次.md> --src <仓库根> \
       --result-json gate-result.json [--manifest <本批清单.json>] [--apply] \
       [--final-json gate-result.final.json]
#   不给 --result-json 时仍走旧路径（自己跑闸门 + 解析展示文本）；输出里会提示改用新路径。
#   盖章后复跑闸门的最终哈希写进 --final-json（缺省 <result>.final.json），与盖章前的哈希分开记录，
#   避免"盖章前哈希"冒充"最终成品已核验"。
```

## 3. 修一批（而不是写一批）时的安全做法

1. **先分类再动手**（血证 H1）：闸门报的"不符"有四种，处置完全不同——
   | 分类 | 判据 | 处置 |
   |---|---|---|
   | 源码演进 | 行只在本批快照命中 | 标【历史版本示例】+ 补当前实现块；**禁止重写历史块** |
   | 教材注释格式 | 代码命中，只因行尾写了中文或旧补注 | 改成 `// :Lnn  ←教材：…`，**不是代码错** |
   | 缩写/改写/压行 | 多行压一行、去花括号、省略号、字段名被顺改 | 用注入工具**整块重注入** |
   | 编造 | 快照与当前树都没有 | 按源码重写，并回查同批其它块与节外引用 |
2. **只替换目标节**，写 `tmpnew` → 校验"节外内容逐字节不变" → `os.replace`。**禁止 `open(target,'w')` 写长内容**（历史事故：中断写出全 NUL）。
3. **改代码块只能"插入"，不能"整段替换"**（血证 H14）：用区间替换时，若区间**跨了围栏**（开头是 ```` ```java ````、结尾是 ```` ``` ````），替换体**必须把围栏一并写回**；更稳的做法是改成"在锚点前插入"，完全不碰旧行。
   **别再手写区间替换脚本了——用技能自带的护栏工具**（血证 H17 / 契约 V3）：
   ```bash
   python "<skill>/scripts/safe_edit.py" --file <批次.md> --insert-before "### 6.2 " --block block.txt [--apply]
   python "<skill>/scripts/safe_edit.py" --file <批次.md> --replace 120 180 --block block.txt [--apply]
   python "<skill>/scripts/safe_edit.py" --file <批次.md> --replace-section 3866 4037 --block new_section.md [--apply]
   #   缺省 dry-run；--apply 才写盘并留一份 <批次.md>.bak（只在不存在时写，保住"第一次编辑之前"的原样）
   #   safe_replace_range() 会比对"被替换区间"与"替换体"的围栏事件序列，不一致 → [ABORT]，绝不静默改坏
   #   **整节重写用 --replace-section**：它不要求事件序列一致（整节重写必然引入更多代码块），
   #   改用 S1 区间两端必须在块外 / S2 区间自身自洽 / S3 替换体与拼接后全文自洽且无 A/D/H3（血证 H19）
   ```
   写驱动脚本时：`sys.path.insert(0, "<skill>/scripts")` 后 `from safe_edit import load, save, insert_before, safe_replace_range, safe_replace_section`。
   **怎么选**：改几行 / 换一个块 → `--replace`；**把一整节换成含更多代码块的新版本 → `--replace-section`**。
   两条都不适用（例如只想删掉一个代码块）时**不要手写区间替换**，先回到"插入 + 用 `--replace-section` 重写覆盖"的组合。
4. **改完立即复检围栏配对**（不要等闸门跑完才看）：
   ```bash
   python "<skill>/scripts/safe_edit.py" --check "<批次.md>"     # A 块内带标签围栏 / D 未闭合 / H3 标题被吞
   ```
   （权威判定仍是闸门 ⓪；这条只是"改完立刻知道有没有弄坏"。）
5. 修完按血证 H7 逐节人工过一遍"⑥ 节之外的残留引用"（②⑦⑧⑩⑪⑯）。

## 4. 源码块注入（写新批次与修旧批次的**主力动作**）

```bash
# 首选：按**稳定槽位**寻址（槽位由 new_batch.py --plan 写进 ⑥，见第 4.1 节）
python "<skill>/scripts/batch_build.py" --batch <batch.json> [--dry-run|--check]   # 组装+注入一步到位
python "<skill>/scripts/inject_source.py" <讲解.md> <annotations.json> --src <仓库根> [--dry]

# 旧寻址（兼容既有批次：讲解里没有槽位标记时自动退回并告警）
#   plan.json: {"blocks": [{"anchor": "6.2 Foo（唯一命中该小节下的块）", "lang": "java",
#                           "src": "rag/src/main/java/.../Foo.java", "start": 17, "end": 103,
#                           "anno": {"40": "交给 Spring 管理（会写成 ←教材：…）"}}]}
```
- 代码 100% 来自 `src` 文件，**脚本不接受任何手写代码**；每行都打上 `// :L<真实行号>`。
- 每注入一块都会逐行复核"这一行确实来自源文件第 no 行"，**行号错位直接拒绝写入**。
- 换块走 `safe_edit.safe_replace_range`（比对围栏事件序列）→ 区间跨围栏而替换体没写回围栏时**当场拒绝**（血证 H14）；整节重写走 `safe_edit.safe_replace_section`（S1/S2/S3 三道检查，血证 H19）。
- 写入走 `tmpnew → 三道校验 → os.replace`，并留一份 `.bak`。
- `anno` 里写了不在注入范围内的行号会**告警**（多半是行号写错了）。

### 4.1 稳定源码槽位与可重复构建（方案 §3.3）

```bash
# 骨架 + 分片 + 注释计划 = 可重建的终稿；槽位标记是块身份
python "<skill>/scripts/new_batch.py" --stage 3 --batch 48 --title "…" --classes "…" --sha 16984b9 \
       --out "<本批.md>" --src <仓库根> \
       --plan <注释计划.json> --batch-json <batch.json> [--manifest <本批清单.json>]
# 生成物：骨架（⑥ 每件一行槽位标记 + 待注入围栏）、batch.json（批次状态）、annotations.json（含 slot）
python "<skill>/scripts/batch_build.py" --batch <batch.json>          # 组装 + 注入 + 原子落盘
python "<skill>/scripts/batch_build.py" --batch <batch.json> --check   # 磁盘终稿是否与重建结果一致
```

槽位标记长这样（在 ⑥ 的每件里，紧挨着要被注入的围栏块）：

```markdown
<!-- src-slot id="source:90d042e8:6.8" path="rag/src/.../TableChunker.java" lines="1-183" sha256="90d042e8…" lang="java" -->
```

- **身份 = 槽位 ID + 源路径**：标题、`contains`、块内已替换掉的文本都不参与寻址 →
  "补几条注释再重注入"不用猜旧占位串，重复注入/重复构建**逐字节幂等**。
- 注入前核对标记里的 `path`/`lines`/`sha256` 与计划、与源文件：**不符或源文件已改 → 拒绝写入**
  （不会把旧行号套到改过的源码上）；hash 不符**不会**降级成旧寻址。
- 旧分片（无槽位标记）→ 自动退回 `anchor`/`contains` 并打印 `⚠ 槽位 … 未命中 → 退回 anchor 旧寻址`。
- `batch.json` 字段：`src / skeleton / parts_dir / annotations / manifest / out / slots / batch_id`。
  终稿永远是派生物：**改分片或注释后重跑 `batch_build.py`，不要手改组装品**。
- 只组装、不注入（排查某节分片时）：`python "<skill>/scripts/assemble_batch.py" --base <骨架.md> --part <章节.md> --out <批次.md>`
  ——只允许替换完整的 `##` 章节，片段标题必须与骨架标题逐字一致。

> ① 正向保真 100% 与 ④ 行号零漂移，在正确流程里是**注入出来的**，不是事后修出来的——行号由脚本从源文件取，"手打打错"从源头不发生。

## 5. 调用点提取（补【怎么用】/【怎么接】时用）

```bash
python "<skill>/scripts/callsite.py" <类型名或方法名> --src <源码根>
#   输出三段：声明 / 使用调用点（每处标 :Lnn in xxx() [声明 :Lnn]） / 仅提及
#   --roots rag,framework 只看某些模块；--out 清单.txt 落盘；--json 出结构化结果
```
**调用点一律以工具输出为准，不凭印象**；注册/装配机制回源码读那个装配类的构造器；查不到的写「本仓库尚未实现」，不许编。
源码根是**自动发现**的（`<模块>/src/{main,test}/{java,python}`），Maven/Gradle 多模块项目直接可用。

## 7. 全库记分卡与判据回归（§6.6 铁律 2 的执行工具）

```bash
python "<skill>/scripts/gate_all.py" --root <讲解目录> --src <源码根> --out v28.json
python "<skill>/scripts/gate_all.py" --root <讲解目录> --src <源码根> --baseline v27.json
#   逐字段比对：任何字段变化即退出码 1 —— "不该变的判定必须一字不变"
#   记分卡尾部的"合计 N 个文件仍有问题"是存量信息，不影响退出码
```
改动判据前先存一份基线；改完再跑一次带 `--baseline`，把"判定零附带影响"作为可复核证据写进变更登记。

> **工具自身的依赖也被看管**：`fix_lineno.py` / `gate_all.py` 顶部声明 `GATE_API`（它们用到的 `gate_lecture` 内部符号）。
> 判据改动若删/改了这些名字，工具会**立刻 ABORT 并指出缺哪个符号**，`skill_selfcheck.py` 也会报红 ——
> 这正是"执行规程的工具必须随技能一起被自检"（血证 H17 / 契约 V3）的落地方式。

## 8. 新批次怎么起手（契约 V4）

```bash
python "<skill>/scripts/new_batch.py" --stage 8 --batch 1 \
    --title "对话记忆滑窗（ConversationMemoryService★+JdbcConversationMemoryStore★）" \
    --classes "ConversationMemoryService★, JdbcConversationMemoryStore★" \
    --sha <批头 commit> --src <仓库根> --out "NOTES/教学讲解/阶段8-…/批次1-….md"
```
生成物：**批头**（一句话/核心类/验收结果/源码依据）+ **①~⑯ + 索引，共 17 个 `## ` 节**，其中 `⑦.5`、⑫ 八条与八段提示词标签、⑯ 空表都已就位。**这些结构项是"由构造保证"的**——不是靠写完再回头检查。

## 12. ⑫ 段一次成型：自指 = 0、八段标签 = 8（连续四批返工后的做法）

  |---|---|
  | 本批 / 本次批次的 6 个类 | 这个模块里的那几个类 / 这套契约 |
  | 批次6 的幂等切面 | 项目里已有的 `@IdempotentSubmit` / 既有的幂等切面 |

  | 批次8 的 `MessageWrapper.uuid` | 既有契约 `MessageWrapper` 的 `uuid` |

- **两条机械自检（写完 ⑫ 立刻跑，别等闸门）**：

  # ① 自指必须为 0（在 ⑫~⑬ 区间内数）

## 13. 回填覆盖矩阵的三个陷阱与三项复核（2026-09-16 实战，本批三处返工的原因）

- **症状**：矩阵看起来"回填完成"，但抽查发现：① 某些行的链接标签指向**上一批**（`[批次7]` 却指向批次8 的文件）；② 链接**少了右括号**（`[批次9](path.md` 而不是 `[批次9](path.md)`）；③ 有 5 行**本不该标已讲解**的行被标了。
- **三个陷阱**：
  1. **多行字符串 + `sed` 生成的脚本只替换第一行**：用一个"上一批的 fill 脚本"派生新脚本时，`B8 = ("[批次8](.../"` + `"批次8-...md")"` 这种两行拼接，`sed` 的 `s|批次7|批次8|` 只作用于**第一个匹配**，于是链接标签留在旧批次 → **回填后必须抽查"每批链接的行数"**。
  2. **用短文件名匹配会误伤同名文件**：用 `"/pom.xml\`"` 去定位第 N 行的 pom，会同时命中 `rag/pom.xml`、`agent/pom.xml`、`system/pom.xml`、`infra-ai/pom.xml`、`mcp-server/pom.xml` → 一次误标 5 行。**定位必须用"从仓库根开始的完整路径"**（前缀加模块名）。
  3. **括号/引号在拼接中丢失**：字符串拼接漏一个 `)` 不会报错，只会让 markdown 链接失效（渲染成纯文本）。**回填后必须做括号配对检查**。
- **三项机械复核（每次回填矩阵后立刻跑）**：
  ```bash
  # ① 各批链接行数（应为该批的"件数 + 证据文件数"，可用覆盖矩阵的批次数作交叉验证）
  for n in 6 7 8 9 10; do echo "[批次$n] $(grep -o "\[批次$n\](" NOTES/项目文件覆盖矩阵.md | wc -l) 行"; done
  # ② 链接括号配对（应全为 0）
  python - <<'PY'
  import io
  t = io.open('NOTES/项目文件覆盖矩阵.md', encoding='utf-8').read()
  bad = [l for l in t.split('\n') if l.count('](') and l.count('(') != l.count(')')]
  print('括号不配对行数 =', len(bad))
  PY
  # ③ 已讲解总数增量 == 本批新增行数（多或少都说明误伤/漏填）
  grep -c '| 已讲解 |' NOTES/项目文件覆盖矩阵.md
  ```
- **同族提醒**：矩阵是**唯一权威**的"哪些文件已讲"清单，它错了会污染后续所有切批判断（处方件数、阶段状态、能力账本）。**回填完必须复核，不能只看脚本打印的"已回填 N 行"。**

## 14. 切批时"处方件数"必须现算（2026-09-16 实战）

- **症状**：续传处方写着"下一批 = X 族 6 件（列出 2 个已知文件 + 「其余按目录实测清单取满 6 件」）"，切批时照做，结果**该目录里只剩 2 件未讲**——凑不满稳档下限（6~8 件）。
- **根因**：处方的"件数"多半是**上一批收尾时的推断**（按包族印象估的），而实际件数会因"该包已有文件在前几批讲过"而缩水。**处方不是磁盘事实。**
- **怎么办（两条）**：
  1. **切批前先现算**：`ls <包路径>/*.java | wc -l` + 逐个 `wc -l`，再减去"覆盖矩阵里已标 `已讲解` 的那些文件"——**剩下的才是本批可用的件**（矩阵是唯一权威，别凭记忆）。
  2. **凑不满就合族，而不是降件数**：把主题相邻的族合并（例：`web` 流式 2 件 + `trace` 3 件 + `cache` 1 件 = 6 件，统一主题为"流式长生命周期链路的横切关注点"），并在批头 ①/③ 里写明**合并理由**；同时在状态文件里**记录这次处方偏差**，避免下次再踩。
- **不要做的事**：① 不要为了凑数把"已讲过的文件"再讲一遍（重复计入进度）；② 不要降件数硬做 4 件批（违反稳档约定）；③ 不要把不相关的族硬拼（主题不统一时，宁可去改稳档约定并留痕）。
- **同族提醒**：`⑥ 件` 的"件"指**整文件注入**的文件数，测试类只在整文件注入时计入；仅作证据引用的测试文件**不计入件数**（但可以计入覆盖矩阵的"已讲解"行）。

## 15. ① 报「无法归属源文件」但那是教学合成片段？（判据 2.17 / 2026-09-16 实战）

- **症状**：① 正向保真度打印 `无法归属源文件  <讲解.md>:<行号>  ### 4.1 …`，并伴随 `候选不符 N 行`，而**那段代码明明是你自己写的教学片段**（业务里手写幂等的反面对照、极简替身实现等），不是本仓源码。
- **根因**：① 的**免检判定看的是代码块所属小节的标题**（`is_exempt` 只匹配 `sect`/`h2` 里的免检词：手写 / No-Framework / 等价实现 / 反例 / 对照实现 / 穿透卡 / 卡N / L0-L4 / 示例 / 演示 / 伪代码 / Tiny …）。把片段放在一个**普通小节**（如 `### 4.1 深潜：…`）里，就等于声明"这是源码"，① 会拿它去仓库里逐行找。
- **怎么办（改标题，不改内容）**：给该小节标题补一个免检词即可——最自然的是把它标成它的真实身份：
  - `### 4.1 深潜：AOP 环绕通知与"自调用失效"` → `### 4.1 深潜：AOP 环绕通知与"自调用失效"（含手写示例）`
  - 或 `…（用法示例）` / `…（等价实现）` / `### 反例：…`
  **不要**为了让闸门变绿而删掉片段或把它改成 ```` ```text ````——那会把"读者本该看到的对照代码"藏起来。
- **判据别的地方也有同一族设计**：⑧ 的 L2 块要落在 `#### 卡 N · …` 下、⑨ 靠一级节名 `No-Framework`、⑩ 靠 `反例`、`**【怎么用】/【怎么接】/【扩展步骤】/【上下游】**` 标记之下的块**只要不带 `// :Lnn`** 也算片段。
- **同族教训（与 §12/§13 一致）**：闸门报的"整改要求"有时指向的是**标注缺失**而不是内容缺陷。看到具体到行号的 FAIL，先花一分钟确认"它说的那一段真的是源码吗、它所在小节标题写对了吗"。

## 16. ⑤ 报「缺【怎么接】」但这一件看起来根本没有接口？（判据 2.14 / 血证 H24）

先别急着补那一节——**很可能是判据一个旧缺陷在指使你写不该写的东西**。

- **症状**：报的是**最后一个 6.x 件**（例如 `6.12 ThreadPoolExecutorConfig`），而该件讲的是一个 `@Configuration` 类。
- **机理**：2.14 之前，⑤ 的"件段"用**下一个 6.x 件的标题**当结束位置；最后一个件没有下一个 → 件段一直延伸到**文件末尾**，把 ⑧ 穿透卡 / ⑨ No-Framework / ⑩ 反例全吞了进来。⑨ 节里通常有一段手写等价骨架（`interface Scorer { … }`），于是末件凭空获得"抽象件"身份。
- **怎么判**：在报的那一件里搜 `interface `，如果命中的那一行来自 **⑥ 之后的小节**，就是它。
- **怎么办**：确认判据版本 ≥ 2.14（闸门首行会打印版本）；低于 2.14 就升级脚本，**不要改文档**。升到 2.14 之后仍报，才是真缺口。

## 18. 三处"结构陷阱"：子标题被当成件 / 锚点随标题漂移 / 围栏内 `__占位__`

**背景**：批次11 首跑的三处 FAIL 里有 2 处是这类"格式副作用"，与内容质量无关，但会让闸门红。

**① `#### 6.x.y` 子标题会被闸门当成"件"（⑤ 组 FAIL）**
- 判据：`ITEM_RE = ^(#{3,6})\s*(6\.\d[\d\.]*)\s*(.*)$` —— `### 6.5` 与 `#### 6.5.1` **都命中**。
- 后果：⑥ 的"件数"从 6 变成 14，随后每个 `6.x.y` 都被要求写【怎么用】/【上下游】→ 8 个 FAIL。
- **一次成型的写法**：件用 `### 6.N`；件的**内部小节不要用** `#### 6.N.M` 这种编号标题，改用粗体行 `**6.5.1 状态载体：…**`（既保留编号可读性，又不被当成件）。

**② 注入锚点 = **紧邻块上方**的那个标题（会随子标题增减而漂移）**
- 判据：`inject_source.py` 对每个代码块取"向上第一个 `^#{2,5} ` 标题"作为它的 owner，再用 plan 里的 `anchor` 去匹配这个标题。
- 本批实测的连锁：`6.5` 的 src 块原本位于 `#### 6.5.1` 之下 → anchor 必须是 `6.5.1 状态载体`；一旦把 `#### 6.5.1` 降级为粗体（陷阱 ①），owner 又变回 `### 6.5`，**anchor 必须改回** `6.5 \`ModelHealthStore\``，否则报 `命中 0 个 java 代码块`。
- **对策（两条）**：① 注入块一律紧跟 `### 6.N` 标题之后、任何子标题之前（owner 稳定为 6.N）；② 若必须先写子标题，就在 plan 里用**子标题**做 anchor，并在改标题层级后**重跑注入**。

**③ 围栏内的 `__xxx__` 会被判「占位符残留」（⓪ 组 FAIL）**
- 判据：`PLACEHOLDER = __[^_\n]*[\u4e00-\u9fff][^_\n]*__`，且**只在代码块内**统计；`<<<SRC:`/`CONT-`/`TODO`/`FIXME` 同样命中。
- 高频来源：**从骨架模板抄下来的示意链**（`1 __业务层__ → __类1__.__方法1__()`）、伪代码块里的 `__数据起点__`。批次11 因此被判 40 处。
- **对策**：写 ⑦.1 调用链等示意块时，**直接写真实标识符**（类名.方法名），不要保留骨架占位符；若确实要占位，用 `（业务侧）`/`（类1）` 这类括号文字。

**三条的自检命令（写完立刻跑，成本 < 10 秒）**：
```bash
F=<批次.md>
echo "子标题当件: $(awk '/^## ⑥/{p=1} /^## ⑦/{p=0} p' "$F" | grep -cE '^#{3,6}\s*6\.\d+\.\d')"     # 期望 0
echo "围栏内占位: $(awk 'BEGIN{m=0} /^\s*\x60{3,}/{m=!m;next} m&&/__[^_]*[一-龥][^_]*__/{c++} END{print c+0}' "$F")"  # 期望 0
echo "⑧ 省略段:  $(awk '/^## ⑧/{p=1} /^## ⑨/{p=0} p' "$F" | grep -c '省略')"                                  # 期望 ≥1
```

## 19. 清「骨架占位符」时**不得误伤注入标记**（`__INJECT__` / `<<<SRC:`）——一次真实的自毁事故

- **症状**：`inject_source.py` 报
  `[ABORT] anchor '6.4 \`ProbeStreamBridge\`' + contains '__INJECT__ ProbeStreamBridge' 命中 0 个 java 代码块（应为 1）`
  而正文里该件的小节**明明在**。
- **根因**：为了清掉骨架模板残留的 `__业务侧__` / `__类1__.__方法1__()` 这类占位符，跑了
  ```python
  s = re.sub(r"__([^_\n]+)__", r"\1", s)     # ★ 危险
  ```
  这条正则**同时命中 `// __INJECT__ ProbeStreamBridge`**（`__INJECT__` 满足"两对下划线、中间无下划线"），
  于是注入点被改写成 `// INJECT ProbeStreamBridge` → `contains` 永远匹配不到 → 注入 ABORT，
  而拼装出来的正文里其它件照旧有占位符，**看起来像"注入器坏了"**。
- **三条对策（任选，建议全做）**：
  1. **只清"含中文"的占位符**——骨架占位符总是中文（`__类1__`、`__业务侧__`），而注入标记是纯 ASCII：
     ```python
     s = re.sub(r"__[^_\n]*[\u4e00-\u9fff][^_\n]*__", lambda m: m.group(0)[2:-2], s)
     ```
     （这同时与闸门 ⓪ 的口径一致：闸门的 PLACEHOLDER 也只数"含中文"的。）
  2. 若确实要清全部 `__x__`，必须**排除保留标记**：
     ```python
     s = re.sub(r"__(?!INJECT__)([^_\n]+)__", r"\1", s)      # 负向断言排除 INJECT
     ```
     同理排除 `<<<SRC:`（旧式占位前缀）与任何你自定义的注入标记。
  3. **清理与注入的顺序**：先在**分片文件**上清占位符 → 再拼装 → 再注入；**不要**在已注入的成品上跑清理脚本
     （成品里的 `←教材：` 注释与 `// :Lnn` 行号是资产，误伤代价更高）。
- **注入失败的第一诊断动作**（10 秒定位）：
  ```bash
  echo "剩余注入点：$(grep -c '__INJECT__' <批次.md>)（应为计划块数）"
  grep -n 'INJECT' <批次.md | grep -v '__INJECT__'      # 看有没有被改写成裸 INJECT
  ```
  若出现裸 `INJECT`，就是被清理脚本吃掉了——**改回占位符再重跑注入即可**（不必重新拼装）。
- **同族提醒**：任何"批量做文本替换"的脚本（清占位符、清 `.bak`、统一标点、改编号）在批次流水线上都要先
  **`--dry` 打印将被替换的行数**再落盘；本事故的替换脚本当时只打印了"已替换 N 处"，而 N 里混着注入点，肉眼看不出来。

## 20. 两处易踩的"判定/定位"陷阱：`abstract class` 也算抽象件；正文编辑禁用"字符串首现"

**背景**：批次13 首跑 1 FAIL、且编辑正文时误删过大段（靠分片齐全才恢复）。两条都与"工具的判定口径"有关，与内容质量无关。

**① ⑤ 组：`abstract class` 与 `interface` 一样被认作"抽象件"（必须写【怎么接】）**
- 判据：`IFACE_RE = ^\s*(?:public\s+|abstract\s+|sealed\s+|static\s+)*(?:interface|abstract\s+class)\s+\w+`——**抽象基类同样命中**。
- 症状：件的源码里出现 `public abstract class XxxClient implements Yyy` → 该件被判 `iface=True` → 若只写了【怎么用】/【上下游】，⑤ 组报「缺【怎么接】」。
- **一次成型的写法**：凡件内含 `interface` **或** `abstract class` 声明，就在【上下游】之后补一张【怎么接】表，写清：① 为什么容易忽略（它看起来"不需要接入"）② 实现类与注册方式（子类 `@Service`？工厂 `new`？）③ 依赖 Bean 从哪来 ④ 写新实现的 checklist ⑤ 验证命令（`git grep -c "extends ..."` / `implements ...`）。
- 提醒：`record` **不**命中 `IFACE_RE`（批次11 的 `ModelTarget`、批次13 的 `ParsedEvent` 都没触发），所以"record 件不需要【怎么接】"。

**② 正文编辑：定位必须唯一，禁用 `find("某段文本")` 直接删/插**
- 事故：为了把一段【怎么接】从 ⑦ 末尾挪到 6.6 件末，脚本写 `start = s.find("\n**【怎么接】（抽象件必写）**")` ——**该字符串在 6.1 件里也有一份**，于是"删除"从 6.1 开始一路删到下一个锚点，**一次删掉 6.1~⑦.5 的全部正文**。
- **恢复路径（重要）**：分片文件（`p0_head.md` … `pNN*.md`）是**正文唯一真源**——重跑 `assemble.py`（→ 拼装）+ `inject_source.py`（→ 注入）即可完整恢复；代价只是要重跑 `⑬.1 写入闸门输出` 与 `sync_gate_result.py --apply` 两步（都是脚本，1 分钟）。**所以"分片不删、批中不清"是硬纪律。**
- **三条防身规则**：
  1. **先数再改**：`grep -c "<待替换文本>" <文件>` 必须等于预期次数（1 次）；不等就改用更长的上下文，或直接用**行号**操作。
  2. **插入用结构锚点**：`"\n## ⑦ "` 这类**一级节标题**是唯一锚点；"件内小标题/固定句"几乎都会重复出现。
  3. **改完立刻断言**：`assert 行数变化符合预期`（删 N 行 / 加 M 行），或改完马上 `wc -l` + `git diff --stat` 对一眼——本事故若当时看一眼行数（-600 行）就会当场发现。
- **同族提醒**：这条与 §19（清占位符脚本误伤 `__INJECT__`）是同一类错误的两个面——**凡是"批量或定位式文本操作"，先 dry-run / 先数命中 / 后断言增量**。

**⚠️ 写回填/注入脚本时的高频自伤（批次14 一天踩了 3 次）**：Python 源文件里写成
`"92": "★ 语义是"默认不发"，…"` ——**值里嵌了 ASCII 双引号 → SyntaxError（invalid syntax / perhaps you forgot a comma）**，
而且报错行常常指向"下一行"或看起来无辜的地方，排查很费时。
- **对策**：值内的引号一律用 **`「」` 或全角引号**（中文教材里本来也更自然）；
- **已中招时的批量修法**（把每行值内的成对 `"` 改成 `「…」`）：
  ```python
  for i, l in enumerate(lines):
      m = re.match(r'^(\s+)"(.*)"(,|\),)$', l)          # 同时覆盖 "key": "value", 与纯 value 行
      if m and '"' in m.group(2):
          out, open_ = [], True
          for ch in m.group(2):
              if ch == '"':
                  out.append('「' if open_ else '」'); open_ = not open_
              else:
                  out.append(ch)
          lines[i] = m.group(1) + '"' + ''.join(out) + '"' + m.group(3)
  ```
- **顺带**：`mkplan` 的 `anno`、`fill_matrix` 的 `ROWS` 都是"大段中文 + 标点"的高发区，**写之前先把引号规范定下来**（建议：外层 Python 用 ASCII，值内一律 `「」`）。

## 21. 凡「零 X / 全 X」类结论，必须当场跑命令并贴输出（2026-09-17 两次真实事故）

**背景**：同一份教材在**同一天**连犯两次「未核实即断言」——① 批次15/17 连续写「本批 7 件在 `*Test.java` 中零命中」，实际有 `ChatTierConfigValidatorTest`（4 例）与 `BaiLianRerankClientTest`（5 例）；② 收官批又写「矩阵未开始 = 0」「`rag/src/test` 47 个测试文件」，实际是 **3** 与 **44**。**两次都不是笔误，而是「把未执行的命令写成结论」。**

**为什么这类错最贵**：
- 它**不会报错**（没有任何工具会拦住你）；
- 它**污染事实层**——教材的价值建立在事实之上，一个错的「零」会让读者形成错误印象（以为"精排那三处血证设计没有测试守护"，实际有 5 例）；
- 它**制造重复劳动**——基于错误结论开出的「补测清单」里，前 4 组其实已有测试；
- 它**向下传播**——后来者会引用它继续建论。

**硬规则（写进流程，不靠自觉）**：
1. **结论句旁边必须有可复现的命令 + 期望输出**。例如不写「测试覆盖为 0」，而写：
   ```
   git grep -l "ChatTierConfigValidator" -- '*Test.java'
   → rag/src/test/.../infra/model/ChatTierConfigValidatorTest.java（95 行 / 4 例）
   ```
2. **搜索必须覆盖所有可能的物理位置**。本仓的测试分布在**三处**：`infra-ai/src/test`（本模块）、`rag/src/test/.../infra/...`（**跨模块**，包路径仍是 `infra`）、`rag/src/test` 的邻域域（如 rag 域里测 infra 产物的 `EvidenceGatePostProcessorTest`）。**只搜一处必然漏。**
3. **数字类结论禁止脑算**：`=` 后面那个数必须来自命令输出；**不要把「两处相加」的结果当成「某一处」的数**（本轮 47 vs 44 就是这么错的）。
4. **修正时保留「原结论 → 实际」对照**，不要静默改掉——**错误本身是最好的教学材料**（本轮把两次事故都写进了教材 §11.4 / §11.4b）。
5. **收尾前跑一遍「交付物里所有数字的可复算命令」**：这是收官批的标准动作（本轮正是这一步抓出了第二次错误）。

**同族提醒**：这条与 §19（清占位符误伤注入标记）、§20（正文编辑用字符串首现定位）是同一族——**凡「我说了某件事」的地方，都要问一句「我的证据是什么、别人能不能复算」**。
