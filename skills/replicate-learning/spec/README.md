| 文件 | 是什么 | 谁读 |

## 怎么改（顺序不能反）

1. **改 `00-质量契约.json`**：加/改条目（`stmt` 写判据原文，`doc` 写"必须能在 SKILL.md 里找到的原文锚点"）。
2. **同步三处投影**：`references/第一册质量细则.md` 正文、`references/批次讲解全文模板.md` 骨架、`scripts/gate_lecture.py` 判定。
3. **跑 `python scripts/skill_selfcheck.py`**：它会对账 SSOT↔质量细则↔模板↔gate，并把缺失条目直接报出来。
4. **判据有变**则按 `references/第一册质量细则.md` §6.6 三件套：递增 `GATE_VERSION` → 登记 → 回归集判定不变 → 公告与存量工单。
5. **同步仓库与实际安装副本并 commit**（见质量细则 §6.6 的 DoD）。

## 层级说明（为什么分 L1/L2/L3）

- **L1 机械门**：闸门能精确判定的项（结构/保真/行号/密度/签名/覆盖）。**所有批次都必须过**，不过就修。
- **L2 内容契约**：闸门能查"有没有"，但内容对不对要人读（用法与接入、快照、证据等级、骨架清单）。核心件必写；零件件按 `references/零件类讲解模板.md` 精简，**但不许省掉【怎么用】/【上下游】**。
- **L3 教学增益**：讲解质量本身（【讲解】的推理、⑨ 手写版够不够真、⑫ 八条的实质）。**不假装机械可验**——由 `⑯ 质量自检` 逐段核对 + 抽样人审，未审就标"未审"。

> **注意**：本项目**不做分级降档**（AGENTS.md 明文：所有类都满深度）。L1/L2/L3 分的是"谁来负责判定"，**不是"哪些件可以少讲"**。控成本请调**批次粒度**（零件件合并成批、核心件一批 2~3 件），不要降单件深度。
