# 安装与执行边界

## 1. Skill 的正确形态

本项目采用标准 Agent Skill 形态：

```text
replicate-learning/
  SKILL.md
  references/
  scripts/
  examples/
  spec/
  docs/
  tests/fixtures/       回归夹具（batch48 真实批次 + py_mini 合成边界用例）
```

模型识别 `SKILL.md` 后，以其中的 `description` 判断是否触发，再按 V2 意图路由读取协议、模板和脚本。`SKILL.md` 是入口，不要求把所有规则拼成一条超长提示词。

## 2. 能保证什么

当前版本可以通过自动化检查保证：

- Skill 有合法入口和明确触发范围；
- 默认第一册、显式扩展册、独立工程日志和八步工程流程有落点；
- 引用的模板、协议、规范和脚本存在；
- 旧版源码保真规则没有被破坏；
- 关键工具和质量契约能够自检（`skill_selfcheck` 113 项；单测 143 项；项数随版本增长，以脚本实际输出为准）；
- 批次的分步耗时**可以**被采集（脚本侧），但**模型写作耗时**只能由操作者按秒表记录——没记就写"未实测"；
- Windows 下自检不会因子进程代码页产生误导性线程异常（工具入口统一把 stdout/stderr 切到 UTF-8，
  重定向到文件或管道时不再 `UnicodeEncodeError`）。

## 3. 不能保证什么

Skill 不能保证任意模型对任意项目都一次性得到正确教材。模型仍可能：

- 漏读代码或误判业务；
- 无法安装依赖或启动项目；
- 把推断写成事实；
- 生成不完整的实验或实现；
- 需要用户审查和反馈后才能完成任务。

因此“正常执行”的定义不是 AI 自动宣布完成，而是：产物落盘、证据可回链、验证结果如实记录、缺口可续传，并由用户做最终 Accept。

## 4. 使用前检查

在 Skill 根目录运行：

```powershell
python scripts/skill_selfcheck.py
python scripts/v2_selfcheck.py
```

两个命令都 PASS 后，才进入目标项目试运行。首次使用至少提供：

1. 被学习项目路径；
2. 可写的教材目录或允许写入目标项目 `NOTES/`；
3. 独立工程日志根目录，未指定时使用目标项目同级 `.replicate-learning-log/<项目名>/`。

## 5. 试运行的真实边界

本 Skill 的仓库是 `D:\develop\workspace\replicate-learningV2`（V2 主线，判据 2.31），主要是本 Skill 的方法、模板和脚本仓库，不等同于一个业务样例项目。用它可以验证 Skill 包自身的发现、路由和自检；教材质量还需用真实业务项目的批次闸门与人工语义审读验证。

旧线 `D:\develop\workspace\replicate-learning` 的本 Skill 副本停在判据 2.14，已不再接收更新，也不作为安装源；对外安装与同步一律以 V2 仓库为准。

首次真实试运行应至少完成：

```text
四份基础地图
  + 第一册一个源码批次
  + 源码及测试证据
  + 批次闸门与人工语义审读
  + 明确请求后分别验收实验、架构挑战和 Issue 闭环
```
