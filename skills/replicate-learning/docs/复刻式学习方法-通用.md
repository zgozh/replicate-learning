# 复刻式学习方法 · 通用方法论

> 适用：任何「想通过参考一个成熟开源项目，把它的业务-架构-代码-底层机制-工程判断吃透」的学习场景。
> 时代前提：**vibecoding**——读者不用手写代码，代码由 AI 产出；读者要练的是**看懂、讲清、判断、指挥**。因此本方法**不设任何"读者动手"环节**（不手写、不交作业、不复述卡关），把"练"全部**以读代练**转译进讲解文本。
> 核心载体：**落盘的教学讲解**（聊天会被压缩折叠，磁盘上的完整讲解才是教材）。
> 模板：空白模板在 `../references/`（系统全景地图 / 概念词典 / 类清单表 / 业务闭环定位图 / 零件类讲解 / 批次讲解全文 / AGENTS.md-模板 / AGENTS.md-复刻增量 / 通用工程约定）；`../SKILL.md` 是入口（任务定义 / 七阶段工作流 A~G / 批次教材结构 / 交互约定 / 质量禁区）；`../examples/黄金样例.md` 是"每类讲多深算达标"的锚点。

## 怎么用（先问在哪复刻 + 开局四件套 + 整体到部分）

-1. **先问在哪复刻（务必）**：官方项目（答案卷）与复刻目录放**同一级**（diff 方便、官方只读互不干扰）。确认后复刻目录 = 本项目根（`AGENTS.md` 放这）。
0. **初始化「开局四件套」**（一次性生成，之后学习 = AI 产出讲解、读者阅读）：
   ① `AGENTS.md`：复制模板填命名/进度/资料指针；
   ② `NOTES/00-系统全景地图.md`：**整体认知第一课**（五件产物，见 §4），边学边回填；
   ③ `NOTES/概念词典.md`：全局白话词典（§5），每批新词回填；
   ④ `docs/阶段0-开工清单.md`：跑通参照环境的命令序列 + 抓"打穿全栈"的请求链路。
1. **分阶段 → 分批 → 逐件**：先全景（整体），再模块（部分）；阶段里件多按「相关类聚合」分批，多轮次推进。
2. **每次做完更新 AGENTS.md「当前进度 + 下一步」**：续传靠它，不靠会话记忆。

> AGENTS.md =「这个项目的当前状态页」；系统全景地图 =「这个系统长什么样」；概念词典 =「这些词什么意思」；本文档 =「讲解怎么做」。**换项目 = 复制模板重填；换会话 = 读 AGENTS.md + 全景图续传。**

## 核心原则

1. **答案卷是「参考」，不是「教材」**：官方项目 clone 到只读目录当答案卷，始终放旁边供对照与 diff，不必先把它全学完再动手。
2. **AI 复刻 + 讲解 = 你的教材**：配置/DTO/常量/目录等工程惯例直接复刻（省时间），机制/算法也复刻并**讲透原理**（那才是学到的东西）。**写码、构建、diff、跑实验都由 AI 执行；读者只读讲解、对照源码、提问。**
3. **整体 → 部分**：先系统全景，再阶段/批次/单件。没有全局的局部讲解 = 盲人摸象。
4. **做中学的等价物 = 具象化的讲解**：既然读者不动手，"做中学"由 AI 的**真实产物**补足——真跑通、真抓链路、真 diff、真做 L4 故障实验、真查源码与 git 历史，把"做"的证据全部写进讲解。凡"关系/流转"类内容（数据流/状态机/调用链/依赖）**用 ASCII 图/流程图画一张**，别只文字。

## 从整体到部分：系统全景地图（第一课，强制）

**目的**：让读者先看见整头大象，再学每块拼图。产出 `NOTES/00-系统全景地图.md`，含**五件**（模板见 `../references/系统全景地图模板.md`）：

| # | 产物 | 内容与要求 |
|---|---|---|
| 1 | **运行时部署图** | 进程、端口、中间件、外部依赖（物理视角）。每个框一句"它挂了会怎样"。给读者的意义：代码跑在哪、依赖谁 |
| 2 | **一条请求打穿全栈（Trace 实操）** | **真跑一遍抓完整链路**（起服务 → 发一个请求 → 从入口日志/断点/链路逐层走到 DB/外部系统 → 原路返回），贴真实日志/调用栈。**不是画出来的想象链**。给读者的意义：第一次"看见"一次完整业务流转 |
| 3 | **数据模型全景** | ER 图 + **表↔模块读写矩阵**（哪张表被谁读、被谁写）+ 每张表"为什么这么设计"（主键策略/索引/冗余字段动机）。数据比代码稳定，先看数据再看代码 |
| 4 | **模块依赖方向图** | 模块切分 + 依赖方向 + 每模块一句话职责 + **"删掉它，哪个业务问题会回来"** |
| 5 | **业务约束 → 架构决策推导链** | 把非功能需求（QPS / 数据量 / 一致性 / 延迟 / 成本）逐条推导到选型：为什么 MySQL 不 PG？为什么 Redis？为什么 MQ？**每条给备选 + 不选的理由 + 代价**。不会推导 = 只会照抄选型 |

**使用方式**：每类讲解的②架构位置都要**挂回全景图**（"这个类在地图第 2 块的 xxx 处"）；学的过程发现问题就回填修正（地图不是一次成型，是边学边长的活文档）。

## 概念词典（讲解去重与复习的关键）

- 位置：`NOTES/概念词典.md`。**讲过一次的概念不再展开**，后续只写「见概念词典 §X」。
- 词条格式：`概念 | 大白话 + 生活化类比 | 首次出处（批次文件）| 备注`。类比是记忆钩子（token=游乐园手环、Redis=键值仓库、HTTP 请求=信封+信纸、AOP=门帘）。
- 扫描范围：不只业务/框架词，**底层平台与协议词同样收录**（HTTP 方法、CORS 预检、Servlet 容器/过滤器链、DispatcherType、线程池、序列化、ThreadLocal、AOP…）。
- 判定法：凡"解释它时不得不再用一个没讲过的词"的，两个都进词典。
- 收益：讲解篇幅下降（同一词不重复讲）+ 词典本身就是复习神器（三个月后翻一遍想回大半）。

## 讲解标准总则（读者视角 + 术语到底 + 满深度）

1. **读者尺度**：默认读者 = 懂一门语言 + 基础语法。概念第一次出现必须大白话 + 例子解释，不许默认"这我该会"，不许甩名词。
2. **解释必须「到底」（术语不自举）**：解释里每个词要么是生活语言/语言基础，要么前文已解释过。拿「预检请求」解释 OPTIONS、拿「异步派发」解释 ASYNC 都是悬空（"预检""派发"本身也是生词）。判定法：读给"只会语言语法的人"，有一个词不认识且没铺垫 = 继续拆到底。
3. **溯源**：讲解与归档允许写"参考思路/出处"（学习需要可追溯）。
4. **权限**：读者觉得"某个概念被默认我会了"，随时打断要求解释；AI 察觉自己没铺垫概念，必须停下来先补。
5. **满深度、不分档**：机制、DTO、配置、常量、建表 SQL 一律讲满（为什么存在 / 数据从哪来 / 被谁用 / 为什么这样设计），差别只在份量。零件类用**紧凑讲解模板**（`../references/零件类讲解模板.md`），深度不减、篇幅更省。
6. **讲解合格线（阅读者版）**：任何一个件讲完，读者若仍"不知道它在哪、干嘛、会怎么坏、AI 这么写对不对"，该件讲解视为没讲完，回炉。六段讲的是"可判断"，不是"可默写"。

**认知主线（业务 → 架构 → 代码）**：熟练 vibecoding 的前提 = 先有业务能力 → 再架构设计能力 → 最后看懂并掌控代码。三层是讲解的认知骨架，顺序不许打乱：业务（服务闭环哪个动作）→ 架构（站哪层/为什么）→ 代码（每行干嘛、每个 API 内部怎么做到、为什么这么设计、会怎么坏）。**项目维度同理**：全景 → 阶段 → 批次 → 单件。

## 每件讲解结构：六段 + 工程视角（以读代练）

> 详细深度基准对照 `../examples/黄金样例.md`。每件独立成节（`### 类 X/N：类名`，分母 = 本批实际件数，随批动态，禁止沿用上批分母）。六段各占独立小节，禁止压成一行式密集文本。下面每段逐条带"读者视角"要求：

1. **① 业务场景**：**具象镜头**——有名字/身份的人 + 具体数值 + 期望结果（"运营小李把 200MB 知识库传上去，希望 5 分钟内能被检索到"），不许抽象主体（"用户上传文档"没有名字无数值 = 不合格）。业务名词先白话点一句。
2. **② 架构位置**：先白话每个架构术语（模块/依赖方向/横切关注点/契约/切面…），再讲放哪层、上下游、依赖方向、为什么在这 + **挂回系统全景地图**。
3. **③ 实现四问 = 开发四问**（完整教学句，禁电报体"手法：A+B"）：**思路**（解决什么 + 分几步 + 为什么这么拆）/ **设计决策**（为什么这么设计？备选？为什么选这个不选别的？代价？——给方案对比，不只陈述现状）/ **手法**（每个手法 = 是什么 → L0/L1 内部怎么做到 → L2 手写示范 → L3 不用会怎样；穿透融进手法问）/ **数据流与边界**（数据怎么流转 + 异常/并发/降级/边界在哪怎么兜底，每个分支补一句"为什么这条分支存在"）。
4. **④ 代码逐行**：≥1 段**整方法**真实代码（标"节选" = 片段 = 不达标；类短就整文件贴出），注释**长在代码内**——每个关键行/每个陌生 API/库调用/平台机制都要行内三问（这是什么→落到机制层 / 为什么这行要它 / 不这样会怎样）。讲解贴的代码 = 写进源码文件的那份（AI 复刻时就带逐行中文注释，讲解直接照它讲，不重复劳动）。
5. **⑤ 调用链实例 ≥8 跳**：从业务入口到落点一跳一跳，带真实类名/方法名 + 每跳一句大白话"它干嘛"，结尾给读法提示（"断在第 N~M 跳 = 还没懂的点"）。
6. **⑥ 用法 + 触发回放**：可照跑的请求/输入 → 逐段流转 → 返回长什么样。**末尾给 No-Framework 手写示范**（★ 类必给整段等价手写、其余至少"手写要做哪几步"）——**作为理解机制的阅读材料，明确标注"读者阅读即可，不必自己写"**。
7. **⑦ 工程视角（按值得配给，不是每件都全）**——把"练才学得会"的东西以读代练写进来：

| 小节 | 讲什么 | 给哪些件 |
|---|---|---|
| **直觉对照** | 新手/照抄者本能会怎么写、会漏什么、为什么翻车 → 答案卷为什么这么设计 | 设计决策有反直觉点的机制件 |
| **故障情景** | 具体故障 → 现象 → 排查路径（从哪行日志看起 → 怎么缩小 → 定位到哪个类哪行），配 L4 真跑证据 | ★ 件、有防御逻辑的件 |
| **测试视角** | 这类的哪几条分支值得测、造什么输入、断言什么、典型坑（如 mock 时 `excludePathPatterns(String...)` 与 `List<String>` 重载歧义） | 分支多、有可测逻辑的件 |
| **演进视角** | AI 跑 `git log -p / git blame`，讲这个类被哪些 bug/需求改过、为什么长成现在这样 | 答案卷 git 历史有料的件 |
| **横向对照** | 同一机制别的成熟项目怎么做、差异与原因 | 每阶段选 1~2 个核心机制件 |

**六段 + 工程视角的配给原则**：六段每件必走；工程视角按"值得讲"选 1~2 个（机制件多给，零件件通常只给直觉对照或测试视角的其中一段，甚至不给）。**禁止"全部件都塞满全部小节"**（那是堆料不是讲解）。

**零件类（DTO/枚举/配置/常量/建表 SQL）**：用 `../references/零件类讲解模板.md` 的紧凑结构（为什么存在 / 每个字段语义 / 数据从哪来 / 被谁读走 / 为什么这么设计（方案对比）/ 会咬人的地方 / L1 机制 / 手写示范），**每处仍要有具体的人与故障镜头**，不许滑成字典。

**讲到外部中间件时（红线）**：涉及 Redis/MQ/MySQL/MinIO/LLM 等外部调用时，在③边界与⑥用法里除"数据进出"外再讲四件事——①它是什么（白话一句角色）②怎么接（客户端/连接/初始化/配置在哪）③惯用 API（关键方法 + 正确写法 + 真实代码）④失败怎么办（超时/重试/降级/兜底——中间件挂了主链路还有没有保底）。**这是学会成熟项目最值钱的部分。**

## 底层穿透 L0~L4（防 API 调用工程师）

项目代码大多是层层包装的框架/工具/SDK 调用。只讲"调 X 的 Y 方法做 Z" = 记 API 清单 = 换框架归零。所以**凡外部调用一律往下剥**，穿透全部由 AI 查证后写进讲解：

| 层 | 回答什么 | 达标（含硬要求） |
|---|---|---|
| **L0 源码实证**（所有机制性调用） | 内部靠什么做到？证据？ | 贴**真实源码片段 + 文件 + 行号**（IDE 跳转/反编译 jar/GitHub）。禁止凭记忆；悬空动词回炉 |
| **L1 机制层**（所有外部调用） | 替你干了哪几件事，每件怎么做到的？ | 拆到"换我自己写是哪些步骤"，指真实类名/方法名。例：@TableLogic → TableInfoHelper 解析进 TableFieldInfo.logicDelete → DefaultSqlInjector 按有无逻辑删除字段选 SqlMethod.LOGIC_DELETE_BY_ID 而非 DELETE_BY_ID → select 自动 append AND deleted=0 |
| **L2 手写示范**（★ 类与核心依赖） | 不用它，等价实现长什么样？ | 20~40 行等价手写**作为讲解示范（阅读即可）**，要**够真**：逐条写出框架扛的边界（清理/失败改写/模板求值/松散绑定递归/转义/池化…至少 3~4 条）并点明去哪了。玩具骨架（try/catch+save）不合格 |
| **L3 取舍层**（★ 类） | 为什么这么设计？不用会出什么具体故障？ | "人-时-错"三元组推演："业务 01.250 提问 → 配置全 null → 选不出模型 → NPE，且启动时校验不触发、运行时才炸"。形容词（难维护/易出错）回炉 |
| **L4 故障实证**（★ 中间件，做得到就做） | 真破坏看到什么？ | AI 替读者真跑：删 `clear()` / 停 Redis / 事务放错层 → 贴**真实报错/日志/数据行**。做不动退 L3 并注明"推演未实测" |

**示例密度**：每批至少 1 处完整穿透（L0~L3，给最"包装"的依赖）；其余外部调用至少 L0+L1；★ 类打满 L1~L3、尽量 L4。**穿透点清单**：写码前先列本批每个外部调用点，逐条判「归哪类、穿到哪层、销号」；前面批次已穿透的显式引用「机制见批次N / 黄金样例 §X / 概念词典 §X」，不重复拆。

**防糊弄自检**：L0/L1 写完后问"我还在用『扫描/改写/环绕/私有/解析』这类悬空动词吗？落到哪个类、哪个方法、哪个字段？"答不上 = 没拆到底，回炉。

## 复刻代码的阅读顺序（读者怎么读源码）

讲解是主教材，源码是配套材料（AI 复刻时已带三问逐行注释）。读者想加深时可照此读：

1. **先排雷**：把每个件归两类——**样板**（注解/DTO/常量/枚举/工具：结构简单，给契约或数据）/ **机制**（切面/算法/状态机/路由：真正的核心逻辑）。读的顺序：先样板热身、后机制攻坚。
2. **读入口**：看业务方怎么调用它、有什么旋钮（方法签名、参数含义、能力边界）。
3. **读支撑件**（枚举/工具/常量）：通常很短，被机制依赖，搞清"状态值怎么来"。
4. **读机制件**（最重要，花最多时间）：两把尺子——**调用链**（谁拦谁、谁调谁、在哪阶段织入）+ **数据流**（数据从哪生成 → 怎么进外部系统 → 怎么被判别/流转）。
5. **对比升华**：模块里两件相似但不同的事（防重复提交 vs 防重复消费），对比**为什么机制不同**——这才是学会。

**卡住怎么办**：①对答案卷 diff 看差异遗漏；②追一条完整数据流，中间断开处就是没懂的地方；③用自己的话向 AI 复述，讲不清处 = 让 AI 再讲。

## 推进流程（标准循环 + 落盘 + 续传）

**阶段级**：读全景/拆解 → 跑通参照 → 每批：AI 复刻（三问注释）→ Gate（穿透清单/讲解骨架）→ 逐件六段讲解（含工程视角）→ diff → 构建验证（贴证据）→ **讲解全文落盘** + 核对问答 → 回填词典/全景图 → 更新状态 → commit → 续传。

**每批 = 一个可运行的最小实现增量 + 一份完整讲解**。一批一个 commit（最小实现原则，不攒阶段收尾；`NOTES/` 等学习件是否入 git 按项目约定）。

**红线**：
- 写码先于讲解、讲解落到真实码上（AI 复刻的码带注释，讲解照码讲）；全批写完不逐件讲 = 没讲完。
- 每批完成即构建验证并贴真实证据（铁律见 `../references/通用工程约定.md` §1），未跑不得宣称完成。
- 讲解粒度 = 每件独立成节、每件讲满；**不设"读者先写/先复述才放行"的门禁**——读者唯一义务是读与提问。

## 讲解落盘与归档（教材 = 教学讲解目录）

**触发时机**：一批讲完立即落盘（不等阶段结束）。**为什么**：聊天窗口随会话变长被**压缩折叠**，讲过的内容回头翻不到（真实事故：某阶段批次2 的整份讲解在聊天里消失，只能整批重讲）。**磁盘上的完整讲解才是教材。**

**目录结构**（"阶段 → 批次"两级，命名带"跟什么有关"）：

```
NOTES/教学讲解/
  └─ 阶段4-system支撑域（Sa-Token认证+审计变更日志）/        ← 阶段目录名带本阶段关键技术 2~3 个
       ├─ 00-阶段总览.md                                    ← 索引：定位 + 批次清单链接 + 进度
       ├─ 批次1-SaToken认证三件套（三件套+UserDO+UserRole）.md
       ├─ 批次2-Auth登录登出（AuthServiceImpl★+LoginVO）.md   ← 批次文件名带本批核心类，★标重点
       └─ 批次3-审计写侧（BizChangeLogContext★+RecordService）.md
```

- **命名规则**：阶段目录 `阶段N-<主题>（<关键技术 2~3 个>）`；批次文件 `批次M-<一句话主题>（<核心类，★标重点>）`。总长 ≤40 字；禁 `\ / : * ? " < > |`（多类名用 `+` 连接）。
- **批次文件 = 教材全文**，块齐全（模板 `../references/批次讲解全文模板.md`）：本批地图 / 先修概念 / 业务闭环定位 / 类清单表 / 逐件详解全文（六段 + 工程视角）/ 核对问答（带标准答案）/ 构建证据 / 溯源与 diff 结论。
- **核对问答（无提交无卡关）**：一问一答带答案（业务/架构/代码三层各至少 1 题，题数随本批知识点与难点数浮动）。读者看完答案自己对，答不上回去重读对应段或问 AI。**不要求交任何东西、不卡进度。**
- **三件套分工**：讲解全文 = `NOTES/教学讲解/`；状态与索引 = 完整性地图勾选 + `NOTES/阶段N-主题.md`（机制摘要/构建证据/下一步，全文一律链接到教学讲解，不重复存）+ AGENTS.md「当前进度+下一步」；**概念词 = `NOTES/概念词典.md`**。
- 面试题（可选）：追加到 `NOTES/面试题.md`（跨阶段累积）。

> 原则：不等读者催，**一批讲完立即落盘**。教学讲解（概念+讲解层全文）+ 阶段档案（决策/坑）+ 复刻代码（模式）三者 = 概念/决策/模式/坑/代码五层齐备，可跨会话、跨项目回看。

## 会话分配策略（跨项目通用）

**按「上下文相对独立的工作单元」切会话，不是死板"一阶段一会话"。** 新会话触发：①切换大业务域；②当前会话 token 过高/上下文混乱（长会话+大量日志是正常信号）；③一个工作单元（一个阶段/模块/自洽功能）完成。**模型应主动提醒**归档 + 开新会话。

**会话衔接依赖持久化状态，绝不依赖会话内记忆**：进度+下一步 → AGENTS.md；讲解教材 → `NOTES/教学讲解/`（磁盘）；概念 → 概念词典；全景 → 系统全景地图；代码成果 → git commit（每批一次）；参考实现 → 官方答案卷（只读）。新会话读 AGENTS.md + 全景图 + 词典即可无缝续传。

## 全量复刻完整性方法（零遗漏）

目标 = 把参考项目**整个**复刻 + 讲透，杜绝漏模块/漏文件：

1. **全量盘点**：枚举答案卷每个文件，按类型归类——后端代码 → 后端阶段；前端代码 → 独立前端 track；基础设施（SQL/yaml/docker/脚本）→ 建库/装配阶段；文档/素材 → 收尾对照阶段。
2. **按技术栈分 track**：后端优先、前端殿后（依赖接口好用再联调），别混同一阶段。
3. **建权威清单**：每个文件写进 `NOTES/阶段对照-完整性地图.md`，带 `[x]/[ ]` + ★（重点/难点提示，非深度开关——所有件同满深度）。零遗漏唯一依据 + 续传入口。
4. **阶段边界对照**：每进新阶段先对照答案卷该模块包清单确认无漏；每完成一件勾 `[x]`。
5. **样板/机制分治**：样板直接复刻；机制复刻并讲透原理。
6. **最终 diff 兜底**：收尾阶段全量 diff，清单所有 `[ ]` 清零才算 100%。

## 选择性复刻（跨栈 / 降配 / 时间受限场景）

全量复刻不是默认答案。出现以下任一情况改走选择性复刻：参照项目技术栈 ≠ 目标栈；有近期交付目标只能碎片时间；大部分能力已有等价积累。

**做法**：挑 3~5 个核心机制 mini-replicate + 讲透，其余内容降级为"读拆解文档/讲解的对应章节"。机制入选须同时满足：①面试高频、能讲出权衡；②近期真的要用（学完长在交付物上，一鱼两吃）；③机制自洽（一个工作单元内能完成"复刻→讲透→验证"闭环）。

## 常见翻车（讲解中心版）

- 只讲 API 不穿透 → API 调用工程师。判定：把 API 名全换成别的框架同款，讲解还成立 = 只讲了调用姿势。
- 穿透停在悬空动词（"扫描/改写/环绕/线程私有"）→ 拆到真实类名/方法/字段，配 L0 源码证据。
- 「不用会怎样」写成形容词 → 改"人-时-错"三元组，形容词回炉。
- 零件件讲成字典 → 要有具体的人 + 方案对比 + 反例镜头。
- 概念重复展开不引词典 → 先修只讲新词，已收录「见概念词典 §X」。
- 整体缺席、一上来钻类 → 先全景地图，每件挂回定位。
- 讲解写成"你回去自己练" → 以读代练：直觉对照/故障情景/测试视角/演进视角写进文本。
- 完整讲解只留聊天不落盘 → 每批讲完立即整篇写入教学讲解目录。
- 命名不带"跟什么有关" → 三个月后是盲盒。
- 上一批数字当常量照抄 → 分母/题数随本批动态。
- 代码贴"节选" → 整方法/整段。
- 先修只有"术语→定义"无类比 → 类比是钩子（token=手环/Redis=仓库/AOP=门帘）。
- 构建验证"攒到最后一次性做" → 每批即验证，贴真实证据。

## 新项目快速开始模板（开局四件套 + 复刻增量）

> 基础 AGENTS.md 一页模板见 `../references/AGENTS.md-模板.md`；通用工程约定见 `../references/通用工程约定.md`。下面是**复刻场景增量**，拼接到基础模板之后：

````markdown
### 增量A · 运行资源与答案卷错开（强约束）
数据库名 / bucket 名 / 端口号全部用自己的一套（如 `<project>` / `<project>-sources` / 错开端口），compose 与 yaml 每一处同步——同机对照运行互不干扰、不与答案卷撞名。

### 增量B · 学习资料指针（喂 AI 的上下文，强制）
| 资料 | 路径 | 用法 |
|---|---|---|
| 答案卷（只读） | `<答案卷根目录>` | 对照源码 / 写完 diff |
| 系统全景地图 | `NOTES/00-系统全景地图.md` | 每件讲解②挂回定位；边学边回填 |
| 概念词典 | `NOTES/概念词典.md` | 先修只讲新词，已收录引用 |

> 给 AI 的标准指令模板：「读 AGENTS.md + 系统全景地图，继续阶段 N / 讲批次 M」。

### 增量C · 学习进度表 + 会话规划
- 进度表：阶段 0~N 状态（⬜ 未开始 / 🔶 进行中+已完成+commit hash / ✅ 验收通过）。放 AGENTS.md 或 NOTES，二选一定死。
- 新会话触发 = 切换大业务域 / token 过高 / 一个工作单元完成。

````

**阅读者学习法速查（供每次学习遵循）**：AI 复刻（码带三问注释）→ 逐件六段讲解（含工程视角以读代练）→ diff → 构建验证（贴证据）→ 讲解全文落盘 + 核对问答 → 回填词典/全景图 → commit。读者只读 + 提问，**无任何动手提交环节**。
