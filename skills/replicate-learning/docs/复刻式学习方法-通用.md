## 拿到这份文档怎么用（先问在哪复刻 + 开局三件套 + 两步）

-1. **先问在哪复刻（务必）**：开课前先确认复刻目录，且**官方项目与复刻目录放同一级**：
   - 本地已有项目 → 在**该项目父目录**下建复刻目录（`<项目>-replica`，与官方同级）；
   - 给的是 GitHub/远程地址 → 先定一个"项目根"，官方 clone 进去、复刻目录也在**同级**（如官方 `<项目>-book` 只读 + 复刻 `<项目>-replica`）；
   - 好处：`diff` 对照方便、官方只读互不干扰、路径短好找。确认后**复刻目录 = 本项目根**（`AGENTS.md` 放这里）。
0. **初始化「开局三件套」**（一次性生成，之后学习=纯执行）：
   - ①`AGENTS.md`：复制文末骨架模板，填命名/进度/资料指针；
   - ②`NOTES/阶段对照-完整性地图.md`：把答案卷交付面拆成阶段勾选清单，★ 标注「重点/难点」（含真实算法/状态流转/路由/编排/并发/兜底逻辑、较难讲透的类）；★★ 只是「这类的机制逻辑较难、要多花时间讲透」的路标，**不关联讲解深度——所有类都同样满深度讲**；
   - ③`docs/阶段0-开工清单.md`：跑通参照环境的命令序列（阶段0 的定义是**跑通参照**，不是写代码）。
1. **按「会话分配策略」拆工作单元**：不要一阶段一会话，按上下文独立切会话。
2. **每次做完更新 AGENTS.md 的「当前进度 + 下一步」**：续传靠它，不靠会话记忆。

> AGENTS.md 是「这个项目的当前状态页」，本文档是「怎么做」的说明书。**换项目 = 复制模板重填；换会话 = 读 AGENTS.md 续传。**
> AI 协作要点：AGENTS.md 的「学习资料指针」节同时是喂给 AI 的上下文——每阶段开工让 AI「先读教材对应章节再写码」，AI 有地图就不会瞎编架构；人负责用样板 vs 机制表和构建验证做 gate。

## 核心原则

1. **答案卷是「参考」，不是「教材」**：把原项目 clone 到只读目录当作「参考答案」，始终放在旁边供对照，而不是先把它全部学完再动手。
2. **直接复刻 + 讲透**：
   - 配置、DTO、常量、目录结构等「工程惯例/样板」→ 从参考项目**直接复刻**；
   - 「机制/算法」（熔断、路由、融合、幂等、摘要、排队等）→ 也从参考项目**直接复刻**，并**讲透原理**（这才是真正要掌握的）——不强制学习者手写第一版，重点是把"为什么这么做、怎么转译成自己的代码"讲清楚。
3. **阶段式、单元式推进**：把项目拆成阶段/模块，每推进一处 commit 一次，粒度清晰。
4. **做中学 + 具象化**：`直接复刻 + 写码先行` 就是「动手做」——先照着写、跑通，再逐行讲，比空听更快（成熟 AI 教学平台如清华 OpenMAIC 的共识：被动听 ❌、动手做 ✅）。凡"关系/流转"类内容（数据流、状态机、调用链、架构依赖）**能用一张 ASCII 图/流程图示意就画一张**，别只文字——初学者看图比读字好学。

## 先修：业务与架构（初学者必读，最高优先讲清楚这两层）

> **默认读者是初学者**：以下每个概念首次出现都用大白话 + 例子解释；任何词你没见过就当场打断问「解释一下这个词」，**不许默认"这我该会"**。这是讲解的最高优先层——业务没讲清，架构是空壳；架构没讲清，代码是语法。
> **底层平台/协议词同等对待**：HTTP 方法（GET/POST/OPTIONS…）与 CORS 跨域预检、Servlet 容器/过滤器链/请求分发类型（`DispatcherType`）、线程池、序列化……这些"平台词"和业务词一样必须进先修、拆到已知地基——**判定法**：凡"解释它时不得不用另一个没讲过的词"的，连那个词一起拆。

### 先修概念① 业务与业务闭环

- **大白话**：业务 = 这个软件替用户解决什么问题；业务闭环 = 「用户进来 → 拿到价值出去」的一次完整流转。
- **例子**（知识库问答平台）：上传文档 → 解析分块 → 向量入库 → 用户提问 → 理解 → 检索 → 生成 → 带引用回答。从"用户传文档"到"用户拿到可回溯的答案"，一圈就是闭环。
- **为什么要先讲业务**：架构、选型、模块划分全是给业务服务的。不知道"做什么"就选型 = 猜；知道了闭环，每个模块/机制才有"它服务闭环哪一环"的坐标（这就是「业务闭环定位图」的由来）。

### 先修概念② 架构：模块怎么分、谁依赖谁、公共的放哪

**大白话**：架构 = 软件的组织方式，就三个问题：
1. **切成几块（模块化）**——按"变化频率"切：几乎不变的（地基）vs 经常变的（业务编排）分开，改一处不波及其他；
2. **谁能用谁（依赖方向）**——稳定在下、易变在上：地基不许依赖业务，业务可以依赖地基。例：framework（地基，零业务名词）← system/infra-ai（支撑）← rag/agent（业务域）← bootstrap（装配，依赖所有人）；
3. **大家都用的放哪（横切关注点）**——所有模块都会用到的能力（统一出参、参数校验、幂等、日志、Trace）**收到底层一处**。这就是 framework 那"一堆包装"的本质：**横切问题目录，每类问题一个通用解法**。不收敛的后果：每层各写一份出参/校验，改一次规格改十处。

### 先修概念③ 契约：先商量好数据形状，再写实现

- **大白话**：契约 = 模块之间"商量好的数据形状"（DTO、错误码、接口签名）。**先定契约，再写实现**——改实现不惊动使用方；契约放最底层全员共用。
- **例子**：Result（统一出参）定义在最底层 framework；业务层只抛异常不拼信封，翻译官（GlobalExceptionHandler）唯一入口——这就是"契约下沉 + 职责单点"。

### 先修概念④ 数据流：跟一条链走到头

- **大白话**：讲任何机制问三句——数据从哪来 → 在哪转（被谁判别/改写/分流）→ 落到哪（内存/DB/Redis/外部服务）。**跟到底、中间断开的那个点，就是你还没懂的地方**。
- **用法**：读代码从"业务方调用"一路追到外部系统，是最不迷路的读法（对应"复刻代码怎么看"的阅读顺序）。

### 讲解标准（初学者视角 + 溯源 + 权限）

**六段以「每类讲解 · 六段硬格式」为唯一标准**（见下节：①业务场景②架构位置③实现四问④代码块逐行⑤调用链实例⑥用法示例）。这里只补四条贯穿所有讲解的原则，不再另列一套六段：
- **初学者尺度**：默认读者是初学者，概念第一次出现必须用大白话 + 例子解释，不默认"这我该会"；
- **解释必须「到底」（术语不自举）**：任何解释里出现的每个词，要么是生活语言/语言基础，要么是本文此前已解释过的——**禁止用术语解释术语**（拿「预检请求」解释 OPTIONS、拿「异步派发」解释 `DispatcherType.ASYNC` 都是悬空，"预检/派发"本身也要拆）。判定法：把解释读给"只会语言语法的人"，有一个词他不认识且没铺垫 = 悬空，继续往下拆到落地为止。底层机制**首次出现拆到底**，同批内再出现可简写「见先修概念」；
- **溯源**：学习讲解与 NOTES 归档**允许**写"参考思路/出处"（学习需要可追溯）；
- **权限**：任何一次讲解里，你发现"某个概念被默认我会了"，随时打断要求解释；AI 讲解时若自己察觉概念没铺垫过，必须停下来先补概念。

**三层递进主线（业务→架构→代码）**：熟练 vibecoding 的前提是「先业务能力 → 再架构设计 → 最后看懂并掌控代码」。这三层是六段的**认知骨架**，讲解必须按这个顺序走、不许打乱或平铺：
- **第①层 业务能力** ↔ 六段 ①业务场景（+ 业务闭环定位图）——先答「不写代码时，业务上要解决什么、这个类服务闭环哪个动作」；
- **第②层 架构设计** ↔ 六段 ②架构位置——再答「它为什么放这一层、上下游依赖方向是否合理」；
- **第③层 代码实现** ↔ 六段 ③实现四问 + ④代码逐行 + ⑤调用链（⑥用法是"会用"的收口）——最后答「每段代码干嘛、调什么、为什么这么写，看得懂改得动」。
- 每层讲完、每类讲完，都要做「脱手复述测试」（见「验收问题」节）。

### 讲解实例化标准（不许"要点带过"，每个类讲完自问「新手能不能照着示例自己写一遍」）

- **实现必须配码逐行讲**：每个手法（cause 分叉 / 兜底链 / 毒值沉底…）**不允许只给手法名 + 一句**——必须贴对应真实代码段，并把**注释写在代码内部**（每处答三问：这是什么/为什么/不用会怎样）逐行标注；手法与代码一一对应，不能"手法说一套、代码贴另一段"。
- **代码必须自带详细注释，且就写在真实源码文件里（关键，写码那步就做）**：不只是讲解时贴注释——**写码落盘时，就把逐行级中文注释写进真实源文件**（类头职责 / 方法头「先做什么后做什么」/ 每个关键行 + 每个陌生 API 行内注释）。这样才满足「学习者不打开任何讲解、光看源码文件也能读懂每一段在干嘛」。讲解④里的代码块**直接照这份已注释源码贴**，不重复劳动。
- **每处注释答「三问」（正向配方，防只讲为什么不讲是什么）**：**①这是什么**——这个 API/机制本身是什么，一句话落到已知地基（解释里出现新词就继续拆，禁悬空）；**②为什么这行要它**——本行目的；**③不这样会怎样**——反例（关键分支才写）。反例（实测翻车）：`// ② 预检放行` 八个字带过 = 只答了②没答①，初学者不知道 OPTIONS 是什么、"预检"是啥流程；达标写法见 `../examples/黄金样例.md`「注释深度对照」。
- **代码内陌生 API 逐个点（初学者视角）**：代码里出现的每个库调用/工具方法/框架组件（`StrUtil.isEmpty`、`MessageBuilder.withPayload`、`getHeaders().get`、`TransactionTemplate.executeWithoutResult`、`@Builder.Default`、`UUID.randomUUID`…）都要点明它干嘛——初学者可能连这行在干嘛都不知道，不许把它们当"默认会"甩过去。**这个"点"就是三问注释，落在源码文件的该行的行内注释里**（不只讲在会话消息中）。
- **数据流必须给完整调用链实例**：不允许抽象链条（"异常→Spring→前端"）——必须写成带具体类名/方法名的一跳一跳：`小明点上传(200MB) → 浏览器 POST → Tomcat → DispatcherServlet → MultipartResolver 解析 → Tomcat 抛 FileSizeLimitExceededException → 包装成 MaxUploadSizeExceededException → HandlerExceptionResolver 链命中 → GHE.xxx 方法 → Results.failure → Jackson 序列化 → 前端收到 {code,message}`，读者能顺着每一跳跑一遍。
- **用法必须给可照写的示例**：不允许"业务代码 throw new ClientException(...)"一句带过——必须给出最小完整示例（写在哪个类哪个方法、调了什么、返回什么、前端收到什么），读者复制改改就能跑。
- **自检**：任何一个类讲完，若读者"仍然不知道从哪下手写一遍/跑一遍"，该类的讲解视为没讲完，回炉。这比"验收问题"更硬：验收问题是事后考，实例化标准是讲的时候就保证可仿写。**再来四条初学者自检**：①这段码里每个陌生 API/调用我都解释了吗？②注释三问齐吗（是什么/为什么/不用会怎样），有没有只写"为什么"四个字带过的？③**解释链有没有悬空词**（用没讲过的词解释新词，如"预检"解释 OPTIONS、"异步派发"解释 ASYNC）？④一个初学者**光打开源码文件**能看懂每一行在干嘛吗？任一 No = 没讲完。

### 验收问题 · 三层出题 + 脱手复述（方案 B + C：练出「可控 vibecoding」的三层能力）

- **脱手复述测试（每类必做，题数 = 本批类数，动态不固定；比问答更硬，且每题附标准答案）**：每个类讲完，让学习者**合上讲解、光凭自己写的源码（含注释）**，按三层用自己的话复述——**①业务**：这个类在业务闭环里解决什么、删掉会怎样；**②架构**：它为什么放这一层、上下游依赖方向怎样；**③代码**：这段代码分几件事、每件怎么落地、每个关键 API 干嘛。**本批几个类就出几道复述题**（8 类 = 8 题，不截成固定 3 题）；**复述题列出后，紧跟每题的标准答案（一问一答、按三层组织）**——学习者复述完照答案核对，磕巴卡壳的那一层 = 该层没内化 = 回炉该层。这是「你能脱离 AI 掌控代码」的度量器。
- **三层出题（一问一答带标准答案，题数随批动态）**：每批的验收题按三层**分别**出题——**每层出几题 = 该批该层的实际知识点与难点数**（一批有 2 个 ★ 机制难点，代码层可能出 3~4 题、业务层 1~2 题），**禁止死板"各一题"**；每层至少 1 题、题数随本批类量与难度增减，每题**紧跟标准答案**交付（不是"学习者先答、AI 事后给分"）——学习者照答案核对，答错/含糊的点 = 对应层回炉。
- **归档**：「脱手复述测试（题 + 标准答案，题数=类数）」和「三层出题（题 + 答案，每层题数随批动态）」都随该批的**讲解全文**同步写入 `NOTES/教学讲解/阶段N-<主题>（技术）/批次M-<主题>（核心类）.md`（按业务/架构/代码分层记），**一批讲完立即落盘**；
- **目的**：①答案一次给全、减少来回；②跨会话可复现（谁看到纪要都能对的答案）；③**每次验收同时卡死你三层能力的进展**，而不是只考代码语法。

### 每类讲解 · 六段硬格式（唯一标准：缺一段 = 该类未讲完）

> "实例化"太抽象，AI 在批量时会自带"样板能照抄"的降级心态；所以把交付物钉成**命名字段清单**，每个类独立成节，禁止 7 个类合一段讲要点。

> **初学者友好总则（六段每一段都适用）**：每段都按"零基础新手"来看——把术语 / 概念 / 手法 / API **第一次出现就用大白话 + 具体例子讲一句**（"这个 `xx` 就是干这个的"），**概念解释带一个生活化类比**（类比是记忆钩子、纯定义难记：token=游乐园手环、Redis=键值仓库、HTTP 请求=一封信、AOP=门帘），**不许甩名词、不许让新手靠猜**；每段讲完在心里问一句"一个没基础的新手能听懂这段话吗"，答不上就补到能听懂为止。**六段各占独立小节、段内能用图/表就别只用纯文字，禁止把六段压成一行式密集文本。**凡框架/工具/中间件/SDK 调用都要往下剥一层讲机制（防「API 调用工程师」）——★ 类再补 No-Framework 手写版 + 具体故障推演，落点见六段③④⑥与黄金样例「一·续三」。**下面六段逐条带上这条总则。

**每个类的讲解必须按序出现且只能按序出现这六段**：

1. **业务场景**：用**大白话**讲一句**具象**用户场景——**有名字/身份的人 + 具体数值 + 期望结果**（"小明上传 200MB"），不许抽象描述（"审计行要标业务域"这种没有具体的人 = 不合格）；出现看不懂的业务名词先口头点一句。
2. **架构位置**：**每个架构术语（模块 / 依赖方向 / 横切关注点 / 契约 / 切面 / 中间件…）先用大白话 + 例子讲一句、不默认会**，再讲这个类放哪层、上下游是谁、为什么在这。
3. **实现四问**（**禁电报体**：每一问都必须写完整教学句，"手法：A+B""边界：A/B/C"这种名词串一行带过 = 没讲）：①**思路**用大白话拆成"先做什么、后做什么"的明确步骤（不是一句术语，像给同事口头交代活）；②**手法**每个都用大白话讲清"它是什么 / 为什么这么用 / 不用会怎样（反例）"，不只点名——点名了 SaInterceptor，还要说清 SaInterceptor 是什么、为什么登录检查交给它；**若该手法是框架/外部工具，再补一句「它内部怎么做到的」（L1 机制层）**——只写「用 X 做 Y」是 API 清单，不是手法；③**数据流**用大白话跟一条链（从哪来 → 在哪被判别/改写 → 去哪，落 Redis/MQ/DB 哪一处）；④**边界**讲清"什么情况走哪条分支、抛异常、跳过"，每个分支补一句"为什么这条分支存在"。
4. **代码块逐行**：≥1 段真实代码（**必须整方法/整段贴出；标注"节选"也算片段，照样不达标**——"源码文件里已有注释"不是节选的理由，类短就整文件贴出），**注释必须写在代码块内部**——每个关键行/每类行为 `// 一行中文注释` 写「这行在干嘛 + 为什么这样写」；**代码外面写几段话 ≠ 逐行标注**（参照黄金样例：注释都长在代码里）。**这段代码必须和你写进源码文件的那份一致**——即：源码文件本身已经带逐行中文注释（每处答三问），讲解直接照它贴。**代码里每个可能不认识的库调用/工具方法/框架 API/平台机制（`MessageBuilder`、`getHeaders().get`、`TransactionTemplate`、`DefaultRedisScript`、`StrUtil`、`@Builder.Default`、`UUID.randomUUID`、`DispatcherType`、HTTP 方法…）都要在行注释里按三问点清"这是什么/为什么这行要它/不这样会怎样"**——初学者可能连这行是干嘛的都不知道，不许甩裸代码；**其中三问的「①这是什么」要答到机制层**（「它内部靠 X 做到的」），不只是「它是干嘛的」——否则读下来只记住一堆调用姿势；
5. **调用链实例**：从业务入口到落点的一跳一跳完整链路（带类名/方法名），**每一跳用大白话注释它干嘛**（像黄金样例：`DispatcherServlet（Spring MVC 的总入口，所有请求都先到它）`），跳数 **≥8**（详细度基准见下节「黄金样例」）；
6. **用法示例**：可照写的最小片段（写在哪个类哪个方法 / 调了什么 / 返回什么 / 读者复制改改能跑）；**"调了什么、返回什么"用白话说清**。**末尾给「No-Framework 最小手写版」**——不用这个框架/工具你怎么写 20~40 行等价实现（★ 类与核心依赖必给，其余至少一句「手写要做哪几步」）。

**样板不减配**：样板类（DTO / 配置 / 常量 / 枚举 / 工具）第 1~6 段**全部照常存在、照满深度讲**——一个 DTO 也要讲清「它装什么数据、每个字段什么含义、数据从谁流来、被谁读走、为什么这样设计」，不允许只给要点 + 落码路径。区别只在**份量**（3 行的 DTO 讲几十行、上百行的机制讲几百行），**深度不打折**。

**自检**：每个类讲完过一遍六段清单，缺一段立即回炉补那一段；**并逐段问"一个零基础新手能听懂这段吗、每个术语/API 我都白话点一句了吗"**，答不上就回炉；批量时按类分节，禁止合并。

**批量讲解的节流策略（篇幅控制，但不牺牲六段与满深度）**：同类样板（如 3 个 context 类）可共享"先修概念 + 调用链"，但每类自己的代码块和用法示例不共享、必须各自出现——共享的是"共同背景"，不是"偷懒少讲"；每一类该自己讲的（自己的字段、自己的场景、自己的用法）一件不少。

**讲到外部中间件时（红线，别只讲"数据进出"）**：某类/某机制调用外部中间件（Redis / MQ / MySQL / MinIO / 对象存储 / LLM 服务等），或做了网络/进程外调用时，在 **③数据流·边界** 与 **⑥用法** 里，除"数据怎么进出"外必须再讲清四件事——①**它是什么**（一句白话：在系统里扮演什么角色）；②**怎么接**（用什么客户端 / 连接 / 初始化 / 配置落在哪个 bean、config 或环境变量，不能只甩一句"调了个方法"）；③**惯用 API**（关键方法、正确/惯用写法，配真实代码「这行在干嘛/为什么」）；④**失败怎么办**（超时/重试/降级/兜底红线——中间件挂了，主链路还有没有保底、走什么分支）。这是"学会成熟项目"最值钱的部分：很多项目的价值就在中间件集成的接法与取舍。

### 黄金样例参照制（字段清单升级为样例校准，防"完成字段但达不到深度"）

> 六段清单独给了字段名，AI 批量时会"完成字段"而非"达到样例深度"——像按"人物/情节"提纲写小说，写出来只是大纲句。所以把达标形态钉成**可对照的黄金样例**。

- **黄金样例**：`../examples/黄金样例.md`（GHE 六段完整示范 = 每类讲解的达标基准）。**每类开工讲解前先读它校准深度**，而不是对着字段清单打勾；换任何机制只换内容、格式与深度不变。
- **每段详细度基准**（样例文件中有明文判定表）：
  - 业务场景：带**具体的人 + 具体数值/配置值 + 期望结果**（"小明 200MB 文件、yaml 上限 50MB"），无名字无数值 = 抽象句不达标；
  - 调用链：**≥8 跳**、每跳带真实类名/方法名/具体异常名与消息形态，结尾给**读法提示**（"断在第 N~M 跳 = 没懂的点"）；
  - 代码块：**整方法**贴出 + **逐行中文注释**（注释写在**代码内**，这行干嘛 + 为什么这个深度/不是别的方式；**代码外面写几段话不算逐行**），**每个陌生 API/调用点一句"它是干嘛的"**，每个手法必须有**反例对比**（"不这样做会怎样"）；
  - 用法：完整可跑片段 + **触发回放**（输入 → JSON/返回 → 前端反应）；
- **拆批原则**：批次按「相关类聚合」分（一批 = 同一件事的件，3~9 件合理区间，数量不设死上限；十几个/几十个件塞一批必然压缩到大纲句，就按主题切多批，宁多批不量产）。调用链跳数基准 **≥8**。
- **自检**：每类讲完对照黄金样例 6 条自查（样例文件第三节），任一 No = 未讲完，回炉。

## 复刻代码怎么看（阅读顺序 + 详解）

> 场景：面对刚复刻出来的一个模块/一批类，不知道从哪下手。目标是**看懂**，不是背下来。

**核心原则：沿「一条业务/数据链」走，而不是按目录顺序逐行读；先样板热身、后机制攻坚。**

### 阅读顺序（按这个走，就不迷路）
1. **先排雷**：把包里每个类归到两类——
   - **样板**：注解(→Python/TS 的装饰器) / DTO / 常量 / 枚举 / 工具（结构简单，提供契约或数据）；
   - **机制**：切面(→中间件/AOP 横切) / 算法 / 状态机 / 路由（真正的核心逻辑）。
2. **读「入口注解 / 接口」**：看业务方**怎么写、有什么旋钮**。看 `@Target/@Retention`、字段默认值、每个参数含义，搞清能力边界。
3. **读「支撑件」**（枚举 / 工具 / 常量）：通常很短，但被机制依赖。搞清「状态值 / 动态 key」怎么来。
4. **读「机制类」**（最重要，**最后读、花最多时间**）：用**两把尺子**——
   - **调用链**：谁拦截谁、谁调用谁、在哪个阶段织入；
   - **数据流**：数据怎么生成 → 怎么进外部系统（Redis/MQ/DB）→ 怎么被判别/流转。
5. **对比升华**：若模块里有两件相似但不同的事（如「防重复提交 vs 防重复消费」），最后对比**为什么机制不同** —— 这才是学会。

### 每个类 / 方法怎么读
- **先读注释，再读代码**：注释写着「做什么/为什么」，等于先给了地图，别一上来抠语法。
- **先看方法签名与关键分支，最后看喂料的工具函数**：工具函数只是给主逻辑喂数据，放最后。
- **用「三态 / 边界」视角**：看返回值有哪些分支（如 null/状态A/状态B）、哪些情况抛异常、哪些情况直接跳过。

### 卡住怎么办
- **对官方 diff**：拿参考项目对应类对照，看差异和遗漏。
- **追一条完整数据流**：从「业务方调用」一路追到外部系统，中间断开处就是没理解的地方。
- **自己复述**：能用自己的话讲清每条链为什么这么做，才算真懂。

### 交付时配合「详解」，不要一句话带过

**三层学习目标（六段的由来，不是另一套结构）**：讲解背后有三个递进目标——①**业务**（为闭环哪一环服务、解决什么问题）、②**架构**（放哪层、上下游、为什么）、③**功能实现**（机制怎么转、数据怎么流、边界在哪）。**它们分别被六段的 ①业务场景 / ②架构位置 / ③实现四问 承载**，所以讲解只按**六段**走，三层是"为什么这六段"的注脚。样板类与机制类**同一套六段、同一深度**：样板类必讲「业务定位 + 契约语义 + 为什么放在这 + 数据从哪来往哪去」，机制类同样讲，且机制类额外多的是调用链 / 数据流 / 边界——两者都**满深度**，只是份量有别。每个类讲完自问："删掉它或换一种设计，业务闭环的哪个问题会回来？"

**四层 = 六段的前四段（不要当另一套）**：四层（①业务定位 / ②架构定位 / ③实现要点 / ④具体代码讲解）就是六段的 **①→④**；六段再补 ⑤调用链、⑥用法。**所以结构只有六段这一个。** ④是硬性段：只讲要点不贴码、或贴码不逐段讲解，都算没讲。样板与机制**同一结构、同一满深度**；机制也**直接复刻并讲透**（AI 直接给实现 + 讲解），不单独要求学习者自写第一版；两类都按六段满深度讲。

**实现段·四问（六段的③）**：六段的「实现」段固定拆四问——①**实现思路**（这条链怎么串起来，先做什么后做什么）；②**实现手法**（用了什么可迁移技巧：Optional 兜底、判 cause 链、截断堆栈、组合注解、静态工厂…）；③**数据流**（数据从哪来、怎么被判别/流转、去哪）；④**边界**（null/三态分支/异常/跳过场景）。四问缺一问 = 实现段没讲完。

**唯一编排（先看这，别再被下面几套结构绕晕）**：推进顺序 = 下方「工作单元执行流程」的 **0-6**（含 先修概念→业务闭环定位前置→类清单表→逐类六段→每批验收一问一答→每批构建验证→归档，即 `../SKILL.md` 的「标准讲解循环」）；逐类讲解 = **「每类讲解 · 六段硬格式」**（六段是**唯一**逐类结构；前文「讲解标准」小节里那句不全的 ②④ 六段是旧版列法，忽略）。以下是**旧版/同义/不同粒度**，不要照着另讲一套：「讲解闭环」=旧角度（已并入六段+标准循环）；「详解产出模板」已压缩为下面「机制类示例」、「每步交付七要素」已压缩为「每步开工·两件必有」（其余已被六段+先修+验收覆盖）；「推进流程」= **阶段级**循环（粒度更大，与逐批循环不重叠）；「讲解深度与类清单」= 类清单表（每阶段开工一次，不再分档）。

**讲解闭环**：①**零遗漏**：讲解范围 = 边界对照表全表，每个文件都按六段过一遍，不许只挑"重点类"讲；②**讲后验收**：每批讲完由学习者复述/自测（能用自己的话讲清一条链 = 过关），AI 给 2~3 个验收问题；答不上就回炉该批讲解，不得带着"没听懂"进下一批；③学习者可用豁免词跳过验收，但构建验证永不免。

**机制类详解示例（六段的一种浓缩；逐类讲解一律按「六段硬格式」给，此处不再单列一套详解产出模板）**：
> 举例（防重复消费的 Lua 状态机）：责任=用 Redis 原子占位防同一条消息重复消费；权衡=「恰好一次+可重试」决定要带状态而非纯锁；调用链=AOP `@Around` 拦 `@IdempotentConsume` → Lua → StringRedisTemplate；数据流=首次 null 进业务→成功置 CONSUMED→异常删标记可重试→并发重复命中 CONSUMING 抛 ServiceException；代码=那段 `SET NX GET PX` Lua；可复用模式=「业务唯一 key + 三态 + TTL」做幂等。

## 每步开工 · 两件必有（其余被六段/先修/验收覆盖）

> 逐类讲解主体按「六段硬格式」给（①业务场景②架构位置③实现四问④代码块逐行⑤调用链⑥用法）；「先修概念」讲新名词；「每批验收」给面试题+答案。这里只补**六段/先修/验收都没覆盖**的两件：
1. **该创建的文件（路径清单）**：写码前先列出这一步要建/改的文件，标注「直接复刻」。
2. **推进指令**：学习者可用 `done`（完成）→ `next`（下一步）→ `explain`（解释这一步）控制节奏。

## 工作单元执行流程（学习会话 · 强制 gate）

> 解决「方法论说要详解，但没写什么顺序/先讲还是后写」：**默认学习会话走下面硬性顺序，写码先行、讲解在后——讲解要照着已写好的码逐行讲。**

**触发条件（决定是否走讲解流程）**：
- 默认「读 AGENTS.md 继续 <阶段/模块>」= **学习会话** = 必须走这个流程；
- 仅当用户明确说「只要出活 / 量产 / 别讲 / 直接写」时，才可跳过详解直接写码，但交付仍需给「源码 + 设计决策表 + 可复用模式」（一页纸说明，不逐类走读）；**构建验证不随此豁免，任何模式都必须做**。

**半授权指令**：出活豁免的唯一触发 = 用户字面使用豁免词「只要出活 / 量产 / 别讲 / 直接写」。「样板你写」「机制你直接复刻并讲透」等指令只改**实现归属**（样板由 AI 代写 / 机制由 AI 直接复刻），**讲解义务不变**——样板批同样写码后按六段满深度讲，机制写码后按六段满深度讲透（先写码、再照码讲）。

**执行顺序（走读→写码→照码讲）**：
0. **业务闭环定位前置**：先输出「业务闭环定位图」——本批代码在主链路（如 提问→理解→检索→生成→溯源 / 或对应域的主链路）的哪一段、服务哪个业务场景；讲解从全局定位开始落到类，禁止孤立地逐类念注释。
1. **边界对照（先圈范围）**：对照参考项目该模块清单，把要做的类/文件列全，确认无漏再动手（勾 `[x]` 到完整性地图）。
2. **排雷分类**：把本批类分成「样板（注解/DTO/常量/枚举/工具）」与「机制（切面/算法/状态机）」，这**只用于安排阅读顺序**（先简单后难），**不用于决定讲解深浅**——两类都满深度讲。
3. **整批写码 + 逐类六段讲解（主体，写码先于讲解）**：本批开工前先出《类清单表》（见「讲解深度与类清单」）；**开写前先补"先修概念"**（见「先修：业务与架构」，不默认会）；然后**先写该批次的全部类**（复刻出你的实现，用户可全程对照真实码），**再逐个类照码讲**——**每类都按「六段硬格式」完整讲满深度**（1 类 1 节，禁止合并；即便整批先写完，讲解也要逐类完整、不合并；同类样板才可共享先修概念+调用链，每类代码块与用法示例不共享）。**写码先于讲解，讲解必须落到码上**。该批讲解完立即做验收（脱手复述 + 三层出题带标准答案，见「验收问题 · 三层出题 + 脱手复述」）。
4. **对照 diff**：写完后与参考项目对应类 diff，看差异/遗漏，补齐。
5. **构建验证（每批必做，先于归档）**：每写完一批立即构建并如实汇报证据——铁律见「证据先于断言」（`../references/通用工程约定.md` §1，未跑不得宣称完成）。复刻特有的节奏要求只有一条：**每批完成立即验证，不许「全部写完再一次性验证」**。
6. **归档 + 讲解全文落盘 + commit**：归档「完整源码 + 设计决策表 + 可复用模式」；**把本批完整六段讲解整篇写入 `NOTES/教学讲解/阶段N-<主题>（技术）/批次M-<主题>（核心类）.md`**（八块：先修概念 / 业务闭环定位 / 类清单表 / 全局调用链图 / 逐类六段全文 / 验收（脱手复述+三层出题带答案）/ 构建证据 / 溯源与 diff 结论），并同步 `00-阶段总览.md` 索引；更新 `NOTES/阶段N-主题.md`（状态与索引，全文链接过去）；更新项目 AGENTS.md「当前进度 + 下一步」；到一个验收点 commit。

**红线**：
- 讲解顺序 = 阅读顺序（排雷 → 入口注解/接口 → 支撑件 → 机制类 → 对比升华），别跳、别先讲最难的。
- 讲解粒度 = 每个类/每个机制都要拆，不许一句话带过；机制类必须讲「调用链 + 数据流」。
- **写码先于讲解**：先写该批次的类，再照着写真码**逐类**讲六段（每类 1 节、不合并）——代码是讲解的依据；**全批写完不逐类讲=没讲完**，只讲要点不贴码=没讲。
- **每批完成即编译测试**：写完一批 → 立即构建验证并汇报结果，通过才归档 / commit；失败就修到通过、或如实报告阻塞，绝不带着未验证的红状态往下走。

## 大型项目先行：全链路拆解文档（地图先行）

**触发条件**：参考项目体量大（数百个以上源文件）、或计划多阶段长周期复刻时，先一次性投入产出《\<项目名\>-全链路开发详解》，再开始逐阶段动手——避免每个学习会话都在重复「从零建立全局观」。

**覆盖度清单**（缺一块就是盲区，按项目形态裁剪）：
① 业务全景与闭环；② 开发历程还原（从 release notes / upgrade SQL / git 记录反推演进顺序与真实踩坑）；③ 总体架构与技术选型（模块依赖方向图 + 选型理由 + 备选对比）；④ 基建层；⑤ 模型/AI 能力接入层；⑥ 数据入库链路；⑦ 检索/核心算法链路；⑧ 编排/服务层；⑨ 扩展执行架构（Agent 等）；⑩ 前端 + 数据库设计（ER 图 + 字段动机 + 表↔模块读写矩阵，不能只有表清单）；⑪ 测试与质量体系；⑫ 复刻路线图（阶段表：每阶段直接复刻什么、逐类满深度讲解清单、验收标准）。

**粒度红线**：每个机制固定五段——职责／为什么这么设计／调用链／数据流与边界（异常·降级·三态分支）／可复用模式，重点机制附真实源码节选（≤35 行并标注路径）；整体写到「能导航、敢下手」为止，**禁止逐类全文粘贴**——详解的正文是源码本身，文档只是地图。每章末尾必备两件套：「样板 vs 机制清单表」（两类都逐类满深度讲，清单只标各自"是什么"）+ 面试追问点。

**生产方式**（可大幅提速）：主会话亲自写决定全书观点的总览章（业务/历程/架构/路线图），相互独立的大域派子代理并行深读后按统一格式模板产出章节稿，最后汇编成单文件；所有量化口径以实测为准，不信 README 自述数字。

**定位声明（防跑偏）**：拆解文档完成后**冻结为 v1 地图**——使命是导航，不是教材正文；后续只允许由复刻实践回填踩坑与修正，不允许脱离动手的单向加厚。深度发生在「直接复刻→diff→构建验证」里，不在阅读量里。

## 推进流程（阶段级 · 每阶段的动作；区别于逐批「标准讲解循环」）

> 这是**阶段级**的循环（一个阶段从头到尾），与上面「工作单元执行流程」的**逐批**循环粒度不同、不重叠：逐批循环管"每批怎么分、讲+写+验+归档"（批次 = 相关类聚合，见 `../SKILL.md`「分批」），这里管"一个阶段从读全局到归档怎么做"。两者都用，别混。

1. **读总纲/拆解**：先读项目的架构拆解笔记、总教程（大项目若尚无拆解文档，先按上一节「地图先行」流程产出一部），建立「它长什么样」的全局观。
2. **跑通参照**：搭好环境，把参考项目跑起来，看到「目标效果」。
3. **读答案卷对应类**：写某模块前，先读原项目对应类，弄懂「为什么这么写」。
4. **直接复刻**：对照原项目复刻你自己的实现（样板抄、机制复刻并讲透）。
5. **对照验证**：写完 `diff` 对照参考项目，看差异/遗漏。
6. **归档进度**：把「当前进度 + 下一步 + 学习方法」写进项目级约定文件（如 `AGENTS.md`），并把本段产出追加到 `NOTES/NOTES.md`（总览）与 `NOTES/阶段N-主题.md`（阶段详情，见下节），方便新会话/新阶段续传。

## 会话归档（学习笔记，跨项目通用）

**触发时机**：① 讲完一段内容（一个工作单元/知识点讲透）；② 用户提出归档；③ 结束会话前。

**归档结构（三层）**：
- **全局总览**：`<每个项目根>/NOTES/NOTES.md` —— 所有会话、所有阶段都可编辑完善。放：总进度、整体踩坑清单、可复用设计资产、各阶段文件的索引链接。它是「总览 + 索引」。
- **阶段归档（工程侧）**：`<每个项目根>/NOTES/阶段N-主题.md` —— **一个阶段一个文件，只能完善该阶段的内容**。放该阶段的详细会话归档（见下）。随阶段进展在 `NOTES/` 下新增对应文件。**只放状态与索引**（机制摘要 / 构建证据 / 下一步 / 决策），**完整讲解一律链接到下面的教学讲解目录**，不重复存一份。
- **教学讲解（学习侧，「阶段→批次」两级目录）**：`<每个项目根>/NOTES/教学讲解/阶段N-<主题>（技术）/批次M-<主题>（核心类）.md` —— **一批一个文件，装该批的完整六段讲解全文**。这是唯一能跨会话回看的讲解载体，详见下节。

**归档内容（阶段文件，完整代码档）**：
- **阶段概述**：目标、涉及模块、完成状态；
- **完整源码**：每个关键类/配置**贴完整代码**（供其它项目 / AI 直接参考复用）；
- **设计决策**：每个类/结构用「决策 → 原因」表讲清为什么这么写；
- **可复用模式**：抽象出可迁移到什么场景 / 什么项目可复用的模式与技巧；
- **操作记录**：改了哪些文件、解决了什么问题、调用了什么（命令/接口）；
- **问答记录**：重要讨论（问了什么、答了什么）；
- **踩坑细节**：具体到原因和解决（编码/端口/一致性等）；
- **当前进度**：更新到该阶段结束点，方便续传。

**教学讲解（阶段→批次两级目录，装完整讲解，与阶段归档并列）**：

- **为什么必须落盘（这条是踩过坑的）**：聊天窗口会随会话变长被**压缩折叠**，讲过的内容回头就翻不到——真实事故：某阶段批次2 的整份六段讲解在聊天里消失，用户问"给了吗怎么没看到"，只能整批重讲。所以**课堂上那份完整讲解必须整篇写进文件**，纪要式摘要不够用。

- **目录结构**（按「阶段 → 批次」两级建目录，命名带"跟什么有关"的标注）：

  ```
  NOTES/教学讲解/
    └─ 阶段4-system支撑域（Sa-Token认证+审计变更日志）/        ← 目录名带本阶段关键技术
         ├─ 00-阶段总览.md                                    ← 索引：定位 + 批次清单链接 + 进度
         ├─ 批次1-SaToken认证三件套（三件套+UserDO+UserRole）.md
         ├─ 批次2-Auth登录登出（AuthServiceImpl★+LoginVO）.md   ← 文件名带本批核心类
         └─ 批次3-审计写侧（BizChangeLogContext★+RecordService）.md
  ```

- **命名规则**：阶段目录 = `阶段N-<主题>（<本阶段关键技术 2~3 个>）`；批次文件 = `批次M-<一句话主题>（<本批核心类，★ 标重点>）`。**括号里的"跟什么有关"是强制的**——日后扫一眼目录就知道每批讲了什么、涉及哪些类，不必逐个点开。**约束**：总长 ≤40 字；禁用 Windows 非法字符 `\ / : * ? " < > |`（多个类名用 `+` 连接，别用 `/`）。

- **每个批次文件的内容（八块齐全，是"全文"不是"提取物"）**：
  ① **先修概念**（本批新词 → 一句话大白话）；② **业务闭环定位**（本批服务哪个动作 + 定位图）；③ **本批类清单表**（每类一句"它是干嘛的"）；④ **全局调用链图**（先给空间感，再逐类展开）；⑤ **逐类六段全文**（每类独立一节：业务场景 / 架构位置 / 实现四问 / 代码逐行·整方法贴全 / 调用链≥8跳带类名 / 用法+触发回放）；⑥ **验收**（脱手复述题（题数=类数） + 三层出题（每层题数随批动态），**题后紧跟标准答案**）；⑦ **构建验证证据**（测试数、BUILD SUCCESS）；⑧ **溯源 + 与答案卷 diff 结论**。模板见 `../references/批次讲解全文模板.md`。

- **写入时机**：**一批讲完立即写该批文件 + 更新 `00-阶段总览.md`**。禁止"攒到阶段结束一起写"——中途开新会话就拿不回聊天里的讲解了。

- **复用价值**：给其他项目参考时，教学讲解（概念层全文）+ 阶段归档（决策/坑）+ 复刻代码（模式）三者合起来 = 概念 / 决策 / 模式 / 坑 / 代码五层齐备。

**详细度标准**：可被其它项目 / AI 直接当参考，**含完整代码**；代码保留正常说明注释，**可注明出处/引用的框架工具**。

**规则**：
- `NOTES/NOTES.md`（全局）谁都可改；`NOTES/阶段N-xxx.md` 只完善对应阶段的文件；`NOTES/教学讲解/` 下按批新增文件，**已写完的批次文件只补充不重写**；
- 归档到哪个阶段文件 = 按「这个会话推进到哪个阶段」决定；
- 讲完一段即归档，**可注明出处/参考思路**，不进 git（`NOTES/` 整文件夹被 `.gitignore` 排除）；
- **讲解必须落盘**：每批讲完立即把完整六段讲解写进 `NOTES/教学讲解/阶段N-<主题>（技术）/批次M-<主题>（核心类）.md`——聊天会被压缩折叠，只有磁盘上的能长期回看；目录与文件名**必须带"跟什么有关"的标注**；
- **面试题不进阶段归档**，统一追加到 `<项目根>/NOTES/面试题.md`（跨阶段累积，含简答）。

> 原则：**不等用户催，讲完一段即归档**。归档写「做了什么/学到什么」，**可注明出处/参考思路**；全局 `NOTES/NOTES.md` 是总览，阶段文件是详情，二者配合形成可回看、可跨项目参考的完整学习流水。
>
> 续传对齐：本节与「通用长项目上下文管理 / 续接规范」同源——磁盘当记忆，不靠对话；NOTES 体系即它在学习场景的特化实现（PROGRESS.md ≈ AGENTS.md 进度表 + 本 NOTES）。

## 会话分配策略（跨项目通用）

**原则：按「上下文相对独立的工作单元」切会话，不是死板地「一阶段一会话」。**

**新会话触发时机**（满足任一即可归档当前、开新会话）：
1. **切换大业务域**（如从 framework 切到 infra-ai、从建库切到写代码）：不同域的上下文差异大，适合开新会话。
2. **当前会话 token 过高 / 上下文混乱**：长会话 + 大量日志/报错堆栈，应归档；`token` 高是正常信号，不是异常。
3. **一个「工作单元」完成，要开启另一个**：单元边界 = 一个阶段 / 一个模块 / 一个自洽的功能。

> **模型应主动提醒**：当上下文/日志明显偏大、或刚好完成一个工作单元时，主动提示用户「先归档 + 再开新会话」（归档触发时机见上节），把决策权交给用户，不要默默拖长单会话。

**判断「一个会话能装下多少」的依据**（而不是阶段编号）：
- 该单元涉及的上下文类型是否单一（纯配置？纯业务代码？纯排查？）；
- 是否大量来回讨论/打印日志（这些最耗 token）；
- 是否在一个自然的「可验收点」结束（如一个类跑通、一批 commit）。

**会话之间的衔接依赖「持久化状态」，绝不依赖会话内记忆**：
- **进度 + 下一步 + 学习方法** → 写进项目级约定文件 `AGENTS.md`（本地，随工作目录）；
- **代码成果** → git commit（每批一次，一批 = 一个可运行最小增量）；
- **参考实现** → 官方答案卷（只读，始终在）。

> 因此换会话不丢进度——新会话只需读 `AGENTS.md`（自动）+ 看 git log，即可无缝续传。

## 全量复刻完整性方法（零遗漏）

> 适用：目标是「把参考项目**整个**复刻完整」，而非只学某几个模块时。核心是**把参考项目每个文件分配到阶段并逐项勾掉**，杜绝「漏了某个模块/文件」。

**原则**：完整复刻 = 覆盖参考项目**所有可交付内容**，分 track 归阶段，靠清单 + 最终 diff 兜底清零。

1. **全量盘点**：进入项目即枚举参考项目每个文件，按类型归类：
   - 后端代码（`.java` 等）→ 按模块归到对应后端阶段；
   - 前端代码（`.ts/.tsx` 等）→ 独立前端 track；
   - 基础设施（`.sql/.yaml/.properties`、docker、初始化脚本）→ 归到「建库/装配」阶段；
   - 文档/脚本/素材（`.md`、`.sh`、示例、图片）→ 收尾「对照 + 文档」阶段。
2. **按技术栈分 track**：后端与前端是不同技术栈，**别混在同一阶段**。后端优先、前端殿后（前端依赖后端接口好用再联调）。
3. **建权威清单**：把每个文件写进 `<项目根>/NOTES/阶段对照-完整性地图.md`，带 `[x]/[ ]`，并用 **★ 标出「重点/难点」**（面试高频+目标要用+逻辑较难的类）。它既是「零遗漏」的唯一依据，也是续传入口——**不靠记忆，靠清单跑**；★ 项只是「这类的逻辑较难、讲透要多花时间」的提示，**不作为讲解深度区分——所有类都满深度讲**。
4. **阶段边界对照**：每进一个新阶段，先对照该模块参考项目包清单（列出全部类/文件），确认无漏才动手；每完成一个类/文件就勾 `[x]`。
5. **样板/机制分治（后端、前端同理）**：
   - 后端：配置/DTO/常量/目录结构 → 直接复刻；熔断/幂等/摘要/检索/排队等机制 → 直接复刻并讲透原理。
   - 前端：组件骨架/样式/依赖/路由 → 直接复刻；交互逻辑/状态管理/流式渲染 → 直接复刻并讲透原理。
6. **最终 diff 兜底**：收尾阶段把实现与参考项目全量 diff，清单里所有 `[ ]` 清零才算 100% 复刻。

**落地载体**：
- 权威清单：`<项目根>/NOTES/阶段对照-完整性地图.md`（不进 git）；
- 进度/下一步 → 项目级 `AGENTS.md`（本地）；代码成果 → git commit；参考实现 → 只读答案卷。

**示例映射**（一个「后端 Java + 前端 React/TS」的项目）：
| 部分 | 阶段归属 |
|---|---|
| 后端（Java 多模块） | 阶段 0-12（后端） |
| 前端（React/TS） | 阶段 13（前端，殿后） |
| 基础设施（SQL/配置/docker） | 建库/装配阶段 |
| 文档/脚本 | 收尾「对照 + 文档」阶段 |

## 选择性复刻（跨栈 / 降配 / 时间受限场景）

全量复刻不是默认答案。出现以下任一情况，改走「选择性复刻」：
- 参照项目技术栈 ≠ 你的练手/落地目标栈（如 Java 参照物、Python 目标项目）；
- 有明确的近期交付目标（比赛/工期），只能碎片时间投入；
- 参照项目的大部分能力你已有等价积累。

**做法**：挑 3~5 个核心机制在目标栈上 mini-replicate，其余内容降级为「字典式查阅」（读拆解文档对应章节即可，不动手）。机制入选须同时满足三条：
1. 面试高频、能讲出权衡的点；
2. 目标项目近期真的要用（学完直接长在交付物上，一鱼两吃）；
3. 机制足够自洽（一个工作单元内可完成「读懂→复刻→测过」闭环）。

### 讲解深度与类清单（教学标准：每一类都满深度，节奏靠分批控）

**一句话**：讲解深度**不分档、每一类都满深度**——不管是复杂机制还是一个 DTO/配置/常量零件，六段都完整走一遍、讲到新手能看懂每一行为止；**节奏靠分阶段 + 分批控制，不靠降深度省时间**——批次按「相关类聚合」分：一批 = 同一件事（同一主题/调用链）的件，数量不设死上限、以 3~9 件为合理区间（十几个/几十个件硬塞一批必然压成大锅面，就按主题切多批，宁多批不量产）。开工先出《类清单表》（每个该复刻文件一句「是什么/它干嘛的」），确认范围后逐类满深度讲。

**《类清单表》（每阶段开工 gate 第一步给出）**：列出本阶段每个类 + 一句「是什么/它干嘛的」，供你确认范围/有无遗漏后再进入逐类讲解。**不再分级、不再定档——所有类统一满深度。**

| 列 | 内容 |
|---|---|
| 类 / 文件 | 本阶段要实现的类名 |
| 它是什么 / 它干嘛的 | 一句大白话（机制类写"它解决什么+怎么转"，零件类写"它装什么数据/被谁用"） |
| 备注（可选） | ★=重点/难点（逻辑较难，多花时间讲透），仅提示不为分档 |

**每类必满深度、不乱的依据**：
- **★ 只是"重点/难点"提示，不是讲解深度开关**——它在拆地图（开局三件套第②步）时预标，标的是「**这类的逻辑较难、讲透要多花时间**」，而不是「这类的讲深、别的讲浅」。
- 深度按"这个类有没有值得讲透的东西"看，但**结果永远是满深度**：算法/编排/竞态要满深度讲机制，一个 DTO/配置/常量同样满深度讲「它为什么存在、字段什么含义、数据从哪来、被谁用」——差别只在**份量**（行多行少），不在**深度**。
- 《类清单表》在讲解**之前**给，你点头后逐类落实、按批（相关类聚合，3~9 件合理区间）多轮次推进；每批验证通过即 commit（一批 = 一个可运行最小增量，不攒到阶段收尾）。

**讲解记录原则（全文落盘，不只记提取物）**：每批讲完，把**完整六段讲解整篇**写进 `NOTES/教学讲解/阶段N-<主题>（技术）/批次M-<主题>（核心类）.md`——每类独立一节、整方法代码贴全、调用链≥8跳、验收附标准答案。**不要只记"知识提取物"**：摘要检索快但学不回去，而聊天记录会被压缩折叠，摘要 + 消失的聊天 = 两头空。`../examples/黄金样例.md` 是"讲到什么程度算达标"的基准锚点，不是"不用落盘"的理由。

## 经验沉淀

- **踩坑清单**：每阶段遇到的坑（版本/编码/端口/一致性等）记下来，复用。
- **可复用资产分三层沉淀**（对 vibecoding 的复用价值依次递增）：
  1. **思想层·模式卡**：语言无关的模式卡，每张必含「何时用／何时不用／备选／权衡」——**并入已有的技能库/笔记体系对应条目做实证补充，不另起平行体系**；入库格式按通用技能编写规范执行；
  2. **骨架层·可复制骨架**：配置模板、Lua 脚本、SSE 事件协议、表设计模式清单这类与业务无关的工程件，放全局学习资产目录；
  3. **成品层·自研机制代码**：你自己复刻出来的机制实现才是最可复用的资产——每一行你都懂、都能改；它活在复刻仓库里，用 git tag 标注「可复用里程碑」。
- **可复用设计笔记**：项目收官时把三层资产汇总成一页《\<项目名\>-可复用设计笔记》（记忆钩子＋选型链路＋目录模板＋技巧清单），作为该项目的最终蒸馏物。
- **每批一个 commit**：一批验证通过即 commit（一批 = 一个可运行的最小实现增量），commit 历史 = 学习路径，不攒到阶段收尾一次提交。

## 关键提醒

- 参考项目是「被学习的对象」，不是「要被完全复制的成品」——**机制要读懂原理、能自己讲清、能独立实现**，才算学会。
- 面对分布式/生产级特性（熔断、幂等、日志、可观测、配置校验），重点学「它为什么需要、怎么权衡」，而非只搬代码。

## 新项目快速开始模板（开局三件套 + 复刻增量）

> 基础 AGENTS.md 一页模板（定位/目录结构/常用命令/硬性约定/Editing instructions，≤60 行）**见 `../references/AGENTS.md-模板.md`**（此处不重复）；通用工程约定（验证纪律/commit 规范/续接规范）见 `../references/通用工程约定.md`。下面只给**复刻场景增量**，拼接到基础模板之后；加上上文「先问在哪复刻」与第 0 步的完整性地图与阶段0清单，即构成开局三件套。

````markdown
### 增量A · 运行资源与答案卷错开（强约束）
数据库名 / bucket 名 / 端口号全部用自己的一套（如 `<project>` / `<project>-sources` / `<project>-assets>` / 错开端口号），compose 与 application.yaml 每一处同步——目的：同机对照运行互不干扰、不与答案卷撞名。命名规范与依赖版本管理等通用工程惯例按 `../references/通用工程约定.md` 执行，此处不重复。

### 增量B · 学习资料指针（喂 AI 的上下文，强制）
| 资料 | 路径 | 用法 |
|---|---|---|
| 答案卷（只读） | `<答案卷根目录>` | 对照源码 / 写完 diff |
| 教材地图 | `<XX-全链路开发详解.md>` | 每阶段开工先读对应章节再写码 |
| 完整性地图 | `NOTES/阶段对照-完整性地图.md` | 勾选唯一依据，★=重点/难点（逻辑较难多花时间讲透，非深度开关） |

> 给 AI 的标准指令模板：「读 AGENTS.md 和教材第 N 章，继续阶段 N」。

### 增量C · 学习进度表 + 会话规划
- 进度表：阶段 0～N 各自状态（⬜ 未开始 / 🔶 进行中+已完成+commit hash / ✅ 验收通过）。属状态数据，可放 AGENTS.md（豁免一页限制）或 NOTES，二选一定死。
- 新会话触发 = 切换大业务域 / 当前会话 token 过高 / 一个工作单元完成，三者任一。
- 续传靠持久化状态（AGENTS.md + git log + 完整性地图 + 答案卷），不靠会话记忆；磁盘当记忆（续接规范见 `../references/通用工程约定.md` §3）。
- 会话归档：全局总览 `NOTES/NOTES.md`，阶段详情 `NOTES/阶段N-主题.md`，**讲解全文 `NOTES/教学讲解/阶段N-<主题>（技术）/批次M-<主题>（核心类）.md`（讲完即写，带主题标注）**，面试题统一进 `NOTES/面试题.md`；`NOTES/` 不进 git。

### 参考式学习方法速查（供新会话遵循）
原则：参考而非照抄——骨架/配置从原项目直接复刻（工程惯例），机制/算法也从原项目复刻并讲透原理（那是要学的东西）。
1. 七要素交付：目标 / 该创建的文件(标注直接复刻) / 核心代码要点 / 设计权衡 / 新名词 / 知识卡片 / 面试题；done→next→explain 推进。
2. 工作单元 gate：边界对照 → 排雷分类 → 逐类详解(讲一个写一个) → diff 对照 → 每批立即构建验证并汇报（铁律见「证据先于断言」，`../references/通用工程约定.md` §1）→ 归档 + commit（规范见 `../references/通用工程约定.md` §2）。默认「继续X」= 学习会话必须走此流程；用户明说「只要出活」可免讲解，验证不可免。
3. 分阶段 + 分批：先按完整性地图分阶段；阶段里件多就分批，批次按「相关类聚合」分（一批 = 同一件事的件，3~9 件合理区间、不设死上限，宁多批不量产），多轮次依次实现；**每个文件都满深度讲**，不分机制/样板高下，差别只在份量。
````
