# 讲解达标样例（黄金样例）——每类讲解的达标形态参照

> **用法**：开始任何一类的六段讲解之前，先读本文档，用样例深度校准自己的输出——而不是对着六段字段清单打勾。内容换到任何机制（幂等/SSE/雪花/熔断…）都一样：**只换内容，格式与深度保持**。
> **六段对应**：①业务场景 → 小节一；②数据流/调用链 → 小节二；③实现（代码块逐行）→ 小节三；④用法 → 小节四；架构概念与实现四问的知识点分布在逐行注释与反例对比中。
> **深度定性（重要）**：本文档是**满深度的达标基准**。从这一版起，**每一类（不管机制还是 DTO/配置/常量这类零件）都按满深度讲**——六段完整、逐行注释、反例对比、触发回放，差别只在**份量**（机制行多、零件行少），**不降深度、不缩结构**。所以本文档的深度对**所有类都适用**，不只是"重要机制类"。节奏靠**分批**（每批 ≤3 类）控制，不靠降深度省时间。
> **语言无关（重要）**：本例用 Java/Spring（`GlobalExceptionHandler`）演示，教的是**深度/格式/阈值**，**不是内容**。讲到别的项目时，先读该项目源码判断其语言与框架，再按这里的**结构与阈值**（六段、≥8跳调用链带真实类名、整方法逐行+每手法反例、用法带触发回放、结尾读法提示）产出**该语言/框架**的内容——不要照搬 Java 术语（`注解`/`切面`/`TypeHandler` 等在 Python/TS 里对应装饰器/中间件/序列化器）。
> **非 Java 对照样例**：同套六段 + 同阈值的 Python/LangGraph（`NodeRrf`·RRF）演示，见 **`黄金样例-python.md`**（节二/三的判定表与自检表与本文件一致，只换语言不换尺度）。

## 一、达标样例：GlobalExceptionHandler（异常翻译官）——完整示范

### 业务场景（具体到人、事、时）

小明的公司用这套系统管制度文档。今天他在「上传」页选了 **200MB** 的 PDF 点上传（yaml 配置单文件上限 50MB）。他期望系统给他一句人话，而不是浏览器里出现一堆英文报错。

### 数据流 · 完整调用链实例（从一次真实点击一路到前端收到结果）

```text
① 小明网页点上传（200MB 文件）
② 浏览器发出 POST /api/storage/upload（POST=HTTP 动词"提交数据"；Content-Type: multipart/form-data 标明请求体是多段表单，④ 步会解析）
③ Tomcat（真正监听端口、收发 HTTP 报文的服务器，Java 世界叫它"Servlet 容器"）把 HTTP 报文交给 Spring 的 DispatcherServlet（Spring MVC 的总入口，所有请求都先到它）
④ DispatcherServlet 解析参数时调用 MultipartResolver 解析 multipart（多段表单）请求
⑤ 解析过程中 Tomcat 底层检查：单文件 200MB > spring.servlet.multipart.max-file-size(50MB)
   → Tomcat 抛 FileSizeLimitExceededException（"单个文件超限"的原生异常，在 org.apache.tomcat 包）
⑥ MultipartResolver 把它包装成 Spring 统一形态：MaxUploadSizeExceededException（spring-web 包）
   [包装链现形：MaxUploadSizeExceededException → cause IllegalStateException → cause FileSizeLimitExceededException]
⑦ 控制器方法还没开始执行异常已发生 → 异常抛回 DispatcherServlet
⑧ DispatcherServlet 把异常按顺序交给 HandlerExceptionResolver 链
   → 命中 ExceptionHandlerExceptionResolver（它专门收集所有 @RestControllerAdvice 类里的 @ExceptionHandler 方法；
     @RestControllerAdvice 读作"全局异常处理类"标签：贴在某个类上，声明"这个类里的方法负责翻译全项目的异常"）
⑨ 按异常类型匹配：MaxUploadSizeExceededException.class 精确命中 GHE.maxUploadSizeExceededException
   （GHE = GlobalExceptionHandler 的简称，下同）
⑩ 方法内判 cause 链（见下方代码逐行）→ 判定"单文件超限"分支
⑪ 拼出人话 message = "上传文件大小超过限制，单个文件最大允许 50MB"
⑫ return Results.failure(BaseErrorCode.CLIENT_ERROR.code(), message)
   → 一个 Result{code:"A000001", message:"...", data:null, requestId:null}（A=用户端问题）
⑬ DispatcherServlet 把返回值交给 Jackson 序列化 → HTTP 200，响应体就是那段 JSON
   （Jackson = Spring 自带的 JSON 库，负责 Java 对象 ↔ JSON 文本互转；"序列化"= 把内存里的对象转成能在线路上传的文本）
⑭ 小明前端拿到 {"code":"A000001","message":"单个文件最大允许 50MB",...}，
   按 code 首字母 A 判断"是我操作的问题"，把 message 原样弹窗给他看
```

**读法**：断在 ⑤~⑨ 中间任意一跳 = 你找到了还没懂的点（比如"MultipartResolver 是什么、包装链哪来的"），当场问。

### 实现 · 每个手法配代码逐行讲

**手法① cause 分叉（有根因记全栈 / 无根因截 5 帧），abstractException 方法完整代码逐行**：

```java
@ExceptionHandler(value = {AbstractException.class})             // 标签：这个异常类型交给本方法翻译
public Result<Void> abstractException(HttpServletRequest request, AbstractException ex) {
    // HttpServletRequest = 框架递进本方法的"这次 HTTP 请求"对象：里面装着请求方法、URL 等信息（下面打日志要用）
    if (ex.getCause() != null) {                                 // 【有根因】业务异常底下还包着真正的原始异常？
        log.error("[{}] {} [ex] {}", request.getMethod(),        //   是 → 日志打完整堆栈（含 ex 和它的 cause）。
                request.getRequestURL().toString(), ex, ex.getCause());   //   日志串里的 {} 是填空槽：日志框架把后面的参数按顺序填进各槽（免手工拼字符串）
        return Results.failure(ex);                              //   返回业务异常对应的 Result（码/消息在异常里带着）
    }
    StringBuilder stackTraceBuilder = new StringBuilder();       // 【无根因】业务直接 new 出来的（没有底层根因）
    stackTraceBuilder.append(ex.getClass().getName())            //   手工拼日志文本：先写"类名: 消息"
            .append(": ").append(ex.getErrorMessage()).append("\n");
    StackTraceElement[] stackTrace = ex.getStackTrace();         //   拿到堆栈帧数组（Java 每次异常都带）
    for (int i = 0; i < Math.min(5, stackTrace.length); i++) {   //   只取前 5 帧——
        //   为什么是 5：Business new 出来的异常 50 帧里，只有前几帧是"谁调用它"的真实链路，
        //   剩下的都是创建它的框架代码，全打 = 日志噪音（每个异常 50 行）
        stackTraceBuilder.append("\tat ").append(stackTrace[i]).append("\n");  // 按 Java 栈写法 \tat 逐帧拼
    }
    log.error("[{}] {} [ex] {} \n\n{}", request.getMethod(), request.getRequestURL().toString(), ex, stackTraceBuilder);
    return Results.failure(ex);                                  //   两种分支返回同一个 Result（外层表现不变）
}
```

**手法② cause 链判上传类型，maxUploadSizeExceededException 逐行**：

```java
@ExceptionHandler(value = MaxUploadSizeExceededException.class)  // 拦截 Spring 统一的上传超限异常
public Result<Void> maxUploadSizeExceededException(HttpServletRequest request, MaxUploadSizeExceededException ex) {
    log.warn("[{}] {} [upload] 文件上传大小超限: {}", request.getMethod(), getUrl(request), ex.getMessage());  // warn 级日志+[upload]标记；{} 填空槽同手法①
    String message;
    if (ex.getCause() instanceof IllegalStateException           // 第一判：第二层是不是 IllegalStateException？
            && ex.getCause().getCause() instanceof FileSizeLimitExceededException) {  // 第二判：第三层是不是 Tomcat 的"单文件超限"异常？
        message = "上传文件大小超过限制，单个文件最大允许 " + maxFileSize;    // 两层都中 → 单文件超限 → 提示配置的单文件限额
    } else {
        message = "上传请求大小超过限制，单次请求最大允许 " + maxRequestSize;  // 否则 → 整请求超限（多个小文件合计超 100MB）
    }
    // maxFileSize / maxRequestSize 是配置类字段，由 @Value 注入：启动时 Spring 自动把 application.yaml 里配的数值填进来
    // （"注入"= 框架替你把值塞进字段，不用自己读配置文件）——所以提示语永远和 yaml 配置同源，改配置即改提示
    return Results.failure(BaseErrorCode.CLIENT_ERROR.code(), message);  // A 类错误（用户端）+ 人话提示
}
```

### 用法 · 可照写的最小完整示例

业务侧（假设 rag 模块有个提问控制器，你照抄改改就能跑）：

```java
@RestController                                             // 标签：这个类负责接 HTTP 请求、返回 JSON 数据（REST 接口类）
@RequestMapping("/api/ragent/chat")                         // 标签：本类所有接口的 URL 前缀
public class ChatController {

    @PostMapping("/send")                                   // 标签：POST /api/ragent/chat/send 这个请求落到这个方法
    public Result<Void> send(@RequestParam @ChatQuestion String question) {   // @RequestParam=把请求参数 question 的值绑到这个形参上
        // 注意：@ChatQuestion 闸门已在参数解析时挡掉空/超长问题，到这儿的都过了校验
        if ("某某违禁词".equals(question)) {
            throw new ClientException("包含违禁词，请修改后重试");   // ★ 业务侧唯一动作：抛！ClientException=业务异常子类（GHE 会把它翻译成 A 类错误信封），别的都不用管
        }
        return Results.success();                                    // 成功侧：调工厂拿空信封
    }
}
```

小明在前端问了一句违禁词，发生了什么：

```text
ChatController.send → 判中违禁词 → throw new ClientException("包含违禁词，请修改后重试")
→ 异常传出控制器 → DispatcherServlet → HandlerExceptionResolver → GHE.abstractException（无 cause 分支：截 5 帧日志）
→ Results.failure(ex) → JSON: {"code":"A000001","message":"包含违禁词，请修改后重试","data":null,"requestId":null}
→ 前端 popup(message)
```

看完这个示例你会注意到一件事：**业务代码里从头到尾看不到 Result 的失败拼装——抛异常就完事，翻译 100% 是 GHE 的活。** 这比十句"业务只抛异常"都直观，这就是实例化标准的用意。

## 一·续、注释深度对照（真实踩例：用词悬空 vs 解释到底）

> 出处：一次真实实测——拦截器讲解里写了 `// ② 预检放行`，初学者读完仍不知道 OPTIONS 是什么、"预检"是啥流程。**只讲"为什么"不讲"这是什么" = 没注释；用术语解释术语 = 悬空。** 下面用同一处代码做正反对照。

**例①：OPTIONS 放行（跨域预检）**

```java
// ❌ 悬空注释（只答了"为什么"，没答"这是什么"——"预检""跨域""OPTIONS"三个词全是没讲过的词）
if ("OPTIONS".equalsIgnoreCase(request.getMethod())) {
    return; // 预检请求直接放行：浏览器跨域前先发 OPTIONS，不该被登录检查判死
}

// ✅ 解释到底（先讲这是什么、再讲为什么；每个词都落在已知地基）
if ("OPTIONS".equalsIgnoreCase(request.getMethod())) {
    // getMethod() = 读这次请求用的 HTTP 方法（HTTP 方法 = 请求的"动词"：GET=要数据、POST=交数据；
    // OPTIONS = 另一个动词，意思是"先问问你允不允许我发请求"，探测用、不带业务数据）
    return; // 浏览器在"跨域"场景（网页在 a 站、接口在 b 站）真正发请求前，会先自动发一个 OPTIONS 试探；
            // 这趟试探不带登录凭证，若不跳过登录检查，试探会被当成"未登录"拦掉 → 跨域直接失败
}
```

**例②：ASYNC 分发跳过**

```java
// ❌ 悬空注释（"异步派发"本身就是需要解释的词，等于用生词解释生词）
if (request.getDispatcherType() == DispatcherType.ASYNC) {
    return; // 异步派发放行
}

// ✅ 解释到底
// DispatcherType = Servlet 容器（Tomcat 这类"真正接请求的服务器"）给每次流进过滤器的请求打的"来路标签"：
// REQUEST=浏览器原始请求；FORWARD=服务器内部转发；ERROR=进错误页；ASYNC=一次异步任务的开始/收尾被容器重新路由进来
if (request.getDispatcherType() == DispatcherType.ASYNC) {
    return; // SSE 长连接结束时，容器会以 ASYNC 方式把请求"再送进来"走一遍收尾；那时登录上下文已丢，
            // 不跳过就会把正常收尾误判成"未登录"拦掉，流式响应没法正常结束
}
```

**判定规则**：解释里每个词，要么是生活语言/语言基础，要么前文已解释过；有一个悬空 = 没解释，继续拆。底层机制首次出现拆到底，同批内再出现可简写「见先修概念」。

## 二、每段详细度基准（对照自查，任一项不达标 = 该类未讲完）

| 段 | 达标判定（明文标准） | 不达标表现 |
|---|---|---|
| ①业务场景 | 有**具体的人 + 具体数值/配置值 + 期望结果** | 出现"用户/请求"但无名字无数值 = 抽象句 |
| ②调用链 | **≥8 跳**（上方示范 14 跳），每跳带真实类名/方法名/具体异常名与消息形态；结尾有**读法提示** | ≤5 跳 或 抽象链（"请求→Spring→前端"） |
| ③代码块 | **整方法**贴出 + **逐行中文注释**（每处答三问：这是什么/为什么/不用会怎样；解释无悬空词）；**这份注释就是真实源码文件里的注释**（写码时已写进文件，讲解照贴）；每个手法有**反例对比**（不这样做会怎样） | 贴片段 / **标注"节选"** / "见下方落码"指向 / 只讲手法名 / 注释只写"为什么"四个字带过 / 用术语解释术语 / 注释只存在于讲解消息、源码文件是裸的 |
| ④用法 | **完整可跑片段** + **触发回放**（输入 → JSON/返回 → 前端反应）+ **收尾洞察句** | 只有注释式一句 |
| 实现四问 | 思路/手法/数据流/边界四问缺一问即不合格；每问**完整教学句**，手法展开"是什么/为什么/不用会怎样" | 三问或两问带过 / **电报体名词串**（"手法：A+B"一行完事） |
