# 三本书与工程日志

## 第一册：项目源码与工程实现

说明项目是什么、服务谁、业务闭环怎样走、模块如何协作、每个范围内文件做什么，以及关键源码从入口到出口如何执行。主目录：`NOTES/教学讲解/第一册-项目源码与工程实现/`。

## 第二册：实验与机制验证

每个核心机制使用 `Prediction -> Evidence -> Experiment -> Correction`。实验不可运行时记录静态证据、阻塞命令和未验证边界。主目录：`NOTES/教学讲解/第二册-实验与机制验证/`。

## 第三册：架构挑战与独立重构

用户不照抄原项目，提出等价实现、替换存储/协议/框架、删除模块后的退化分析或新领域迁移，再和原项目比较取舍。主目录：`NOTES/教学讲解/第三册-架构挑战与独立重构/`。

## 独立工程日志

工程日志不写入被学习项目的知识教材目录。默认位置是项目同级 `.replicate-learning-log/<项目名>/`，也可由用户指定。每个任务至少有 Issue、Context、Review、Test/Debug、Delivery 五类记录，并链接回第一册涉及的代码和第二册的验证证据。

## 节奏：默认三书同步，单册优先是显式模式

三本书**默认随批同步推进**——这是常态，不是可选项。仅当用户明确说"先要第一册 / 只要第一册 / 先不管二三册"时才进入**单册优先模式**（2026-09-17 · 用户要求 3）：

- 被暂停的册是**欠账**，不是"没有"：状态文件写明"用户指令暂停：第X册（原话摘录）+ 预计何时补"；
- 能力账本为被暂停的册各记一条欠账条目；
- 每次收尾报告的缺口清单必须列出暂停中的册；
- 用户回到"继续"且状态允许时，先确认是否恢复同步；恢复后第一批动作 = 回补欠账。

框架不变，变的是节奏——暂停的理由与归还计划必须随时可从磁盘读到，不依赖聊天记忆。
