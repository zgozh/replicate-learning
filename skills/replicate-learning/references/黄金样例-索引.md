## 1. canonical 样例：是**规则**，不是写死某一份文件

**定义**：canonical 样例 = **在 FAIL 档下通过闸门（退出码 0）的真实批次文件**，且同时满足三条：

1. 第 16 节（教材质量自检）写明「判据版本：v<当前 GATE_VERSION>」——写明即进 FAIL 档，**享受不了存量豁免**（判据 2.19 的适用范围规则）；
2. ⓪b 三项齐备：第 1 节架构图（围栏内 ≥5 行连接符/箭头 + ≥3 个能在仓库里找到的真实标识符）、第 7.1 小节编号调用链（≥5 跳、每跳带行号）、第 8 节穿透卡（L0–L3 四级标签 + 「省略了什么生产边界」）；**判据 v2.25 起另须 ⓪d 形态四项齐**：② 流水线图、⑤ 双清单、⑥ 每件问题开场+要点表锚+★回放、⑭ 完整答案率 100%；
3. 批头写明真实源码依据（`源码依据：commit <sha>`），代码块由 `inject_source.py` 注入（行号不可手打）。

## 3. 盲区与已封堵项（随判据版本更新）

- **无 java 代码块就跳过结构判定** —— **已封堵（2.20）**：结构判定改看「是否教材类文件」（`is_lecture`：声明位豁免 / ≥5 行 java 块 / **教材标志投票 ≥3 项**）；合成无-java 样本已由「跳过」变为 **FAIL**。三份旧样例因首屏声明了「形态状态」而走**显式豁免**（不再是静默通过）。
- **记录类产物（整理批 / 进行中记录 / 草稿）既不按 17 节判、也不能没人管** —— **已立判据（2.21）**：改走记录类形态三项（R1 状态或日期 / R2 未完成与下一步清单 >=2 条 / R3 不冒充成品）；识别只认「文件名含整理批/进行中/草稿/WIP/记录/续传/日志」或「声明位写明记录类」（**不认裸的「进行中」**，否则阶段总览这类状态文档会被误判）；自声明判据版本 >= 2.21 才判 FAIL。
- **节选类参照物的第 0 组与第 5 组本就 FAIL**（血证 H10）：对样例跑闸门的意义是「确认闸门能跑、且不误伤参照物」，**不是**拿节选当全批达标线。

## 4. 机械动作（动笔前 / 收尾后）

```bash
# 动笔前：用骨架起步（骨架自带 17 节 + 第 7.5 小节 + 第 12 节八条与八段 + 判据版本落笔）
python scripts/new_batch.py --stage <N> --batch <M> --title "…" --classes "…" --sha <sha> --out <路径> --src <仓库根>
# 收尾：一条命令定生死（本批已声明判据版本 → 按 FAIL 档判）
python scripts/gate_lecture.py <本批.md> --src <仓库根>
# 参照物体检（新环境首次使用、或判据升级后各跑一次）
python scripts/gate_lecture.py references/十七节黄金样例-节选.md --src <任一真实仓库根>
```

## 5. 维护规则（防样板腐烂）

1. **canonical 样例随批次滚动**：新批一旦在 FAIL 档下 PASS 且规模/覆盖面更完整，就把 §1 的实例替换为它，旧实例降为"历史 canonical"（保留路径与闸门数字）。
2. **判据每升一版，参照物必须复检**：新增或收紧判据后，把 §2 的三份参照物各跑一次闸门，把"形态状态"字段更新为新版本号；**一旦发现参照物在教旧写法，立刻补"不可照抄"条目**——这正是 H26 的教训。
3. **样例不得作为达标线的替代**：唯一达标线始终是闸门 C 组七项判定值（血证 H10）；样例只提供"深度与形态"的参照。
