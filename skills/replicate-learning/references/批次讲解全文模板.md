## 批次文件 · 八块内容（齐全才算讲完）

### ① 先修概念
表格：`词 → 一句话大白话解释（大白话 + 一个生活化类比/例子）`。**类比是钩子、纯定义难记**——token=游乐园手环、Redis=键值仓库、HTTP 请求=一封信（信封+信纸）；**禁止只给「术语→术语定义」**（「AOP=在方法前后插逻辑的技术」是纯定义，要补上「好比给方法门口挂道门帘，进出前后自动登记」）。**扫描范围不只业务/框架词**，还包括底层平台与协议机制（HTTP 方法、CORS、Servlet 容器、线程池、序列化…）。判定法：凡"解释它时不得不再用另一个没讲过的词"的，全都要进这张表。

### ② 业务闭环定位
本批服务主链路（如 提问→理解→检索→生成→溯源）的哪一段 + 定位图 + 一句「删掉这批会怎样」。

### ③ 本批类清单表
表格：每个类一句「它是干嘛的」；★ 标重点难点（逻辑较难、要多花时间讲透，非深度开关——所有类都满深度）。

### ④ 全局调用链图
ASCII 图或流程图。先给空间感，再逐类展开。

### ⑤ 逐类六段全文（每类独立一节，禁止合并）
每个类一个小节，标题 `### 类 X/N：类名`（**N = 本批实际类数，随批动态填**——本批 8 个类就写 `类 1/8` … `类 8/8`；**禁止沿用上一批的分母**：批次2 是 6 类写 `/6`，批次3 有 8 类还写 `/6` 就是「类 8/6」这种错）。**六段各占一个独立小节**（`### ① 业务场景` … `### ⑥ 用法`），**禁止压成一行式密集文本**（`**① 业务场景**：…` 全挤一段读起来死板、掉"教学姿态"）；段内能用 ASCII 图/表格就别只用纯文字。各段要求：

- **① 业务场景**：**具象镜头**——有名字/身份的人 + 具体数值 + 期望结果（"小明上传 200MB"），**禁止抽象主体**（"审计行要标业务域"这种没有具体的人 = 不合格）。
- **② 架构位置**：上下游是谁、依赖方向、为什么放这一层。
- **③ 实现四问**：思路 / 手法 / 数据流 / 边界——**每问写完整教学句，禁电报体**（「手法：A+B」这种名词串不算讲，要展开「它是什么 / 为什么用它 / 不用会怎样」）。**手法每提一个框架/工具，必须补一句「它内部怎么做到的」（L1 机制层）**——只写「用 X 做 Y」是 API 清单，不是手法。
- **④ 代码逐行**：**整方法贴全**（不标"节选"），照源码里的三问注释讲。**每个陌生 API 的三问注释，「①这是什么」要答到机制层**（「它内部靠 X 做到的」），不只是「它是干嘛的」——否则读下来只记住一堆调用姿势。
- **⑤ 调用链 ≥8 跳**：每跳带具体类名/方法名，读者能顺着跑一遍。
- **⑥ 用法 + 触发回放**：可照写的示例（发什么请求、返回什么、什么场景触发、会走到哪一步）。**末尾给「No-Framework 最小手写版」**——不用这个框架/工具你怎么写 20~40 行等价实现（★ 类与核心依赖必给，其余至少一句「手写要做哪几步」）。

### ⑥ 验收（题后紧跟标准答案）
- **脱手复述测试（每类必做，题数 = 本批类数，动态不固定）**：**本批几个类就出几道复述题**（8 类 = 8 题，不截成固定 3 题），每题紧跟标准答案（一问一答，按业务/架构/代码三层组织）。
- **三层出题（每层题数随批动态，不固定"各一题"）**：按业务/架构/代码三层分别出题，**每层出几题 = 该批该层的实际知识点与难点数**——一批有 2 个 ★ 机制难点，代码层可能出 3~4 题、业务层 1~2 题；**每层至少 1 题**、题数随本批类量与难度增减，**每题紧跟标准答案**（不是事后打分）。

### ⑦ 构建验证证据
测试数、通过数、`BUILD SUCCESS`、耗时。**证据先于断言**，未跑不得宣称完成。

### ⑧ 溯源与答案卷 diff 结论
答案卷对应路径、机制是否逐行对齐、差异在哪（包名/命名/自研增量分别说明）。
