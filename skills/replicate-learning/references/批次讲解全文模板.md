# 《批次讲解全文》模板（教学讲解 · 一个批次一个文件）

> **位置**：`<项目根>/NOTES/教学讲解/阶段N-<主题>（<本阶段关键技术>）/批次M-<一句话主题>（<本批核心类>）.md`
> **例**：`NOTES/教学讲解/阶段4-system支撑域（Sa-Token认证+审计变更日志）/批次2-Auth登录登出（AuthServiceImpl★+LoginVO）.md`
> **原则**：**这是完整讲解的全文，不是提取物**——聊天窗口会随会话变长被压缩折叠，只有磁盘上这份能长期回看。**一批讲完立即写，不攒到阶段结束。**
> **规范出处**：`../SKILL.md` 步骤 6️⃣、`../docs/复刻式学习方法-通用.md`「会话归档」节。

| 层级 | 命名格式 | 例 |
|---|---|---|
| 阶段目录 | `阶段N-<主题>（<本阶段关键技术 2~3 个>）` | `阶段4-system支撑域（Sa-Token认证+审计变更日志）` |

**命名约束**：总长 ≤40 字；**禁用 Windows 非法字符** `\ / : * ? " < > |`（多个类名用 `+` 连接，别用 `/`）；**括号里"跟什么有关"的标注是强制的**——日后扫一眼目录就知道每批讲了什么，不必逐个点开。

## 批次文件 · 八块内容（齐全才算讲完）

### ① 先修概念
表格：`词 → 一句话大白话解释`。**扫描范围不只业务/框架词**，还包括底层平台与协议机制（HTTP 方法、CORS、Servlet 容器、线程池、序列化…）。判定法：凡"解释它时不得不再用另一个没讲过的词"的，全都要进这张表。

### ② 业务闭环定位
本批服务主链路（如 提问→理解→检索→生成→溯源）的哪一段 + 定位图 + 一句「删掉这批会怎样」。

### ③ 本批类清单表
表格：每个类一句「它是干嘛的」；★ 标重点难点（逻辑较难、要多花时间讲透，非深度开关——所有类都满深度）。

### ④ 全局调用链图
ASCII 图或流程图。先给空间感，再逐类展开。

### ⑤ 逐类六段全文（每类独立一节，禁止合并）
每个类一个小节，标题 `### 类 X/N：类名`，六段各占一小段：

- **① 业务场景**：具体的人 + 具体的数值，解决什么问题。
- **② 架构位置**：上下游是谁、依赖方向、为什么放这一层。
- **③ 实现四问**：思路 / 手法 / 数据流 / 边界——**每问写完整教学句，禁电报体**（「手法：A+B」这种名词串不算讲，要展开「它是什么 / 为什么用它 / 不用会怎样」）。
- **④ 代码逐行**：**整方法贴全**（不标"节选"），照源码里的三问注释讲。
- **⑤ 调用链 ≥8 跳**：每跳带具体类名/方法名，读者能顺着跑一遍。
- **⑥ 用法 + 触发回放**：可照写的示例（发什么请求、返回什么、什么场景触发、会走到哪一步）。

### ⑥ 验收（题后紧跟标准答案）
- **脱手复述测试（每类必做）**：复述题 + 每题的标准答案（一问一答，按业务/架构/代码三层组织）。
- **三层三题**：业务一题 + 架构一题 + 代码一题，**每题紧跟标准答案**（不是事后打分）。

### ⑦ 构建验证证据
测试数、通过数、`BUILD SUCCESS`、耗时。**证据先于断言**，未跑不得宣称完成。

### ⑧ 溯源与答案卷 diff 结论
答案卷对应路径、机制是否逐行对齐、差异在哪（包名/命名/自研增量分别说明）。
