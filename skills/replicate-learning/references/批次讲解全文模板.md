# 《批次讲解全文》模板（教学讲解 · 一个批次一个文件 · 读者教材 · §6.4 可执行版）

> **位置**：`<项目根>/NOTES/教学讲解/阶段N-<主题>（<本阶段关键技术>）/批次M-<一句话主题>（<本批核心类>）.md`
> **例**：`NOTES/教学讲解/阶段4-system支撑域（Sa-Token认证+审计变更日志）/批次2-Auth登录登出（AuthServiceImpl★+LoginVO）.md`
> **原则**：**这是读者教材的完整讲解全文，不是提取物**——聊天窗口会随会话变长被压缩折叠，只有磁盘上这份能长期回看。**一批讲完立即写，不攒到阶段结束。**
> **阅读者模型**：读者不手写、不交作业、不复述卡关。本文件要把一切"练才学得会"的内容**以读代练**讲进去；文末核对问答供读者自行对照（答案已给，纯阅读）。
> **规范出处**：`../SKILL.md` §6.4（17 节统一化规范——**本模板是 §6.4 的可执行版本，生成批次时由 `scripts/new_batch.py` 抽骨架后填空格，不自由发挥**）、§6.1.2（批次源码快照与「不符」三分类）、`../docs/复刻式学习方法-通用.md`（讲解标准总则 + 工程视角 + 穿透 L0~L4）。

**批头固定行（必写，缺了闸门无法区分「源码演进」与「编造」——SKILL §6.1.2 铁律 1）**：

```markdown
> 阶段__N__（__阶段主题__）· 批次__M__（__阶段定位，如"阶段收官批"__）。源码依据：commit `__sha__`「__提交标题__」；__文件数__ 文件 +__行数__ 行；自写 __N__ 例新增（其中 __M__ 例为真实 __中间件__ 集成），__阶段名__ 收官时 __模块__ __X__/__X__ 全绿。
> 证据等级约定：`【事实-源码】`（可回链行号）/`【实测】`（单测在案）/`【事实-历史】`（git commit 或 mvn 输出）/`【外部事实】`（框架/规范源码）/`【推断】`（无实证的时序分析）。
> 简化说明（刻意剥离）：__剥离了什么、分别归还哪个阶段__。
```

## 批次文件 · 17 节骨架（§6.4 可执行模板，生成时按空格填）

> **执行纪律**：每节"必含"项必须出现；"可选"项按本批内容复杂度自取；所有 `__` 空位必须替换为本批实际内容。§6.4 各节"反例"是警示清单——写本节时对照避免。
> **节标题形态铁律（2.15 / 血证 H25）**：17 个一级节标题必须是 `## ①`…`## ⑯` + `## 索引` 的规范形态（`##` 后恰好一个空格 + 带圈数字）。**带圈数字丢失**（⑨⑩⑫⑮⑯ 等在某些落盘链路会静默丢码）或多余空格会让闸门的节定位正则静默失效——那一节的全部检查被跳过却照样打印 PASS。所以"找不到段"一律报 FAIL 并打印实际标题原文。
> **判据适用范围（2.19）**：本批在本节头部写明「判据版本：vX.Y」——写了就进 ⓪b 三项（① 架构图 / ⑦.1 编号链 / ⑧ 省略段）的 **FAIL 档**；不写则它们只是报告档。新批由 `new_batch.py` 落笔即写，所以**新批一律从严**。

> **教材判定（2.20）**：本文件会被判为「教材类文件」，因此结构判定（17 节 / 围栏配对 / 占位符 / 第 12 节八条与八段 / 自指 / 回链 / 节标题规范形态）**必须全部通过**——即使你把所有代码块换成非 java 语言（也不要删掉骨架）：教材标志投票 >=3 项就会被认出来。

> **记录类形态（2.21）**：整理批 / 进行中记录 / 草稿**不要套用本模板**（它们不是 17 节教材），但必须自证状态：首屏写「状态：进行中/已完成/阻塞」或日期，正文给「未完成 / 下一步」清单（>=2 条）；带成品批迹（⓪带圈节标题 >=3 且含 6.x 小节）时，状态行必须写明未完成或草稿。
> **落盘前**：`__` 之类的**占位符必须清零**（闸门 ⓪ 会查代码块内残留）；教材自指话语（本批/本阶段/教材第/答案卷/阶段N/批次N）必须为 0，改写为**工程坐标**（"解析层已有的 X"而非"批次1 的 X"）；⑫ 末尾必须有 ≥1 条**提问回链**（形如 `- 「…」→ 见第 N 条`）。

```
按依赖顺序拆成可独立编译、可独立验证的小批次，用表格给：步序 / 新增或修改什么 / 这一步的可验证形态。
约束：每步 ≤3 个类；每步结束必须能编译；测试跟着每一步走、不要攒到最后；
最后一步是"总装 + 全量测试 + 产物报告"；另列出"不应触碰的边界"，每条点名文件或依赖。不要写实现代码。
```

**③ 现场会怎样**：__它会压成 3~4 步（太粗）/ 会把测试堆到最后 / 边界清单写成空话__ —— 各写一句你该怎么追问。

| 步 | 新增 / 修改 | 可验证形态 |
|---|---|---|
| ① | __…__ | __编译过 / 哪条测试绿 / 产物出现什么__ |
| ② | __…__ | __…__ |
| …（≥6 行） | | |

#### 5. 可直接使用的提示词（`AI 协作过程`）

**① 为什么不能只写"一个大提示词"**（失败机理，≥3 条）：__上下文不够 / 没有中间验证点 / 偏差复合 / 无法定位哪一步错__

**② 投喂策略**（代码怎么给 AI）
| 对象 | 怎么给 | 为什么 |
|---|---|---|
| 要改的文件 | 整份贴 | 改文件必须看到全文 |
| 要调用的类 | 只贴签名 + javadoc | 挤占上下文，且诱导照抄 |
| 不确定的 API | 让 AI 贴它读到的原文 | 唯一能防它凭记忆编造的手段 |

**③ 轮次序列**（≥3 轮；每轮四件套）
- **轮 0 · 上下文轮**：你发的原文 `__整段可复制__` ｜ 期望形态 `__复述 + 假设清单 + 追问__` ｜ 偏差信号 `__直接写码 / 术语没吃进去__` ｜ 本轮验收 `__它列出的假设里有没有你没想过的__`
- **轮 1 · 契约轮**：只给签名与 javadoc，编译过再填实现 ｜ __…__
- **轮 2 · 样例轮**：给真实输入片段 + 期望输出，**先让它干跑一遍，不写码** ｜ __…__
- **轮 3~N · 逐类实现轮** / **轮 N+1 · 测试与产物轮** / **轮 N+2 · 红灯回灌轮**（贴回 surefire 摘要 + "先给诊断，我确认后再改"）

**④ 可复用的完整骨架**（段名写 `【任务】` 或 `任务：` 都认）

| 段 | 这一轮要写成什么 |
|---|---|
| 任务 | __一句话说清要做什么__ |
| 依赖 | __允许用的已有组件（全限定名，要求它从源码确认后再引用）__ |
| 要新增的类 | __逐个列类名 + 一句话职责 + 交付批次__ |
| 核心约束 | __用"X 失败 → 回退 Y"的因果句式，不是"要兜底"__ |
| 注释要求 | __逐行三问；禁止用术语解释术语；算法分段注释__ |
| 验收标准 | __具体命令 + 期望例数 + 可断言的产物判据__ |
| 禁止 | __不该动的文件 / 不该引的依赖 / 不该越界的范围（每条都有理由）__ |
| 输出格式 | __每次只给本轮的 1~3 个类；先复述理解并停下等确认；每轮附验收命令与预期结果__ |

（生成的骨架会把上面 8 个标签按顺序补进本节，直接往下填内容即可。）

**⑤ 设计要点（为什么这么写，≥5 条）**：__逐条解释上表每段的作用与踩坑教训——目标是让读者学会写提示词，而不是抄走一个__
