# 《批次讲解全文》模板（教学讲解 · 一个批次一个文件 · 读者教材）

> **位置**：`<项目根>/NOTES/教学讲解/阶段N-<主题>（<本阶段关键技术>）/批次M-<一句话主题>（<本批核心类>）.md`
> **例**：`NOTES/教学讲解/阶段4-system支撑域（Sa-Token认证+审计变更日志）/批次2-Auth登录登出（AuthServiceImpl★+LoginVO）.md`
> **原则**：**这是读者教材的完整讲解全文，不是提取物**——聊天窗口会随会话变长被压缩折叠，只有磁盘上这份能长期回看。**一批讲完立即写，不攒到阶段结束。**
> **阅读者模型**：读者不手写、不交作业、不复述卡关。本文件要把一切"练才学得会"的内容**以读代练**讲进去；文末核对问答供读者自行对照（答案已给，纯阅读）。
> **规范出处**：`../SKILL.md`（标准讲解循环）、`../docs/复刻式学习方法-通用.md`（讲解标准总则 + 工程视角 + 穿透 L0~L4）。

| 层级 | 命名格式 | 例 |
|---|---|---|
| 阶段目录 | `阶段N-<主题>（<本阶段关键技术 2~3 个>）` | `阶段4-system支撑域（Sa-Token认证+审计变更日志）` |

| 阶段索引 | `00-阶段总览.md`（固定名，排最前） | — |

**命名约束**：总长 ≤40 字；**禁 Windows 非法字符** `\ / : * ? " < > |`（多类名用 `+` 连接，别用 `/`）；**括号里"跟什么有关"的标注是强制的**——日后扫目录即知每批讲了什么。

## 批次文件 · 内容块（块齐全才算一份完整教材）

### ① 本批地图（空间感）
本批在主链路（如 提问→理解→检索→生成→溯源）的哪一段 + 挂回系统全景地图哪一块 + 件与件关系图（ASCII）+ 一句「删掉这批会怎样」。

### ② 先修概念（只讲本批新词）
表格：`词 → 一句话大白话（大白话 + 生活化类比/例子）`。类比是记忆钩子、纯定义难记——token=游乐园手环、Redis=键值仓库、HTTP 请求=信封+信纸、AOP=门帘。**只讲新词**；已收录词引用「见概念词典 §X」，不重复展开。扫描范围不只业务/框架词，**含底层平台与协议词**（HTTP 方法、CORS 预检、Servlet 容器/过滤器链、DispatcherType、线程池、序列化…）。判定法：凡"解释它时不得不再用一个没讲过的词"的，都进表并同步回填概念词典。

### ③ 业务闭环定位
本批服务哪个业务动作 + 定位图 + 本批贯穿人物（运营小李/审计老王…，从定位到每件场景都用 TA，像连续剧）。

### ④ 本批类清单表
表格：每件（类 + 建表脚本 + 配置文件都算）一句「它是干嘛的」；★ 标重点/难点（逻辑较难、要多花时间讲透——非深度开关，所有件都满深度）。**件数 = 本批实际件数，随批动态**（8 件列 8 行，别抄上批）。

### ⑤ 逐件详解全文（1 件 1 节，禁止合并）
每件一个小节 `### 件 X/N：类名`（N = 本批实际件数，随批动态，禁止沿用上批分母）。每件的讲解结构（各占独立小节，禁压成一行式密集文本）：

- **① 业务场景**：具象镜头——有名字/身份的人 + 具体数值 + 期望结果（"运营小李传 200MB 知识库，希望 5 分钟可检索"），禁抽象主体（"用户/请求/系统"无人名无数值 = 不合格）。
- **② 架构位置**：先白话架构术语，再讲放哪层、上下游、依赖方向、为什么在这 + 挂回系统全景地图。
- **③ 实现四问 = 开发四问**（完整教学句，禁电报体）：①思路（解决什么 + 分几步 + 为什么这么拆）②设计决策（为什么这么设计？备选？为什么选这个？代价？给方案对比）③手法（每个手法 = 是什么 → L0/L1 内部怎么做到 → L2 手写示范 → L3 不用会怎样，穿透融进这里）④数据流与边界（数据怎么流转 + 异常/并发/降级/边界在哪，每条分支补"为什么存在"）。
- **④ 代码逐行**：整方法贴全（标"节选" = 不达标），照源码三问注释逐行讲；每个陌生 API 的「这是什么」答到机制层。讲解贴的代码 = 复刻源码文件里那份（AI 复刻时已带逐行中文注释）。
- **⑤ 调用链 ≥8 跳**：每跳带真实类名/方法名 + 一句大白话，结尾给读法提示（"断在第 N~M 跳 = 还没懂的点"）。
- **⑥ 用法 + 触发回放**：可照跑的请求/输入 → 逐段流转 → 返回长什么样。**末尾给 No-Framework 手写示范**（★ 类必给整段等价手写、其余至少"手写要做哪几步"）——**阅读材料，标注"读者阅读即可，不必自己写"**。
- **⑦ 工程视角（按值得配给 1~2 个，不是每件都全）**：
  - **直觉对照**：新手/照抄者本能会怎么写、会漏什么、为什么翻车 → 答案卷为什么这么设计；
  - **故障情景**：具体故障 → 现象 → 排查路径（从哪行日志看起 → 缩小范围 → 定位到哪个类哪行），配 L4 真跑证据（AI 替读者真跑，贴真实报错/日志/数据行）；
  - **测试视角**：该测哪几条分支、造什么输入、断言什么、典型坑（如 mock 时 `excludePathPatterns(String...)` 与 `List<String>` 重载歧义）；
  - **演进视角**：AI 跑 `git log -p / blame`，讲这件的设计被哪些 bug/需求改过；
  - **横向对照**：同机制别的成熟项目怎么做、差异与原因。

> **配给原则**：六段每件必走、件件满深度；工程视角按"值得讲"选 1~2 个（机制件多给；零件件常只给直觉对照/测试视角之一，甚至不给）。**禁止全部件都塞满全部小节**（堆料不是讲解）。

### ⑥ 核对问答（纯阅读，无提交无卡关；题后紧跟标准答案）
一问一答，**按业务/架构/代码三层分别出**：每层题数 = 该批该层的知识点与难点数（每层至少 1 题，随批动态，禁死板"各一题"），每题紧跟标准答案（不是事后打分）。读者看完答案自己对，答不上/含糊的点 = 回去重读对应段或直接问 AI。**不需要交任何东西、不卡进度。** 想检验"真懂没"，读者可自行合上文件在心里复述（可选动作，非流程要求）。

### ⑦ 构建验证证据
AI 每批跑构建/测试，贴命令 + 关键输出（测试数/通过数/BUILD SUCCESS/耗时）。**证据先于断言**，未跑不得宣称完成。

### ⑧ 溯源与答案卷 diff 结论
答案卷对应路径、机制是否逐行对齐、差异在哪（包名/命名/自研增量分别说明）。

## 每批讲完的三个"立即"（防止断档）

1. **立即写本批文件**（本模板）+ 更新 `00-阶段总览.md` 索引——禁止攒到阶段结束；
2. **立即回填** `NOTES/概念词典.md`（本批新词）+ 修正/回填 `NOTES/00-系统全景地图.md`；
3. **立即勾完整性地图** + 更新 `NOTES/阶段N-主题.md`（状态与索引，全文链接本文件）+ 更新 AGENTS.md「当前进度+下一步」→ commit（一批一个 commit，最小可运行增量）。
