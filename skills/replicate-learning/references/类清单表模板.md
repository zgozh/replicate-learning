# 《类清单表》模板（每阶段开工 gate 第一步）

> 用途：开讲某一阶段/批次前，先把本批**每个该复刻的文件**列全（类 + 建表脚本 + 配置文件）+ 每个写一句「是什么 / 它干嘛的」，让读者先看到全局，再逐件**满深度**讲解（不分档、不降深度）。
> 出处：`../SKILL.md`「分批」/ `../docs/复刻式学习方法-通用.md`（讲解标准总则）。

## 规则

- **每个文件都满深度讲**：不分「机制 / 样板」高下，不管是一个复杂状态机还是一个 3 行的 DTO、一段建表 SQL，都完整走一遍、讲到读者能看懂每一行为止。**不只 .java——建表脚本（建了什么表/每列动机/索引为什么这样建）、配置（每个旋钮字段语义/怎么被注入）都要入表、都要讲**；答案卷里该复刻的文件不许漏讲。
- **差别只在份量，不在深度**：机制件行多、零件件行少，但「它为什么存在 / 数据从哪来 / 被谁用 / 为什么这样设计」每件都要讲透。零件件用紧凑讲解（见 `零件类讲解模板.md`），深度不减。
- **★ 只是「重点/难点」提示**：标 ★ 的件逻辑较难、要多花时间讲透，**不是「讲深、别的讲浅」的开关**——所有件同样满深度。
- **初心者视角 + 词典**：每件那句「它干嘛的」用大白话写，不甩术语；件里出现的新词回填概念词典。
- **批次 = 相关类聚合**：一批装「同一件事」的件（3~9 件合理区间），数量不设死上限；一批装不下十几/几十个件就按主题切多批，宁多批不量产。
- **阅读者模型**：本表用于"看清本批范围"，**不是读者作业清单**——读者只读讲解，无动手提交环节。
