# 《零件类讲解》模板（DTO / 枚举 / 配置 / 常量 / 建表 SQL · 紧凑满深度）

> **用途**：零件件（结构简单、提供契约或数据的件）不写散文六段，改用**紧凑结构化**讲解——深度不减（每件仍答全"为什么存在/数据从哪来/被谁用/为什么这么设计"），篇幅省一半以上，还好复习。
> **判定"哪些件用本模板"**：DTO / 枚举 / 配置类 / 常量类 / 简单的建表脚本。一旦这个件有分支逻辑、防御逻辑、状态流转，回到机制件的六段模板（`批次讲解全文模板.md` 的"每件讲解结构"）。
> **红线**：零件件 ≠ 说明书。每处都要有**具体的人在用 + 方案对比 + 反例**（"同事把 'bailian' 拼成 'BaiLian'，equals 失配静默跳别家"），不许滑成"它存了这几家 id"的字典口吻。
> 出处：`../SKILL.md`（满深度不分级）、`../docs/复刻式学习方法-通用.md`（零件件紧凑讲解）。

## 结构（八项，项项答全）

```markdown
### 件 3/8：UserRole（枚举）
- **为什么存在**：……（一句话职责；删掉它，哪里会出问题）
- **每个值的语义**：ADMIN=…… / USER=……（逐个白话）
- **数据从哪来**：DB 哪个字段 → 谁转换 → 谁塞进来（链式写清，指到类+方法）
- **被谁读走**：谁判断它、判断后做什么（指到具体类+方法；可以画一句调用）
- **为什么用枚举而不用 String/int**：方案对比 + 取舍（枚举=编译期就锁死合法值，拼错直接编译错；String 拼错是运行期静默错）
- **会咬人的地方（反例镜头）**：某同事把 "ADMIN" 写成 "Admin" → equals 失配 → 走错分支 → …（具体到人和故障，不许形容词）
- **L0/L1 机制**：它在 JVM/框架里到底是什么（如枚举本质是 final class + 静态实例，switch 枚举为何不用判 null）——拆到底
- **手写示范 / 阅读提示**：不用枚举怎么写（≤15 行等价，如常量类 + 校验），**阅读即可不必自己写**
```

## 建表 SQL / 配置文件的零件变体

- **建表脚本**：改为——建了什么表（业务上装什么）/ 每列语义与动机 / 主键与索引为什么这样建（对照真实查询路径）/ 外键为什么不用 / 这表被谁读写。落一条"删掉这列/这张表会怎样"。
- **配置文件（yaml/properties）**：改为——每个旋钮字段语义 / 值从哪来（默认值?环境变量?）/ 怎么被注入（哪个 @ConfigurationProperties/@Value 收走，指到类）/ 改错会怎样（具体故障）。凡有嵌套/绑定的配置，机制穿透照 L0~L4 做（见 `黄金样例.md` 例⑥ @ConfigurationProperties）。
