# V2 执行协议

## 1. 启动与续传

先确定三个路径：被学习项目根目录、项目知识目录 `NOTES/`、独立工程日志目录。检查 `AGENTS.md`、README、现有状态、覆盖矩阵、总索引、Git 状态、构建入口和测试入口。若已有状态，按状态中的“下一步入口”继续；不要凭聊天记忆重排进度。

首次运行至少写入四份地图：系统全景、文件覆盖矩阵、概念词典、阶段对照完整性地图。默认只建立第一册总索引和状态快照；用户显式请求的扩展册才另建索引。扫描可使用 `rg --files`、目录统计、依赖清单和 Git 历史，但不要一次性读取全仓库源码。

**版本库可见性检查（2026-09-17）**：教材默认就地写入目标项目 `NOTES/`。开工时看一眼 `.gitignore`：若 `NOTES/` 会被忽略或用户不希望教材进库，给出两个选项——(a) 加 `!NOTES/` 例外（默认推荐，教材随项目走）；(b) 项目外隔离副本（仅"答案卷隔离"或目标项目零 diff 场景）。结论写进状态文件；项目没有 git 则跳过。

## 2. 阶段顺序

| 阶段 | 目标 | 退出证据 |
|---|---|---|
| A | 项目考古 | 四份基础地图 |
| B | 业务建模 | 角色、闭环、状态、异常、约束 |
| C | 架构/运行时建模 | 依赖、请求、异步、数据、部署图 |
| D | 第一册教材化 | 文件覆盖链接、批次正文、源码证据 |
| E | 第二册验证 | Prediction、Evidence、Experiment、复盘 |
| F | 第三册挑战 | Architecture Challenge、重构、迁移 |
| G | AI 工程交付 | Issue 八步、Review、Test、Accept、日志 |

阶段可在一个批次内交叉推进，但不能跳过证据和状态落盘。

**册范围**：默认只推进 D（第一册）；E（第二册）与 F（第三册）只有用户显式请求对应册时才进入执行范围。没有请求的册状态是 `not_requested`，不算暂停或欠账，也不在“继续”时询问恢复。用户明确要求三册同步且未撤销时保留该项目的已确认范围。第一册内部的源码核验、机制穿透和AI协作教学仍照常执行。

## 3. 证据协议

每个重要结论标注一种证据：`事实-源码`、`事实-实测`、`事实-历史`、`外部事实`、`推断`。源码块必须通过既有注入工具生成；行号不得手写。不能运行时写明命令、错误原文、已排查范围和“未实测”，不能写成“已验证”。

## 4. Vibe Coding 八步

1. `Understand`：说明角色、问题、当前行为、期望行为、范围和验收。
2. `Investigate`：只读调查入口、调用链、依赖、测试和风险。
3. `Predict`：用户先预测改动文件、不改文件、回归和最大风险。
4. `Plan`：列不变量、兼容性、边界、异常和验证命令。
5. `Delegate`：用 Context Pack 把 Issue、证据、约束和禁止事项交给 AI。
6. `Review`：检查 diff 范围、接口、状态、事务、权限、并发、重试和测试真实性。
7. `Test`：按风险执行构建、静态检查、单测、集成、故障和回归验证。
8. `Accept`：用户选择四种最终状态之一并记录证据；AI 不能代替用户接受。

## 5. 交互边界

默认不要求用户手写核心生产代码。只在业务判断、关键预测、架构挑战、diff 审查和最终验收处请求用户参与；普通样板、检索、实验脚本和修复迭代由 AI 完成。路径、权限、安全边界和不可逆操作无法推断时才强制提问。

## 6. 失败与降级

任何阶段失败都先落盘：已完成内容、失败命令、关键错误、推断、风险和下一步。缺依赖时保留静态分析；缺运行环境时降到 L0-L3；不得删除文件、减少覆盖范围或虚报完成。
