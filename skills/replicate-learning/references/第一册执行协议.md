# 第一册执行协议

默认只生成第一册。本文管普通“开始、继续、讲下一批”的动作；第二、三册的单独请求见 `V2执行协议.md`。先读本文件，再按当前节查 `第一册质量细则.md` §6.4 与短检查表。

## 首次与续传

首次识别项目根、`NOTES/`、源码语言、`AGENTS.md`、README、构建/测试入口及全部纳入范围文件，建立系统全景、覆盖矩阵、概念词典、阶段完整性地图与总索引。Java与Python都需查生产源码、测试、配置、脚本和部署文件；第三方、生成与二进制文件有排除理由。

续传只读状态、矩阵、最近批次、源码差异和必要的旧结论。若旧状态写“第一册优先、二三册暂停”，解释为`books=[1]`，不再追问恢复或持续记欠账。已有明确三册指令则保留。

## 开批

0. 起一块秒表：`python scripts/batch_trace.py --file <本批目录>/trace.jsonl start --batch-id <本批号>`；
   之后每个阶段 `begin/end --phase prepare|investigate|write|inject|repair|gate|verify|publish`，
   收尾 `report`。脚本采集不到的（模型写作）由人记并写明口径，**没测就写"未实测"**。
1. 定一个真实业务/机制闭环，记录主讲文件与只回链文件；同一文件只有一份主讲，新增视角可另写并回链。
2. 固定源码依据：commit加工作树差异；源码有未提交变化时记录每文件hash，不将工作树内容冒称该commit内容。
3. 批量读取全部主讲文件、关键调用方和相关测试；对跨模块测试也搜索。`callsite.py`的“仅提及”不能写成调用现场。
4. 生成manifest：`python scripts/batch_manifest.py prepare --src <项目根> --file <相对路径> [--file <相对路径> ...] --out <本批manifest.json>`。该工具按字节记录Java/Python等文件hash，日后用`check --src <项目根> --manifest <文件>`查变化。它只查列入的文件，不代表全仓未变化。
5. 以当前最终判据版本运行 `new_batch.py` 生成17节骨架（`--out` 是终稿、`--skeleton` 是骨架，**两个不同文件**）；本批不在成稿后才提高判据版本。第⑤节的计划可以在工作文件里维护，正文仍按当前质量契约展示。
6. **写注释计划 → 先预检，再注入**：`python scripts/batch_preflight.py --src <项目根> --plan <计划.json> --manifest <清单.json> [--lecture <批次.md>]`。清单要**一次 `prepare` 出本批全部文件**（`batch_manifest.py prepare` 拒绝覆盖已有清单）；真逐文件生成多份就**全部 `--manifest` 传进来**——预检要求清单覆盖注释计划里的全部源文件，缺件直接 FAIL（2.30 起）。
   它用**闸门自己的函数**（`check_density`/`check_sig`/`check_reverse`）算一遍，直接报出「★ 签名缺口几处、
   哪几个块有多少行无注释连段、可从哪些源文件行补注」，并检查注释键是否为真实行号、是否落在
   Python 多行字符串/反斜杠续行这类**注了也不生效**的位置。预检 FAIL 就先改计划——不要靠"注入后跑闸门"试错。

## 写作与组装

读者一开始要知道问题、输入、输出、调用顺序和失败时怎样。对第一册的每件写够可独立阅读的说明；旧概念在本批用一两句回忆并回链原主讲，新增行为则再次深入。Java/Python不分“高/低”档，注入器按语言选择注释前缀；不支持行内注释的语法使用块外解释，不改变源代码语义。

让 `inject_source.py` 读取源文件并带真实行号，教学注释放在注释计划；模型写段前白话、要点表、逐步回放、边界与取舍，不在对话里重新打整份源码。稳定分片先写工作目录，随后运行 `python scripts/batch_build.py --batch <batch.json>` **重建终稿**——它按「骨架 + `parts/*.md` + `annotations.json`」重组并注入，改了分片或注释就重跑一次；`--check` 比对磁盘终稿是否与重建结果一致（⑯ 的机器盖章块与判据版本行由 `sync_gate_result.py` 写入，已排除在比对之外），`--dry-run` 只报告会改什么（失败一律不写盘）。**构建前的 fail-closed 护栏（2.30 起）**：`skeleton` 与 `out` 同路径、`annotations` 指回 `plan_source`、分片目录为空、某一节仍是模板占位原文（缺分片）——四种都直接拒绝，不让"旧正文冒充重建结果"。单独组装某一节仍可用 `python scripts/assemble_batch.py --base <骨架.md> --part <章节1.md> --part <章节2.md> --out <批次.md>`；片段标题必须和骨架的 `##` 标题完全一致。

**源码块的身份是稳定槽位（方案 §3.3）**：`new_batch.py --plan <注释计划> --batch-json <batch.json>` 会在 ⑥ 为每件写一行
`<!-- src-slot id="source:<sha8>:6.N" path=<仓库相对路径> lines=<a-b> sha256=<全文hash> -->`，
其后紧跟一个待注入的围栏块。`annotations.json`（同一次生成的派生物）里每块都带同一个 `slot`。
于是：① 补注释/改标题/重写正文都**不影响块身份**，重复构建与重复注入都是逐字节幂等的；
② 源文件改了而槽位记的 hash 没变 → **拒绝写入**（不会"悄悄把旧行号套到改了内容的源码上"）；
③ 讲解里没有槽位标记（旧分片）时自动退回 `anchor`/`contains` 旧寻址并打印告警。
局部失败只修相应分片或注释表，再重建并复检。已有不同内容的目标需确认后加 `--force`。必要时使用 `safe_edit.py` 的围栏护栏。

⑫写作保留AI协作教学。真实迭代必须有真实失败证据；尚未发生的失败写为“预设验证场景”，不能伪造实测。当前v2.31的固定形态和数量门禁仍生效；规则优化必须另起契约版本，不用临时绕过门禁代替变更。

## 检查与收尾

先检查围栏、节序、占位、表格；后运行 `gate_lecture.py <批次.md> --src <项目根> --manifest <本批清单.json> --json <结果.json>`。`--manifest` 给的是**本批源码清单**（`batch_manifest.py prepare` 的产物，就是盖章要核对的那份；与"位置契约清单 `<讲稿名>.blocks.json`"不是一回事）。`--json` 是**结构化结果**：每条检查带稳定规则 ID（与 `spec/00-质量契约.json` 条款挂钩）、状态、**核验对象数**与定位；`NOT_CHECKED`（0 对象）与 `ERROR` 都**不算通过**。一次收集所有同源问题，修后重新构建并跑完整终检。

**版本档位只看 ⑯ 的规范版本字段**（2.30 修复）：⓪b/⓪d/⓪e/⓪f 四门的 FAIL 档起点都由 `⑯` 声明的版本决定，四个门同源。因此**首跑闸门与盖章后的档位一致**——不会再出现"盖章前 PASS、盖章后失败"（那曾让人以为整批要重写）。

⑯ 的实测表由结果渲染，不手抄数字：`python scripts/sync_gate_result.py <批次.md> --src <项目根> --result-json <结果.json> --manifest <清单.json> --apply`——盖章前先验契约版本、**被检查正文的哈希**与清单哈希（正文在检查之后被改过 → 拒绝盖章，旧结果不得给新正文背书；闸门与盖章**必须用同一份 `--manifest`**，否则会出现"结果 source_manifest_sha256 ≠ 当前清单"的假冲突），盖章后**自动复跑一次完整闸门**校验最终成品，并把最终哈希写进独立记录（`--final-json`，缺省 `<结果>.final.json`）。终稿运行manifest check。若源码在写作中变了，重新调查受影响文件与调用方。

门禁PASS只表示它实际检查的范围PASS。源码事实、编译、单测、集成、人工审读与用户验收分别记录；快照无法读取或某语言块不受检时不得把结果概括成完整通过。书写状态时把当前事实放短状态文件，长过程追加独立日志。覆盖矩阵、总索引和状态只在终稿确认后更新，且用**一份批次记录**统一更新：`python scripts/publish_batch.py --record <batch_record.json>`（`--dry-run` 先看差异，`--apply` 才写；它会先验路径不逃逸、讲义哈希与门禁最终记录一致、主讲不重复、下一批号不回退，冲突时一个文件都不动，重复运行零变化；已发布批次的**既有行**回修（判据改版后的行内旧版本号）用同一工具的 `update_line` op——`anchor` 回修后仍唯一命中、`expect` 是该行当前整行原文，**不许另写一次性脚本**）；中途失败落盘草稿、失败证据和下一步入口。

全库回归属于skill判据修改或阶段收尾的任务，不是每批默认动作。宿主项目自带额外门禁时先核对脚本与退出码语义，不能因为进程退出0就忽略打印出的缺口。
