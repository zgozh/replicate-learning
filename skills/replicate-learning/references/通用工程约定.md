# 通用工程约定（本技能自带的横向规范）

> 用途：`复刻式学习方法` 在讲解/实施里会用到一些**跨场景的工程规范**（验证、commit、续接、协作）。为了**自给自足、任何人拿了就能用**，这里把常用的几条写实，不再指向外部技能。若你所在环境已有同类约定，可替换/覆盖这里的对应条目。

## 1. 验证纪律（证据先于断言）
- **完成/修复/合并前必须跑验证命令并贴真实输出**；**未跑成功，不得宣称完成**。
- 验证命令：测试（`pytest`/`npm test` 等）、构建（`mvn package`/`pnpm build` 等）、或项目自带的 lint/typecheck。
- 汇报要带证据：贴命令 + 输出关键行（成功/失败）。
- 常见翻车：`试了应该没问题`、`改完了但没跑`、`只跑了部分没跑全量`——都算没验证。

## 2. commit 规范（Conventional Commits 摘要）
- 格式：`<type>(<scope>): <subject>`，subject 一句话，描述"做了什么"。
- 常用 `type`：`feat`（新功能）/ `fix`（修 bug）/ `refactor`（重构不改行为）/ `chore`（构建/杂务）/ `docs`（文档）/ `test`（测试）/ `style`（格式）。
- 例：`feat(import): support incremental import` / `fix(query): handle empty rerank results`。
- 一条提交做一件事；改多个不相关文件时拆开提交。

## 3. 续接规范（磁盘当记忆）
- 进度/决策/坑都**落盘**（`AGENTS.md` 的「当前进度+下一步」、`NOTES/` 阶段归档、`git log`、完整性地图）。
- 复刻学习项目再读两份活文档再续：**系统全景地图**（`NOTES/00-系统全景地图.md`，先找回整体）与**概念词典**（`NOTES/概念词典.md`，术语口径统一）。
- 下次开新会话说「继续」，先**读这些文件**从当前状态续接，**不靠会话记忆**——会话会丢，磁盘不会。
- 一个工作单元完成、或切换大业务域、或 token 过高 → 归档一次。

## 4. 工程协作要点（复刻场景适用）
- **AGENTS.md 怎么写**：放定位/目录/常用命令/硬性约定/Editing instructions（≤60 行），给 AI 当上下文，开工先读。
- **验收清单**：明确"什么叫这步算完"（能跑、测试过、地图勾掉），先定标准再动手。
- **派活指令模板**：让 AI 干活时给足上下文与边界——"读 X 文件，做 Y，完成后跑 Z 验证，汇报证据"。别只给一句话。
- **决策记录（ADR）**：关键取舍（为什么选 A 不选 B）一句话记下来，放 `NOTES/ADR.md`，避免回头忘了当时为什么这么定。

> 提示：`.gitignore` 里把 `NOTES/` 等过程笔记排除（不进版本库），只把结论（如进度表、ADR）留下。
