# Replicate-Learning（复刻式学习）

**照着/复刻一个成熟项目，一步步学会它。** 骨架/配置从原项目抄（工程惯例），机制/算法自己手写（那才是真正学到的东西）。

> 定位：**参考而非照抄**，非强制规范。这是一套教学/学习方法论，不是代码规范——用不用、用到哪一步，由你决定。

---

## 它是什么 / 解决什么问题

一个人想学会一个成熟开源项目（看源码、能讲清每个机制、能自己复刻一份），最容易踩的坑是：看完就忘、动手不会、每个类都写一长篇却抓不住重点、写到一半断了下次不知道从哪继续。

这个技能给出一套可操作的流程：**把项目拆成阶段** → **每个类先讲懂（六段）再复刻** → **按档位控制讲解深度（防止每类都一样长、成本失控）** → **每批构建验证** → **逐阶段归档**（进度+地图笔记落盘，下次能无缝续传）。

它只负责「学习复刻」这一件事，不碰"从想法做一个新产品"那类场景。

## 工作流

**1. 先确认在哪个目录复刻。（重要）**
先问使用者在哪做这次复刻。规范：**官方项目与复刻目录放同一级**。
- 本地已有源码：在**该项目父目录**下建复刻目录。例 `D:\dev\myapp` → `D:\dev\myapp-replica`。
- 给的是 GitHub/远程地址：先定一个"项目根"，官方 clone 进去，复刻目录也在**同级**。例 `D:\projects\` → `D:\projects\myapp-book`（官方，只读）+ `D:\projects\myapp-replica`（你的复刻）。
- 好处：`diff` 对照方便、官方只读互不干扰、路径短好找。

**2. 在复刻目录建"开局三件套"。**
- `AGENTS.md`：项目名 + 当前进度 + 学习资料指针（模板见 `references/`）。
- `NOTES/阶段对照-完整性地图.md`：把官方项目交付面拆成阶段勾选清单，标出 **★ 必亲手写的机制**。
- `docs/阶段0-开工清单.md`：跑通官方项目的命令序列。

**3. 逐阶段复刻。**
读教材对应章 → 跑通参照 → 读答案卷对应类 → **抄样板 / 写机制** → `diff` 对照 → **每批立即构建验证** → 归档 + 勾地图 + 更新进度表 + commit。

**4. 讲解先分级，再给深度。**
每阶段开工先出**《讲解分级表》**（类 + 档位 + 一句理由）。档位定好后不中途改：**★机制**满深度、**中等**半深、**样板**精简。每批 ≤3 类，宁多轮不量产。

**5. 每类按"六段"讲透。**
业务场景 → 架构概念先补 → 实现四问（思路/手法/数据流/边界）→ 代码逐行 + 每手法反例 → 调用链（≥8 跳带类名）→ 用法（可照跑 + 触发回放）。

**6. 续传。**
每阶段归档到 `AGENTS.md` + 完整性地图 + `NOTES/阶段N`。下次说「继续复刻 / 接着做」，它读这些文件从当前状态接着来，**不靠对话记忆**。

## 一个例子

你想学会并复刻一个开源知识库（RAG）项目：

1. 你说："我想学着复刻这个知识库项目。" 它先问你在哪复刻。你给本地路径 `D:\dev\kb-src`；它建议复刻目录 `D:\dev\kb-replica`（同级），并在里面建 `AGENTS.md` + `NOTES/阶段对照-完整性地图.md` + `docs/阶段0-开工清单.md`。
2. 阶段0：跑通官方项目，看到"提问→检索→带引用回答"的效果。
3. 阶段1：拆地图，标 ★（如 RRF 排名融合、重排、幂等导入）。出《讲解分级表》。
4. 逐类：先讲懂（六段）再实现；样板照抄、★机制自己写第一版；写完 `diff`；每批立即跑测试。
5. 每批归档 `NOTES/阶段N` + 教学讲解纪要 + 勾地图 + 更新进度表 + `commit`。
6. 下次开新会话说"继续复刻"，它读 `AGENTS.md` + 地图 + `NOTES/阶段N` 接着做，不丢进度。

## 安装

这是一个标准 Agent Skill：一个目录 + 一个 `SKILL.md`（frontmatter 仅 `name` + `description`，符合 [Agent Skills 规范](https://agentskills.io/specification)）。

```bash
# 把 skills/replicate-learning/ 整个目录放进你的技能目录即可：
#   ~/.agents/skills/replicate-learning        (Claude Code / Codex / Gemini CLI 均识别 ~/.agents/skills/)
#   ~/.claude/skills/replicate-learning
```

装好后，对一个学习/复刻项目说「我想复刻这个项目 / 读 AGENTS.md 继续阶段 N」即可触发。

## 讲解深度分级（概述）

| 档位 | 判定 | 深度 |
|---|---|---|
| ★机制（满深度） | 完整性地图标★；或含算法/状态机/路由/多步编排等并发、分支、兜底、fail-fast 红线逻辑；或面试高频 | 六段全量（人+数值、≥8跳调用链、整方法逐行+反例、用法触发回放） |
| 中等（半深） | 非★，但含分支/状态流转/字段校验逻辑 | 场景+调用链+关键代码+用法，反例挑重点 |
| 样板（精简） | 纯声明/映射/配置/DTO/常量/枚举/注解 | 六段精简（一行业务+一行架构+一行契约+一行用法） |

> 意图：**该深的地方舍得下功夫（★机制要学透），该简的地方不烧讲解成本**；并防止批量时把所有类都压成大纲句。

## 哲学

- **参考而非照抄**。——答案卷是"参考"，不是"教材"；机制要读懂原理、能自己讲清、能独立实现，才算学会。骨架/配置可以抄，机制/算法必须自己写。
- **诚实边界**。——注释/代码只写「做什么/为什么」，不出现"来源于/参照/复刻自"这类字眼；对外表述"个人结合 AI 辅助 + 自研增量"。
- **讲解成本可控**。——档位事先定死、每批 ≤3 类、宁多轮不量产；不把讲解当流水线。
- **证据先于断言**。——每批完成即构建验证并如实汇报；未跑不得宣称完成。

## 贡献

对这个技能提改进，建议用"技能版 TDD"：先写一个没有本技能时会翻车的场景作为用例（RED），再改技能文档直到通过（GREEN），最后收口反模式（REFACTOR）。提交前对照 `docs/验证报告.md` 的检验项（触发与深度合规）。
