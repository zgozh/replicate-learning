# Replicate-Learning（复刻式项目深度学习）

**照着一个真实项目，AI 负责扫描、复刻、验证并把每个文件讲透，讲解全文落盘成可长期阅读的中文教材——让你在 vibecoding 时代吃透它的业务、架构与代码。**

> 时代前提：**vibecoding**——代码由 AI 产出，人负责看懂、判断、指挥。所以这套方法**不要求你手写 / 复述 / 交作业**，一切"练才学得会"的东西都**以读代练**写进讲解。
> 目标能力：说清业务闭环 → 说清架构取舍 → 读懂范围内**每一个文件**（源码/测试/配置/脚本/SQL/构建/前端/部署）→ 判断 AI 生成代码对不对 → 用 Vibecoding 高效演进项目。

---

## 它解决什么问题

想学会一个成熟项目，最容易踩的坑：看完就忘、只记住 API 调用姿势（换框架归零）、只讲入口不讲外围、学到一半断片不知从哪继续、讲过的内容被聊天窗口压缩折叠再也翻不到、AI 生成的代码不敢判断对错。

这个技能给出一条可机械执行的流程：**项目考古出四份基础地图 → 业务建模 → 架构推导 → 按闭环分批把全文件教材化 → 关键机制底层穿透 → Vibecoding 工程能力 → 每批验证归档**。产出的**教材**是主交付物；交互、提问、手写练习都是可选，绝不阻塞流程。

它只负责"学习并复刻一个已有项目"，不碰"从想法做新产品"。

## 核心机制

**1. 七阶段工作流（A~G）**

| 阶段 | 干什么 |
|---|---|
| A 项目考古 | 扫描全项目（含构建/锁文件/脚本/配置/资源/迁移/容器/CI/工具/文档），落盘四份基础地图 + **全文件覆盖矩阵** |
| B 业务建模 | 从角色、场景、业务规则、状态变化、异常、审计重建系统；说清"删掉某模块业务怎么退化" |
| C 架构推导 | 运行时全景图 / 模块依赖图 / 请求链路图 / 异步链路图 / 数据模型图 / 部署拓扑；每个选择都要给替代方案、代价和最可能故障 |
| D 全文件教材化 | 按业务闭环分批，**每个纳入范围的文件都必须出现在教材或覆盖矩阵**，状态唯一（未开始/已定位/已讲解/已验证/排除-有理由） |
| E 底层穿透 | 关键机制解释真实源码、框架替你做了什么、不用框架怎么等价实现、具体失败时间线、怎么定位 |
| F Vibecoding 工程能力 | 展示如何让 AI 正确完成：写上下文与约束、拆可验证批次、先读再改、审查 diff、测试/日志/运行反馈闭环、识别幻觉与假测试 |
| G 验证与归档 | 每批跑适合项目的构建/测试/静态检查/启动/最小链路验证，记录命令与结果；失败也如实写层级、排查范围与剩余风险 |

**2. 证据分级（不得混写）**
`事实-源码`（可回链文件/类/方法/行号）· `事实-实测`（命令/测试/日志/堆栈）· `事实-历史`（Git 提交/差异/blame）· `外部事实`（官方文档/依赖源码/协议规范）· `推断`（推导但未验证，必须标出）。

**3. 全文件覆盖矩阵（零遗漏）**
路径 / 文件类型 / 所属能力 / 上下游 / 是否已讲 / 教程链接 / 证据状态 / 遗留问题。**被排除的文件也要记理由**。自动生成文件、第三方目录、二进制资源可以不逐行讲，但必须记录作用、来源、被谁引用与排除理由——不靠删文件换篇幅，文件多就加批次。

**4. 批次教材 12 项 + L0~L4 穿透**
每批至少含：全景位置 / 业务场景与端到端闭环 / 文件清单与一句话职责 / 新概念白话 / 逐文件讲解 / 完整方法或代码段逐行说明 / 调用链·数据流·状态变化·边界 / 不用框架的等价实现 / 失败场景与定位反例 / 测试视角 / Vibecoding 视角 / 验证证据·已知限制·复习问答·索引。

关键机制按 L0-L4 穿透：**L0 源码证据 → L1 机制拆解 → L2 等价实现 → L3 设计取舍与失败时间线 → L4 故障实证**（不能跑就写"未实测"退回 L3，不许编造）。

**5. 不分级、不降档**
机制类、DTO、枚举、配置、建表 SQL、脚本一律满深度讲透，区别只在份量不在深度；零件类用紧凑模板（`references/零件类讲解模板.md`）省篇幅不省深度。

**6. 续传以磁盘为准**
每批立即写盘并更新矩阵、索引与状态文件（当前阶段/批次、已讲文件数/总数、未完成文件、最近验证命令与结果、已知风险、下一步）。下次"继续学习/继续复刻/next"读磁盘接着做，**不依赖聊天记录**。

## 怎么用

1. **说清对象**：给项目路径（或 GitHub 地址）。若同时给原项目与复刻项目，原项目只读、复刻项目按授权使用；只给一个就把它当被学习项目，教材写进它的 `NOTES/教学讲解/`。
2. **考古 + 四份地图**：`00-系统全景地图.md`、`项目文件覆盖矩阵.md`、`概念词典.md`、`阶段对照-完整性地图.md`，外加 `教学讲解/00-总索引.md`。
3. **按闭环分批推进**：每批前先列两张内部清单（外部调用穿透清单 / 讲解骨架清单），写完正文再验证、落盘、更新矩阵。
4. **随时可续传**：说"继续学习""讲第 N 批""讲某文件""验收"即可，动作由意图自动路由（见 `SKILL.md` §1.1）。

> 适合小模型执行：摘要先行、小批推进、上下文复用（已讲概念只回链）、先写后续、证据优先、单次运行至少完成一个可续传批次。

```text

  项目文件覆盖矩阵.md          全文件零遗漏台账（含排除理由）

  阶段对照-完整性地图.md       阶段勾选清单（★ = 重点难点，非深度开关）
  教学讲解/
    00-总索引.md
    阶段N-主题/
      00-阶段总览.md
      批次M-主题.md
```

状态同步写入 `AGENTS.md`（或项目约定的状态文件），跨会话以磁盘为准。

## 安装

标准 Agent Skill：一个目录 + 一个 `SKILL.md`（frontmatter 仅 `name` + `description`，符合 [Agent Skills 规范](https://agentskills.io/specification)）。

```bash
# 把 skills/replicate-learning/ 整个目录放进你的技能目录：
#   ~/.workbuddy/skills/replicate-learning
#   ~/.agents/skills/replicate-learning        (Claude Code / Codex / Gemini CLI 等识别 ~/.agents/skills/)
#   ~/.claude/skills/replicate-learning
```

装好后说「我想学会这个项目 / 继续学习 / 讲第 N 批 / 验收」即可触发。

## 质量禁区（摘要）

不漏讲文件，不把"框架自动处理"当解释；不只讲外围 API 与 README；不编造源码、运行结果、性能数据和故障；不用"高可用/易维护/解耦"等空泛词代替因果链；不把玩具骨架冒充等价实现；**不强制用户手写、复述、提交或闯关**；不压缩业务/底层/测试/工程视角；不把"已扫描"写成"已讲解"、"已讲解"写成"已验证"；不用固定文件数或题数套项目。

## 哲学

- **读者 = 指挥者**。——不要求手写/复述/交作业；练的是看懂、判断、指挥 AI。一切"练才学得会"的内容以读代练写进讲解。
- **教材落盘 = 交付物**。——聊天会被压缩折叠，磁盘上 `NOTES/教学讲解/` 的完整讲解才是能长期回看的教材。
- **整体先于部分**。——先全景地图与覆盖矩阵，再阶段/批次/单文件；每个文件都挂回全景。
- **零遗漏 + 证据分级**。——范围内每个文件都要有覆盖状态和理由；每个结论标证据等级，推断不伪装成事实。
- **满深度、不分级**。——机制、DTO、配置、脚本都讲透；差别只在份量，不在深度。
- **底层穿透到实证**。——L0 源码证据 → L1 机制 → L2 等价实现 → L3 具体故障 → L4 真跑实证，防"API 调用工程师"。
- **具象化**。——关系类内容用 ASCII 图画出来；场景必有具名人物 + 具体数值。
- **初学者友好**。——默认读者只懂一门语言 + 基础语法；新概念用白话 + 类比，禁止用术语解释术语。
- **证据先于断言**。——每批完成即验证并如实汇报；未跑不得宣称完成。

## 贡献

提改进建议用"技能版 TDD"：先写一个没有本技能会翻车的场景作为用例（RED），再改技能文档直到通过（GREEN），最后收口反模式（REFACTOR）。提交前照 `SKILL.md` 自查（触发与覆盖合规、读者模型一致、无强制读者动手环节、无未标等级的推断）。
